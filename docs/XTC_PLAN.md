# XTC(스피커 크로스토크 제거) 시험 계획

대상은 갤럭시 S26 Ultra 내장 스테레오 스피커이고, 가로로 들고 30~50 cm 거리에서 음악을 듣는 경우다. 목표는 소리를 더 넓고 또렷하게 들리게 하는 것이다. 다만 음질을 해치거나 거슬리는 것이 생기면 채택하지 않는다.

## 1. 문헌에서 알 수 있는 것 (요약)

- **원리:** 왼쪽 스피커 소리가 오른쪽 귀에도 들어가는 성분(크로스토크)을 반대 스피커에서 반대 위상으로 미리 빼 준다. 2×2 전달 경로를 역필터로 푸는 문제이고, 모든 방식이 이 역행렬의 근사다(Kirkeby·Nelson의 정규화 역필터, Cooper-Bauck 셔플러, BACCH, OSD, RACE).
- **폰 배치에서의 어려움(노트의 계산):** 스피커 간격을 14~16 cm로 가정하면, 30~50 cm에서 스피커가 이루는 각은 약 17~28°다.
  - 저역은 조건이 나빠 차(L−R) 채널을 크게 키워야 한다. 300 Hz에서 +15~21 dB, 저역 끝에서 +18~27 dB가 필요하다.
  - 조건이 가장 좋은 대역은 약 2~4 kHz이고, 4~8 kHz 위에서 다시 나빠진다.
- **기대치:**
  - 비슷한 배치에서 측정된 분리도는 1~8 kHz에서 15 dB 이상, 0.25~1 kHz에서 10 dB 이상이었다(Ma·Hohnerlein·Ahrens 2019).
  - 일반 HRTF로 설계하면 넓은 대역에서 13~15 dB를 넘기 어렵다(Choueiri, Majdak 2013).
  - 폰에서 직접 측정한 논문은 찾지 못했다. 음악을 넓히는 용도라면 "제한된 대역에서 몇 dB만 분리돼도 쓸모가 있다"는 언급이 있다(Choueiri).
- **청취 위치:** 몇 cm만 옆으로 움직이거나 머리를 1~2° 돌려도 효과가 줄어든다. 폰은 거리 변화(±5 cm → 각도 ±2.5°)에도 민감하다.
- **업계 방식:**
  - Dolby 특허: 가로 방향에서만 XTC를 쓴다. 저음은 모노로 아래 스피커에 보내고 XTC를 거치지 않으며, XTC는 고역 통과 신호에만 적용한다. 스피커별 보정 필터로 두 스피커를 맞춘다.
  - Qualcomm 특허: 먼저 두 스피커를 같게 맞추고, 크로스 성분을 약 0.5~1.2 kHz 위로만 둔다.
- **비용:** 1024탭 필터 4개를 분할 FFT 합성곱(B=256)으로 돌리면 약 10 MFLOP/s다. 셔플러 구조면 약 7 MFLOP/s로, 한 코어의 1% 미만이다(노트의 계산이고 실측은 아님). 지연은 블록 5.3 ms에 모델링 지연 2~4 ms를 더한 정도다.

## 2. 설계 방향 (RACE 방식으로 결정, 2026-10-22)

BACCH 계열은 핵심 방법(주파수별 정규화로 응답을 평탄하게 만드는 것)이 유효한 특허(US9167344)에 걸려 있다. 출처가 불분명한 복제본은 참조하지 않는다. 그래서 공개된 RACE(Glasgal 2007) 방식의 재귀형 제거기로 간다. 구조 자체는 1960년대 Atal–Schroeder부터 이어진 것이다(법률 검토 아님).

**구조:** 각 출력에서 반대쪽 출력을 지연 τ만큼 늦추고 g만큼 줄여 뺀다. 되먹임 경로에만 대역 제한 필터(2차 고역 통과 fLo, 2차 저역 통과 fHi)를 둔다. 그래서 저음과 최고역은 손대지 않고, 크로스오버를 합칠 때 생기는 골도 없다.

**두 가지 방식:**
- **중앙 보존(기본):** 차(S) 신호에만 재귀를 건다. 가운데 소리(보컬)의 음색은 그대로다. 대신 분리가 덜 된다.
- **완전 RACE:** 좌우 모두에 건다. 분리는 더 되지만, 가운데 소리가 4~5 kHz에서 솟고 1 kHz 근처에서 꺼진다.

**머리 크기는 재지 않는다.** τ는 표준 구형 머리(Woodworth 공식, 반지름 8.75 cm)와 청취 거리로 계산한다.
- 선택지는 모자 크기 소(54 cm), 중(57 cm, 기본), 대(60 cm) 세 가지다.
- 머리 크기가 τ에 주는 영향은 ±5% 정도로, 거리(30↔50 cm에서 약 1.6배)보다 훨씬 작다.

**스피커 간격:** 15.5 cm로 가정한다. 기기마다 한 번 재면 되는 값이고, 사용자에게 묻지 않는다.

**모델 계산값** (`tools/xtc/race_design.py`, 40 cm, 머리 중, 대역 0.7~5 kHz; 분리도는 머리 그림자 모델로 추정한 값이고 실측이 아님):

| 방식 | 세기(g) | 가운데 음색 변화 | 차 신호 최대 증폭 | 분리도 1~4 kHz (끔 → 켬) | 30~50 cm·머리 소~대 중 최악 |
|---|---|---|---|---|---|
| 중앙 보존 | 약 −6 dB | 0 | +5.5 dB | 2.7 → 5.9 dB | 4.8 dB |
| 중앙 보존 | 강 −3 dB | 0 | +9.3 dB | 2.7 → 7.6 dB | 6.1 dB |
| 완전 RACE | 약 −6 dB | −3.3 ~ +5.1 dB | +5.5 dB | 2.7 → 9.6 dB | 7.6 dB |
| 완전 RACE | 강 −3 dB | −4.4 ~ +8.6 dB | +9.3 dB | 2.7 → 13.3 dB | 7.6 dB |

- 스크립트를 Python으로 그대로 옮겨 임펄스 응답을 재 보았다. 모델과의 차이는 0.4 dB 이내였다(선형 보간 지연 때문). 꼬리는 0으로 수렴하므로 재귀는 안정적이다.
- 처리 순서는 JamesDSP LiveProg(XTC) → 가상 저음 → true-peak 리미터다. XTC는 0.7~5 kHz만 다루므로 저음 생성과 겹치지 않는다.
- 차 신호가 최대 +5~9 dB 커지므로, 리미터 작동량을 측정해 판단한다.

## 3. 단계

### 0단계: 사전 확인

1. 가로 방향을 반대로 돌렸을 때 Android가 좌우 채널을 바꿔 주는지 확인한다. 테스트 음 L/R로 확인한다.
2. 기준 측정: REW와 측정 마이크를 청취 위치에 두고 L만, R만, L+R, L−R을 스윕으로 잰다. Dolby Atmos 끄고, Rootnote 처리도 끈 상태다. 두 스피커의 레벨과 대역 차이, 수화부 스피커의 저역 한계를 확인한다.

### 1단계: 시제품, 앱 빌드 없음

1. `tools/xtc/race_xtc.eel`을 폰에 옮겨 Rootnote의 LiveProg에서 불러온다.
2. 설정: 방식(중앙 보존 / 완전 RACE), 세기(약 / 중 / 강), 거리(cm), 머리 크기(소 / 중 / 대), 스피커 간격, 대역, 우회(비교용).
3. 가상 저음과 리미터는 평소대로 켜고 듣는다.

### 2단계: 측정 (1일)

- **측정 마이크만 있을 때(머리 없음):** 귀 자리 두 점에서 M(L+R)과 S(L−R) 응답, 리미터 작동량, 처리 부하를 잰다. 머리 그림자가 없으므로 분리도 자체는 잴 수 없다. 대신 정중앙 소리(보컬)의 음색이 그대로인지를 확인한다.
- **바이노럴 귀마이크가 있을 때(선택):** 개발 확인용으로만 쓴다. 자기 머리에 끼고 L만, R만 스윕을 재서 χ(f)=같은 쪽 귀/반대쪽 귀 응답을 구한다. XTC 끔과 켬을 비교하고, 머리를 좌우 ±3 cm, 앞뒤 ±5 cm 옮겨서도 잰다. 사용자에게는 어떤 측정도 요구하지 않는다.

### 3단계: 블라인드 청취 (2~3일, 나눠서)

음량은 맞춘다. 앱의 블라인드 비교 기능은 가상 저음 설정만 바꾸므로, LiveProg 시제품 단계에서는 스크립트의 "우회" 설정을 다른 사람이 몰래 바꿔 주는 방식으로 한다. 엔진에 넣은 뒤(4단계)에는 블라인드 비교 기능에 XTC를 추가한다.

1. **구별 시험(ABX):** 끔 vs 약. 구별하지 못하면 강으로도 해 본다. 둘 다 구별 못 하면 중단한다.
2. **선호 비교:** 끔/약/강을 짝지어 비교한다. 곡은 세 종류다: 보컬이 가운데인 곡, 좌우로 넓게 믹스된 곡, 저음이 많은 곡. 같은 쌍을 한 번 더 넣어(같은 것끼리 비교) 일관성을 본다.
3. 들으면서 볼 것:
   - 가운데 보컬이 흔들리거나 얇아지는가
   - 위상이 꼬인 느낌(머릿속이 울렁거림)이 나는가
   - 고음이 날카로워지는가
   - 저음이 줄었다고 느끼는가
   - 10분 이상 들었을 때 피곤한가
   - 폰을 조금 기울이거나 거리를 바꿨을 때 이상해지는가

### 4단계: 엔진 구현 (채택될 때만, 2~3일)

- libpvb에 같은 재귀형 제거기를 넣는다. 지연선 2개, 쌍2차 필터 4개, 곱셈 몇 번이라 CPU 부담은 사실상 없다. 지연은 더 나은 보간(3차 Lagrange 또는 전역통과)으로 바꾼다.
- 가로 방향일 때만 켜고, 세로이거나 이어폰·블루투스 출력일 때는 끈다.
- 비트 비교 시험: XTC 끔일 때 지금 출력과 비트 단위로 같아야 한다. 필터 설계 단위 시험(모노 합 평탄도, 최대 이득)을 CI에 넣는다.
- 설정: 끔 / 약 / 강, 기본은 끔. 나중에 전면 카메라 머리 추적도 생각할 수 있지만, 배터리와 권한 부담이 커서 이번 범위에서는 뺀다.

## 4. 채택 기준과 중단 기준

**채택(모두 만족):**
- ABX에서 구별된다. 12번 중 10번 이상 맞힌다.
- 선호 비교에서 약 또는 강이 끔보다 일관되게 낫다. 같은 쌍 반복에서도 같은 답이 나와야 한다.
- 가운데 보컬 음색 변화가 귀로 거슬리지 않는다. 측정으로는 모노 합 ±1 dB 이내다.
- 리미터 작동량 증가가 평균 1 dB 미만이다.
- CPU 증가가 한 코어 기준 1% 미만이다.

**중단(하나라도 해당):**
- 구별이 안 된다.
- 위상이 꼬인 느낌이나 피로감이 있다.
- 폰을 조금 움직였을 때 소리가 이상해진다.
- 저음이 줄었다고 느낀다. 가상 저음 효과를 깎으면 손해다.

## 5. 위험

| 위험 | 대응 |
|---|---|
| 청취 위치가 좁음 | 대역을 좁히고 세기를 낮게 둔다. 손에 들고 듣는 자세 그대로 시험한다 |
| 두 스피커가 다름(수화부 스피커가 약하고 저역이 없음) | 스피커별 보정을 하고, 그 대역에서는 XTC를 끈다 |
| 삼성 자체 스피커 처리를 모름 | 모든 측정을 실제 출력 경로(Atmos 끔)로 한다 |
| 음색 변화(정규화로 생기는 골과 산) | 증폭 상한을 두고, M 경로는 평탄하게 둔다. 측정으로 확인한다 |
| 헤드룸·리미터 | 리미터 작동량을 측정하고, 필요하면 상한을 낮춘다 |
| 특허 | 고전 방식만 쓰고, 특허 절차를 그대로 쓰지 않는다(법률 검토 아님) |
