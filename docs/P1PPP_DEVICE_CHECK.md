# P1+++ 실험 옵션: 폰에서 한 번 확인 (총 9분 이내)

general: 고급 설정 → 가상 저음 → P1+++ · 실험, 48 kHz.
s26u: 스피커 보정 설정 → 가상 저음 → 같은 스위치.
기본은 OFF다. 이 검사는 버그 재현 확인이며, 쌍대 청취나 음질 우열 판정은 하지 않는다.
테스트 키로 서명한 APK이며 배포판 서명을 사용하지 않는다. 설치·업데이트는 사용자가 별도로 수행한다.

1. (1분) 내장 스피커와 평소 편안한 볼륨으로 시작한다. 설정에서 P1+++가 OFF인지 확인한다. 기존에 직접 켜서 저장했다면 ON 복원은 정상이다.
2. (1분) 평소 듣는 곡 하나를 재생하고 P1+++를 한 번 켠다. 상태 화면에 “적용 중 · EQ 고정 · 층 0 dB · 출력 −5 dB”가 나타나는지 확인한다.
3. (1분) 2초 이상 간격으로 OFF→ON을 두 번 반복한다. 전환당 약 0.21초와 블록 대기의 짧은 음소거는 설계된 동작이다. 팝·한쪽 채널 튐·그보다 긴 반복 끊김은 기록한다.
4. (1분) 정지 2초→재개, 곡 중간 탐색을 각각 한 번 한다. 이전 위치의 소리가 반복되거나 장시간 무음이 되지 않는지 확인한다. 캡처 앱은 외부 플레이어의 seek 이벤트를 직접 받지 못하므로 고정 처리 지연 약 149 ms는 남는다.
5. (1분) 이어폰 또는 Bluetooth 연결→내장 스피커 복귀를 한 번 한다. 외부 출력에서는 우회, 복귀 후 적용 상태와 정상 재생을 확인한다.
6. (1분) 세기·EQ 볼륨 연동을 저장한 채 미디어 볼륨을 낮은 평상 범위→높은 평상 범위로 한 번 바꾼다. P1+++ 적용 중 고정층 0 dB·출력 −5 dB 표시가 유지되는지 본다. 배음의 체감 세기를 곡마다 맞추지는 않는다.
7. (1분) 조용한 구간→큰 구간이 있는 곡을 30초 재생한다. 틀린 음 버스트·쿠쿠쿵·공백/음 소실·어택 지연이 문제인 시각과 설정만 적는다. 기존 후보의 알려진 음향 한계를 이번 코드 수정의 개선으로 해석하지 않는다.
8. (1분) 캡처 rate를 바꾸는 기존 앱 설정이 있다면 44.1→48 kHz로 한 번 전환한다. 44.1에서는 “48 kHz에서만 지원”, 48로 복귀하면 적용으로 돌아와야 한다. 해당 설정이 없으면 N/A로 남긴다.
9. (1분) 상태 화면을 연 채 마지막으로 OFF로 돌린다. 저장했던 EQ·세기 설정이 돌아오는지 확인하고 로그와 문제 시각을 저장한다. 발열·끊김이 있으면 실험 옵션을 OFF로 둔다.

## 앱 로그와 상태에서 확인할 것

상태 화면이 열려 있으면 기존 meter 읽기에서 관측한 변화만 `P1PPP` 태그로 기록한다.
형식: `requested=true state=1 rate=48000 speaker=true latency=7140`.
state 1은 적용, 4는 전환, 0은 OFF/encoder의 지원 불가 fallback, 2는 native rate 차단이다.
44.1 kHz fallback은 요청 true + state 0도 정상이며 UI에 지원 불가 이유가 표시된다.
짧은 state 4는 화면 갱신 사이에 지나가 로그에 없을 수 있다. 요청 기록을 적용 성공으로 세지 않는다.
정상 복귀는 rate 48000/state 1/latency 7140, 최종 OFF는 requested=false/state 0이다.
캡처 재생성 시 서비스 로그 `PVB stream reset: capture_recreated`와 진단 discontinuity 표식이 남는다.
일반 재생에서 nonfinite 이벤트가 늘거나 크래시/지속 무음이 생기면 실패다. 상태의 CPU/리미터 값도 함께 기록한다.
Android AudioTrack xrun·열·스피커 DRC는 호스트 수치로 검증되지 않았다. 이 9분 검사는 장시간 RT 보증이 아니다.
