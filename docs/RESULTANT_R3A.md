## Resultant R3-a: 확인 사전 등록 (초안 v0)

**상태:** 초안. 확인군 MoisesDB는 아직 받지 않았다 (사용자가 신청). 자료가 오면 파일 목록·해시 표를 채워 v1로 GPT 관문 ①에 동결을 요청한다. 동결 전에는 MoisesDB에 어떤 모델도 돌리지 않는다 — 파일 목록, 해시, 베이스 stem의 YIN 참조 점검 (모델 렌더 없음)만 한다.
**후보:** R3-a = stage 8388608 (`StageSubOctaveNoHold`, 커밋 a51c8b9). 배경·개발 결과는 `docs/RESULTANT_R3.md` "R3-a".

### 무엇이 이전 (R3 v2d)과 다른가
- **채택 문턱:** 이전의 "곡별 추적 중앙값 ≥ +5 %p"는 청감 근거가 없는 숫자였다 (블라인드 1차: 컴퓨터 스피커에서는 +30 %p까지도 안정적으로 들리지 않았다). 이번에는 "우연이 아님"을 문턱으로 둔다: 곡 단위 부트스트랩 95 % 구간의 하한 > 0.
- **해악 한도는 따로:** 개선이 우연이 아니어도 해악 한도를 넘으면 채택하지 않고 보류한다 (개선·악화 혼재 판정 규칙).
- **청감의 역할:** 판정에 들어가지 않는다. 결과에 등급 ("들리는 개선" / "측정상 개선·청감 중립")을 붙이고 해악을 확인하는 데만 쓴다. 청감은 블라인드로만.

### 비교
P1 (기준, stage 0), R3-a (1차 후보, 8388608), R3 (보조 보고, 2097152). 문턱 10 / 20 dB는 고정, 확인군에서 다시 맞추지 않는다.

### 확인군
- MoisesDB (CC BY-NC-SA 4.0, 비상업 연구; 로컬 전용, 커밋 금지): 베이스 stem이 있는 모든 곡.
- 각 곡 60–120 s (도입부를 피한 60 s). 120 s보다 짧은 곡은 30 s 이상 남는 부분이 있으면 60 s부터 끝까지, 없으면 제외. 이 규칙도 동결 대상이다.
- 믹스 = 모든 stem의 합 (MoisesDB에는 믹스 파일이 없다). 베이스 = `bass` 폴더 stem들의 합.
- 제외 (미리 고정): 베이스 stem 없음, 참조 프레임 20개 미만, 창이 30 s 미만. 제외 곡은 목록과 사유를 보고한다.

### 참조
베이스 stem 합의 YIN (MUSDB와 같은 설정: 3 kHz, 400 Hz 저역 통과, 28–300 Hz, 85 ms 창, 10 ms 간격, CMNDF 0.15, 가장 큰 프레임의 35 dB 안). 한계: 베이스가 둘 이상이면 합의 f0, YIN 자체의 옥타브 오류, 신스 베이스의 배음 구조. MIDI 참조는 없다.

### 지표와 판정 (`research_gt_bass.py --rule v3 --decide`)
- **1차:** 곡별 (R3-a 추적 − P1 추적)의 중앙값과 곡 단위 부트스트랩 95 % 구간 (10,000번, 시드 20261029). None인 곡은 빼고 목록·수를 보고한다.
- **채택 (adopt):** 구간 하한 > 0, 그리고 해악 한도 모두 통과 —
  곡별 옥타브 오류 변화 중앙값 ≤ 0, 모든 대역을 모은 프레임 추적 변화 > 0, ≥ 82 Hz 모은 프레임 추적 손실 ≤ 5 %p, 공통 성공 프레임 \|cents\| 중앙값 증가 ≤ 2 cent.
- **기각 (fail):** 1차 중앙값 ≤ 0 (개선 없음). 기각을 채택보다 먼저 본다 (중앙값 ≤ 0인데 구간 하한 > 0인 드문 경우도 기각).
- **보류 (hold):** 그 밖 — 우연이 아닌 개선이지만 해악 한도를 넘음, 또는 구간이 0에 걸침. 미측정 항목이 있으면 hold와 함께 그 항목을 적는다. 보류 후보는 버리지 않고 (실험) 옵션이나 후속판 (R3-b)로 잇는다.
- **추가 보고:** 대역별 모은 표, 55 Hz 미만 프레임 50개 이상인 곡별 결과, 전체 프레임 cents, 생성층 몫·절대량, R3 비교.

### 실행
`research_gt_bass.py <moisesdb> --reference yin --crop 60,60 --models p1,p1_r3a,p1_r3 --decide --rule v3`, 동결 태그 커밋에서 `build_host.sh`로 빌드한 라이브러리, 깨끗한 작업 트리에서 1회. 보고서 (익명 곡 번호, rows·paired·decision·inventory, 오디오 없음)는 `docs/reports/`에 커밋한다.

이 규칙은 R3 확인 실패와 R3-a 개발 결과를 본 뒤에 정했다. 그래서 두 개발군에서 adopt가 나오는 것은 근거가 아니다. 근거는 아직 보지 않은 MoisesDB 한 번의 결과다. BabySlakh 줄은 이전 문턱이 실제로 있는 개선 (구간이 0 위)을 떨어뜨리는 경우를 보여 준다.
