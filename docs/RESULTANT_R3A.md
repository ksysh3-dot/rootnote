## Resultant R3-a: 확인 사전 등록 (v1)

**상태:** v1, 관문 ① 동의로 규칙 고정 (아래 "관문 ①"). 확인군은 Slakh2100-redux test다. MoisesDB는 신청 메일이 오지 않았고, 오면 실제 녹음 후속 확인으로 따로 등록한다 (아래). Slakh 목록 (모델 없음)을 2026-10-30에 채웠다 (아래 표). 제외는 모두 미리 고정한 규칙 안이라 규칙을 바꾸지 않고 동결 태그를 단다. GPT 휴식 중이라 이후 관문은 SOLO 모드 (Claude 주도, Sonnet 독립 검토)로 진행하고 그렇게 기록한다. 동결 전에는 test에 어떤 모델도 돌리지 않는다.
**후보:** R3-a = stage 8388608 (`StageSubOctaveNoHold`, 커밋 a51c8b9). 배경·개발 결과는 `docs/RESULTANT_R3.md` "R3-a".

### 무엇이 이전 (R3 v2d)과 다른가
- **채택 문턱:** 이전의 "곡별 추적 중앙값 ≥ +5 %p"는 청감 근거가 없는 숫자였다 (블라인드 1차: 컴퓨터 스피커에서는 +30 %p까지도 안정적으로 들리지 않았다). 이번에는 "우연이 아님"을 문턱으로 둔다: 곡 단위 부트스트랩 95 % 구간의 하한 > 0.
- **해악 한도는 따로:** 개선이 우연이 아니어도 해악 한도를 넘으면 채택하지 않고 보류한다 (개선·악화 혼재 판정 규칙).
- **청감의 역할:** 판정에 들어가지 않는다. 결과에 등급 ("들리는 개선" / "측정상 개선·청감 중립")을 붙이고 해악을 확인하는 데만 쓴다. 청감은 블라인드로만.

### 비교
P1 (기준, stage 0), R3-a (1차 후보, 8388608), R3 (보조 보고, 2097152). 문턱 10 / 20 dB는 고정, 확인군에서 다시 맞추지 않는다.

### 확인군: Slakh2100-redux test
- Zenodo 4599666 `slakh2100_flac_redux.tar.gz` (104,322,767,708 바이트, MD5 `f4b71b6c45ac9b506f59788456b3f0c4`, CC BY 4.0)의 `test` 폴더 151곡 전부. 로컬 전용, 커밋 금지. 압축 파일은 외장 SSD에 두고 `fetch_slakh_split.py`로 test만 푼다.
- BabySlakh (Track00001–00020, 원래 분할의 train)와 곡이 겹치지 않는다. redux판은 분할 사이에 중복된 MIDI를 뺀 판이다.
- 각 곡 30–90 s (`--crop 30,60`): v2d BabySlakh 확인과 R3-a 개발 수치가 쓴 창과 같다. 창 안에서 앞 1 s 예열, 끝 0.2 s 제외 (도구 기본). 44.1 kHz FLAC. 믹스 = `mix.flac`, 베이스 = `metadata.yaml`에서 `inst_class: Bass`인 렌더된 stem들의 합.
- **왜 이 자료:** R3가 확인에서 실패한 곳 (≥ 82 Hz를 잘못 내림)이 이 합성 음원 계열이다. R3-a의 수정이 새 곡에서도 통하는지 정면으로 본다. MIDI가 있어 YIN 추정이 아닌 정확한 음 참조를 쓴다.
- **한계:** 합성 음원뿐이다. 실제 녹음에서의 일반화는 이 확인의 주장이 아니다 (MoisesDB 후속 확인 몫).
- **제외 (미리 고정):** 렌더된 베이스 stem 없음 (로더가 건너뜀; 수를 보고), 창이 5 s 미만 (v2d와 같음), 베이스 MIDI 없음, MIDI 옥타브 불명 (아래), 참조 프레임 20개 미만. 제외 곡은 목록과 사유를 보고한다.

### 참조: MIDI 기반, stem YIN으로 옥타브 정렬한 참조
- 베이스 stem MIDI들의 가장 낮은 음 (템포 맵 적용), YIN과 같은 프레임 격자 (10 ms).
- **곡별 옥타브 (`--midi-transpose auto`, `midi_octave`):** 모델 없이 베이스 stem만으로 정한다. 후보 −24 / −12 / 0 / +12 반음 가운데, MIDI f0가 stem의 YIN (MUSDB와 같은 설정)과 50 cent 안에서 맞는 프레임 몫이 가장 큰 것. 둘 다 값이 있는 프레임이 20개 미만이거나, 최고 몫이 50 % 미만이거나, 다음 후보보다 20 %p 이상 앞서지 않으면 그 곡은 "MIDI 옥타브 불명"으로 제외한다.
- 옥타브를 YIN으로 고르고 제외하므로 이 참조는 YIN과 독립인 정답이 아니다. YIN 일치율을 참조의 별도 검증으로 세지 않는다.
- 문턱 (50 %, 20 %p)은 BabySlakh에 돌리기 전에 정했다. BabySlakh (개발군) 30–90 s에 적용하면 19곡 중 18곡이 −12 (일치 91–100 %; 곡 전체로는 68–100 %)로 이전의 손 점검과 같고, Track00012는 −12 일치 49.5 % (곡 전체 47 %)로 제외된다 (v2d에서는 −12 고정으로 포함됐던 곡). 고정 −12와 auto는 남은 곡에서 같은 행을 낸다 (2곡 회귀 점검).

### 지표와 판정 (`research_gt_bass.py --rule v3 --decide`)
- **1차:** 곡별 (R3-a 추적 − P1 추적)의 중앙값과 곡 단위 부트스트랩 95 % 구간 (10,000번, 시드 20261029). None인 곡은 빼고 목록·수를 보고한다.
- **판정 순서 (`decide_v3` 그대로):**
  1. 1차 중앙값이나 구간이 미측정 (None)이면 **보류 (hold)**, 사유에 미측정 항목.
  2. 그렇지 않고 1차 중앙값 ≤ 0이면 **기각 (fail)** (개선 없음; 중앙값 ≤ 0인데 구간 하한 > 0인 드문 경우도, 해악 항목이 미측정이어도 기각).
  3. 그렇지 않고 다음이 모두 참이면 **채택 (adopt)**: 구간 하한 > 0, 곡별 옥타브 오류 변화 중앙값 ≤ 0, 모든 대역을 모은 프레임 추적 변화 > 0, ≥ 82 Hz 모은 프레임 추적 변화 ≥ −5 %p, 공통 성공 프레임 \|cents\| 중앙값 증가 ≤ 2 cent. 미측정 항목은 참으로 치지 않는다.
  4. 그 밖은 **보류 (hold)** — 우연이 아닌 개선이지만 해악 한도를 넘음, 구간이 0에 걸침, 또는 해악 항목 미측정 (사유에 그 항목).
- 보류 후보는 버리지 않고 (실험) 옵션이나 후속판 (R3-b)로 잇는다.
- **주장 범위:** 채택이어도 이 합성 test와 이 참조에서의 측정 개선이다. 청감 개선이나 실제 녹음 일반화가 아니다.
- **추가 보고:** 대역별 모은 표, 55 Hz 미만 프레임 50개 이상인 곡별 결과, 전체 프레임 cents, 생성층 몫·절대량, R3 비교.

### 실행
1. 동결 전 (모델 없음): `fetch_slakh_split.py <out> --source <압축 파일>` (MD5 확인 포함), 그리고 `research_gt_bass.py <out>/test --reference midi --midi-transpose auto --crop 30,60 --inventory-only` → 파일 목록·해시·옥타브 점검을 `docs/reports/r3a-confirm/`에 커밋하고 아래 표를 채운다.
2. 동결 태그 커밋에서 `build_host.sh`로 빌드한 라이브러리, 깨끗한 작업 트리에서 1회: `research_gt_bass.py <out>/test --reference midi --midi-transpose auto --crop 30,60 --models p1,p1_r3a,p1_r3 --decide --rule v3`. 보고서 (익명 곡 번호, rows·paired·decision·inventory, 오디오 없음)는 `docs/reports/r3a-confirm/`에 커밋한다.

이 규칙은 R3 확인 실패와 R3-a 개발 결과를 본 뒤에 정했다. 그래서 두 개발군에서 adopt가 나오는 것은 근거가 아니다. 근거는 아직 보지 않은 Slakh test 한 번의 결과다. BabySlakh 줄은 이전 문턱이 실제로 있는 개선 (구간이 0 위)을 떨어뜨리는 경우를 보여 준다. (BabySlakh 줄은 −12 고정 기준이다.)

### 관문 ① (GPT, #2 댓글 6495296879, 67c3312 기준): 규칙·동결 절차 동의
- 부트스트랩 (곡 단위 10,000번, 시드 20261029, 2.5·97.5 백분위)과 v3 조건을 코드와 대조했다. 정정된 창 (`--crop 30,60`, 5 s 미만 제외)을 목록 단계와 본 실행 모두에 쓴다. `--inventory-only`가 모델 렌더를 건너뛰는 것도 확인했다.
- 고친 문구: 판정 순서를 코드 그대로 적음, 옥타브 차이 "20 %p 이상", 참조 이름 "MIDI 기반, stem YIN으로 옥타브 정렬한 참조" (YIN과 독립인 정답이 아님).
- 남은 절차: 151곡 전체 목록, 제외 사유 (베이스 없음·일부 MIDI 누락 포함), 유효 곡 수, 곡별 옥타브·일치율, 파일 해시를 공개한 뒤 규칙을 바꾸지 않고 태그를 고정한다. 규칙 밖의 제외·중복·분할 불일치가 있으면 모델을 열기 전에 다시 논의한다. 앱·기본값 변경 승인은 아니다. MoisesDB는 따로 동결한다.
