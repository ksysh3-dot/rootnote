# 자동 음향 측정 — UMIK 대조와 타격 전후 변화

2026-10-27. 기준: `release/general-0.9.0-beta.7`의 `68d8318a` 이후 연구 기능.
앱 기본 모델은 P1 그대로다. 일반 빌드의 개발자 모드에서 **자동 음향 측정**을 연다.
새 기능은 실제 녹음의 수집·분석을 연결하며, 이 문서를 쓰는 시점에는 연결된 휴대폰이 없어
새 실기기 녹음 결과는 없다. 합성 검사 통과를 실기기 개선으로 표현하지 않는다.

## 1. UMIK-1 대조 분석

PC의 소리를 폰과 UMIK-1이 함께 듣게 한다. 폰은 고정하고 UMIK-1은 실제 활성 마이크 구멍 가까이에 둔다.
위치 차이·방 반사·몸체 전달의 영향은 남으므로, 폰 마이크만의 무향실 교정이라고 주장하지 않는다.

1. PC에서 아래 명령으로 직접 만든 시험음과 입력 양식을 준비한다. `numpy scipy soundfile`이 필요하다.

   ```sh
   python3 tools/pvb-harness/acoustic_lab.py prepare --out work/mic-reference
   ```

2. REW에서 **교정된 UMIK-1, 1/3옥타브 RTA, SPL 대역 레벨**을 사용한다. 일반 FR 곡선의 점·스윕
   위상·미교정 dBFS를 같은 값으로 입력하지 않는다. 자동 이득이나 입력 볼륨을 중간에 바꾸지 않는다.
3. 앱의 **방 소음 재기**를 누르고 UMIK-1에서도 방 소음을 저장한다.
4. PC에서 `fit.wav`를 재생하고 **보정용 소리 재기**를 누른다. 폰은 지원을 선언한 UNPROCESSED(9),
   VOICE_RECOGNITION(6)을 순서대로 각각 10초씩 듣는다. UMIK-1도 각 구간을 함께 재어 저장한다.
5. `validation.wav`를 별도로 재생하고 **다른 소리로 확인하기**를 누른다. 이 녹음은 보정값 계산에 쓰지 않는다.
6. **마이크 대조 결과 공유**로 JSON을 PC에 저장한다. `reference.csv`의 source별 14개 대역에
   동시 측정한 방 소음·보정·확인 SPL을 넣는다. 원본 신호는 40초이므로 두 방식의 순차 측정을 포함한다.
   각 구간의 REW 값을 써야 한다. 하나의 RTA 순간값을 서로 다른 시간의 측정에 대신 사용하지 않는다.
   UNPROCESSED를 사용할 수 없었던 경우 그 source=9 행은 지운다. 빈 값을 추정해서 채우지 않는다.
7. 실행한다.

   ```sh
   python3 tools/pvb-harness/acoustic_lab.py calibrate acoustic_lab_calibration.json --reference work/mic-reference/reference.csv --out work/mic-analysis
   ```

출력은 `analysis.json`, `RESULTS_KO.md`다. source·실제 입력·채널·OS·포맷을 묶어서 다루며 서로 다른 경로를
합치지 않는다. 양쪽 측정 모두 해당 대역의 신호/방 소음 차이가 15 dB 이상일 때 방 소음 전력을 빼고
`오프셋(f) = 기준 마이크 SPL(f) − 폰 dBFS(f)`를 구한다. 1 kHz를 포함해 유효 대역 10개 이상을 요구한다.
100–2000 Hz 밖으로 외삽하지 않는다. 1 kHz 대역 오프셋은 정현파 절대 감도 인증값과 구분한다.

**보정 전 오차**는 보정 녹음의 1 kHz 한 점으로 레벨만 맞춘 상태다. 단위가 다른 원래 dBFS와 SPL을
그대로 빼서 거대한 개선 수치를 만들지 않는다. **보정 후 오차**는 보정 녹음에서 고정한 대역별 값을
별도 확인 녹음에 적용한 결과다. 확인 녹음에 다시 맞추지 않는다. 대역별 오차, RMSE, 전체 이득 이동을 함께 적는다.
선별 기준은 확인 RMSE ≤2 dB, 평균 이득 이동 ≤1 dB, RMSE 악화 ≤0.25 dB다. 청각 문턱이나 인증 기준이 아니다.
기준을 통과해도 현재 앱 설정에는 적용하지 않는다. 프리셋 채택·다른 기기 전용은 별도 작업이다.

첫 방 소음 이후 환경이 안정적이었다고 가정한다. 다른 위치·녹음 방식·입력 레벨에서의 선형성을
이 두 녹음만으로 보장할 수 없다. 선언값이나 미지원 API를 실측으로 바꾸어 표시하지 않는다.

## 2. 타격 전후 자동 비교

현재 시스템 볼륨에서 P1(6), P1+(11), P1++ v0.2(12), v0.3(13)을 비교한다. 앱 안의 실제 네이티브 엔진을
별도 인스턴스로 실행하고 AudioTrack으로 내장 스피커에 보낸다. JamesDSP 효과·다른 앱 캡처 경로는 제외한다.
따라서 실제 스피커 재생 실험이지만 평소 서비스의 전체 경로와 동등함을 주장하지 않는다.

- 직접 생성한 100 Hz 지속음, 그리고 같은 지속음에 160 ms의 킥/잡음 타격을 더한 입력을 짝짓는다.
- 4모델 × 입력 세기 2개(12 dB 차이) × 3반복 × 지속음/타격 2조건 = 48회, 약 4분이다.
- 짝 내부 순서를 균형 있게 섞고 짝의 순서를 난수로 섞는다. seed와 PCM SHA-256을 기록한다.
- 배음 +4 dB, 출력 −5 dB, 같은 EQ와 리미터로 고정한다. 저장한 사용자 설정이나 시스템 볼륨을 바꾸지 않는다.
- 실제 렌더에 포함된 고역 표식을 녹음과 상관시켜 지연을 맞춘다. 모델별 처리 지연을 타격 전 잡음으로 세지 않는다.
- 인과적인 150–2000 Hz 필터를 사용한다. 측정용 필터가 타격 이전에 링잉을 만들지 않는다.
- 타격 시작 전 −450~−80 ms, 어택 0~80 ms, 초기 80~300 ms, 후기 300~800 ms를 함께 기록한다.
- 회복은 타격 시작 후 최소 160 ms부터 지속음 기준의 ±1 dB 안에 50 ms 연속 머문 첫 시점이다.
  약 0.9초까지 돌아오지 않거나 지속음이 방 소음보다 충분히 크지 않으면 `null`이다.
  타격 파형 자체의 끝·인과 필터 지연도 포함하므로 모델 내부 릴리즈 상수와 같지 않다.

UNPROCESSED 지원 선언이 없거나 첫 녹음을 열 수 없으면 VOICE_RECOGNITION을 명시해서 쓴다.
한 비교 도중 source를 바꾸지는 않는다. 실제 source, 활성 마이크·채널, 입력 기기, 클라이언트 효과 끄기 요청,
스트림 효과, 음소거 여부, 시계, 볼륨, 엔진 파라미터, 정렬 점수를 기록한다. 활성 마이크 정보가 비었거나
vendor 효과를 읽지 못했다고 가공 없음이 검증됐다고 취급하지 않는다. 녹음 경로가 변하거나 읽기 공백·
재생 오류·볼륨 변경이 생기면 중단하고 완료되지 않은 결과로 남긴다. 화면을 떠나도 중단한다.

**48회 자동 측정 시작**을 누른 뒤 JSON을 공유하고 실행한다.

```sh
python3 tools/pvb-harness/acoustic_lab.py impact acoustic_lab_impact.json --out work/impact-analysis
```

출력에서 다음을 함께 본다.

- 지속음만 있는 대조군에 비해 타격 조건의 각 시간대 에너지가 얼마나 바뀌었는지.
- 타격 전에 이미 레벨이 달랐는지(±1 dB 초과는 이득 대조 실패), 그 차이를 맞춘 값은 어떤지.
- 어택·초기·후기·회복과 반복 범위. 후기만 줄었다고 좋은 모델로 고르지 않는다.
- 입력 12 dB 증가에 대한 녹음된 지속음의 증가. 스피커 보호와 마이크 처리가 함께 들어간 루프 압축이다.
- 창의 전력이 방 소음보다 10 dB 이상 크지 않으면 차이를 정량화하지 않는다. 매우 작은 수치로
  대체해서 수십 dB 개선으로 세지 않는다. 음수 차이는 펌핑/상쇄일 수도 있어 그대로 남긴다.

이 값은 **스피커·공간·몸체·마이크가 함께 만든 에너지**다. 원하는 타격·배음과 독립 잡음을 분리한 값이 아니다.
미보정 폰 마이크로 절대 SPL/THD를 보증하지 않고 자동 우승 모델을 고르지 않는다. 타격 전후의 반복 가능한
실제 현상을 찾아내고 다른 관측과 대조하는 도구다. 잡음 원인 식별에는 UMIK-1 동시 녹음 등 추가 근거를 쓸 수 있다.

## 3. 저장·검증

마이크 PCM은 메모리에서만 사용한다. 폰에는 `files/acoustic_lab_calibration.json`과
`files/acoustic_lab_impact.json`의 숫자·기기/경로 정보만 남는다. 첫 파일은 3단계가 끝나야 분석할 수 있고,
두 번째는 중단 시 완료된 회차까지 남되 `complete=false`다. 공유는 사용자 버튼으로만, 네트워크 전송 없음.
화면의 지우기로 두 파일을 삭제한다. 기존 백업 규칙은 files/를 제외한다.

```sh
python3 tools/pvb-harness/test_acoustic_lab.py
# 기존 run_jvm_test.sh에도 AcousticLabTest를 포함한다.
```

검사는 알려진 응답 기울기의 별도 신호 보정, 확인 신호의 이득 이동, 경로/참조 결측, 클리핑·음소거·효과,
측정 하한, 전체 감쇠에 의한 가짜 개선, 펌핑, 불완전·중복 회차, 표식 지연·이득·극성, 측정 필터의 인과성을 다룬다.
모두 합성/호스트 검사이며 새 실기기 녹음이나 청취 판정이 아니다.
