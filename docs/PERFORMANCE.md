# 성능과 배터리 (2026-10-22 최적화)

이번 최적화의 원칙은 **들리는 소리를 바꾸지 않는 것**이다. 엔진 출력이 이전과 비트 단위로 같은지를 매번 확인하면서 계산량만 줄였다. 앱 쪽에서는 소리가 없을 때 스피커 출력을 쉬게 했다.

## 1. 측정 결과 (엔진, 호스트)

음악 40초(4곡 × 10초), 48 kHz, 블록 4096 프레임으로 쟀다. 측정 환경은 x86-64 서버 한 코어, clang -O2이고, 수치는 처리 시간을 음악 길이로 나눈 값이다.

| 설정 | 이전 | 이후 | 배수 |
|---|---|---|---|
| 일반 기본(가상 저음 P1 +4) | 30.7% | 4.8% | 6.4배 |
| 가상 저음 끔 | 2.8% | 0.5% | 5.3배 |
| S26U 설정(EQ, 음량 맞춤, 동적 저역, P1 +6) | 31.5% | 5.9% | 5.3배 |
| 실험 기능 4개 모두 켬 | 30.6% | 6.6% | 4.6배 |
| 개발자 모드 값 조정 + 표시 미터 | 29.0% | 5.4% | 5.4배 |
| D2 | 32.1% | 4.8% | 6.7배 |
| J2 (AM 계열 맞춤은 그대로) | 36.5% | 11.8% | 3.1배 |
| 발진기 / gentle / 이전 hpv / Bankstown | 8.8 / 5.7 / 4.5 / 3.1% | 3.5 / 2.5 / 1.9 / 1.0% | 2.3~3.2배 |

폰에서는 연구 메뉴를 열면 보이는 상태 화면의 "처리 부하"(M_LOAD_PCT)로 같은 곡을 놓고 이전 빌드와 비교한다.

## 2. 무엇이 CPU를 썼나 (이전)

callgrind로 P1 6초를 측정했다.

- **저음 떨림 맞춤**(`modulation::fit`)이 전체의 **76%**를 썼다.
  - 매 보코더 프레임(초당 187.5번)마다 384점 × 16열 최소제곱 문제를 Gram-Schmidt(2회)로 4~5번 다시 풀었다.
  - 그 안에서 sin/cos 라이브러리 호출이 프레임당 약 3000번이었다.
- true-peak 리미터: 6%
- 표시용 폰 리미터 모델과 음량 맞춤 필터: 3%
- FFT: 4%
- 보코더 프레임의 나머지(유지 격자 전체 탐색 등): 4%

## 3. 바꾼 것

### 엔진 (`app/src/main/cpp/libpvb`)

| 바꾼 곳 | 방법 | 출력 |
|---|---|---|
| 떨림 맞춤 (`pvb_vb_modulation.h`) | 같은 최소제곱 문제를 정규방정식(창 모멘트와 내적으로 만든 16×16 행렬, Cholesky)으로 푼다. 마지막 풀이에만 원래 행렬로 한 번 다듬는다(반복 정제). 대각 비가 100을 넘거나 피벗이 작으면 원래 방법(Gram-Schmidt 2회)으로 푼다. 합은 정해진 순서의 부분합(벡터화)으로 구한다. | 채택 여부는 동일. 채택된 값의 차이는 실제 음악에서 1e-13, 일부러 어렵게 만든 합성 신호에서 최대 1e-9 Hz |
| sin/cos (`pvb_fastmath.h`) | fdlibm의 범위 축소와 커널을 분기 없이 구현해 루프를 벡터화했다. | 0.8 ulp 이내(라이브러리는 0.52 ulp) |
| 리미터 (`pvb_dsp.h`) | 최근 32샘플이 상한에 닿을 수 없을 만큼 작으면 보간 피크 계산을 건너뛴다(그때 필요한 이득은 정확히 1). 앞보기 최솟값은 갱신식으로 유지한다. | 비트 동일 |
| FFT, 리샘플러, 보코더 프레임 | 단계별 twiddle 표, 독립 버터플라이 2개를 한 벡터로 처리, 필터가 다 찬 뒤에는 경계 검사 생략, 유지 격자는 해당 범위만 탐색, 피크별 복소 지수 1회 계산 | 비트 동일 |
| 표시용 계산 (`pvb_engine.cpp`) | 폰 리미터 추정은 미터를 읽는 화면이 있을 때만(마지막으로 읽은 뒤 3초까지) 돌린다. 음량 맞춤은 "끌 때 음량 맞춤"이 켜져 있을 때만 돌린다. | 소리 영향 없음 |

### 앱 (`RootlessAudioProcessorService`, `SilenceGate`)

- **무음 휴식**
  - 동작:
    - 캡처한 입력과 처리된 출력이 모두 2초 동안 무음이면(16비트 1단계 이하) 출력 트랙을 일시정지하고 처리를 멈춘다. 그러면 스피커 경로(DSP, 앰프)가 대기 상태로 들어갈 수 있다.
    - 소리가 다시 들어오면 그 블록부터 바로 재생한다. 캡처는 계속하므로 놓치는 소리는 없다.
  - 배경: 음악 앱은 일시정지해도 세션을 유지하는 경우가 많다. 그래서 지금까지는 무음을 계속 처리해서 재생했다.
  - 예외: 블라인드 비교, 측정, 진단 녹음 중이거나 개발자 모드 시험 소리가 나는 동안에는 쉬지 않는다.
  - 설정: 기존 "유휴 시 절전" 설정을 따른다.
- **세션이 없을 때 대기:** 50 ms마다 깨어나던 확인(초당 20회)을 바꿨다. 이제 세션이 바뀌면 바로 깨어나고, 그 밖에는 250 ms마다 확인한다.

넣지 않은 것: 일시정지가 오래 이어질 때 캡처(녹음)까지 멈추는 "깊은 절전"이다. 시스템 절전에는 가장 크게 도움이 되지만, 재생을 다시 시작할 때 첫 0.1초 안팎이 잘릴 수 있다.

## 5. 폰에서 확인할 것

1. **처리 부하:** 상태 화면(연구 메뉴)의 "처리 부하 %"를 같은 곡으로 이전 빌드와 비교한다.
2. **무음 휴식:** 음악을 일시정지하고 3초 이상 기다린 뒤 다시 재생한다. 시작 부분이 잘리거나 딸깍 소리가 나면 안 된다. 쉬는 동안 상태 화면은 "대기 중"으로 바뀐다.
3. **배터리:** 같은 조건(음량, 화면 꺼짐, 1시간 재생, 그중 일정 시간은 일시정지)에서 설정 → 배터리의 앱별 사용량을 이전 빌드와 비교한다.
