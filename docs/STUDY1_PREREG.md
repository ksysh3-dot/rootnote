### 질문
사용자가 보고한 "강한 타격 전후로 잡음이 치솟았다가 안정됨"(청감 보고, 미측정)에 대응하는 합성 지표가 **어느 처리 단계에서 생기고 커지는가.** 새 보호 규칙을 만드는 연구가 아니다. 다음 수정의 위치를 정하는 연구다.

### 대상 모델 (동결)
P1+ (`flags=6`, impact mode 0)와 P1++ v0.3 (`flags=6`, impact mode 8). 엔진 설정: `vb_level_db=6`, `ramp_ms=0`, 출력 **−18 dB와 −3 dB 두 조건**. 단계 B의 모든 항목(oracle 렌더, 주입 무결성, 반올림 대조 R, 리미터 계기, G/L 판정, 어택 예산)은 **두 출력 조건에서 각각 실행하고 출력별로 따로 판정한다**(F2).

### 측정량 E: 비가산 상호작용 에너지 (D1 반영)
같은 설정으로 세 번 렌더한다: 혼합 `x = bed + impact`, `bed`만, `impact`만.
`I = stem(x) − stem(bed) − stem(impact)`. 보고 지연으로 정렬하고, 개별 이동·이득 맞춤은 하지 않는다. **E = I의 구간 에너지(입력 타격 에너지 대비 dB). 원 에너지도 함께 기록한다(1e−30 절단 없이).**
- **E는 "두 소리가 만나서 생긴 비가산 상호작용 에너지"이며, 오류의 상한이 아니다.** 정당한 비선형 응답(HPSS 분리 등)도 섞인다. 오류와 정당한 성분이 서로 상쇄될 수도 있으므로, E가 작다고 오류가 작다는 보장은 없다.
- **시간 기준:** `pre`는 타격 시작(onset) 전 150 ms ~ 5 ms이고, `attack`은 onset부터 타격 종료(onset+duration)까지다. **`early`(0–80 ms)와 `late`(80–500 ms)는 타격 종료 시점이 0이다.** 단계 신호의 시각은 3 kHz core 시계 위치이며, 단계별 지연 모델은 없다.
- 직후 구간은 배경음 생성층 모양으로 설명되는 부분과 나머지로 나눠 보고한다.

### 단계 A/A.1/A.2 결과 (개발군만) — #4 진행 기록 2·3·5
- **수치 대조 (D1 BLOCKING 해소):**
  - v1의 "바닥 −273.6 dB" 표기는 **철회한다.** 블록 불변성은 세 번 렌더하는 분해의 오차 상한이 아니기 때문이다.
  - 대신 **입력 반올림 민감도**를 쓴다. 두 입력의 float32 합으로 렌더한 결과와 혼합 렌더의 생성층 차이를 R이라 할 때, 개발군 60설정 × 2구간 × 2출력에서 **R/E는 최대 −118.5 dB, 중앙값 −148 dB였다. 25%는 정확히 0이었다.**
  - 판정 규칙: 어떤 구간에서 R/E > −20 dB이면 그 구간은 dB비 순위에서 제외하고 절대값만 보고한다. 확인군에서도 같은 대조를 반드시 실행한다.
- **리미터 (D4 반영):** 개발군 60설정에서 혼합·bed·impact 각각의 리미터 최소 이득 계기(`LIM_GR_DB`, 렌더 전체 구간)가 **180개 렌더 모두 정확히 0 dB(이득 1)였다**(출력 −18/−3 dB 모두). **배제 범위는 이렇게 관측된 설정(이 생성기, 타격 피크 ≤ −6 dBFS, 두 출력 수준)에 한정한다.** 확인군에서도 렌더마다 같은 계기를 기록한다. 0이 아닌 렌더가 있으면 그 설정에서는 리미터를 배제하지 않는다. v1의 근거로 쓴 "리미터 기여 0.0 dB"는 두 dB 값의 차이였으므로 근거에서 뺀다.
- 비가산성이 처음 나타나는 곳은 ② HPSS 타악 분리(+10 ms)다. 이어 ④–⑥ 진폭·합성 단계로 전파된다.
- **킥:** 진폭 상태가 배경음 상태로 돌아오기까지 121–184 ms(중앙값)가 걸린다.
- **광대역:** 상태는 4 ms 안에 돌아오지만 E_late가 킥보다 35 dB 크다. v0.3은 광대역에서 P1+와 결과가 같다.

### 단계 B — 반사실 oracle 비교 (D2 반영; 호스트 전용 `StageInject52`, 기본 mask 0이라 앱 경로 불변)
**해석 원칙:** 아래 교체는 "그 단계의 비가산분만 정확히 제거"하는 것이 아니다. **그 단계를 정해진 oracle로 바꿨을 때 E가 얼마나 변하는가**를 잰다.
| ID | 단계 | oracle | 현재 상태 |
|---|---|---|---|
| B1 | ② HPSS 출력 | **가산 oracle**: 혼합 렌더의 `selected_h/p`를 같은 core index의 `S(bed)+S(impact)`로 바꾼다. H/P 합과 시간축이 보존된다. 구간은 onset −150 ms부터 끝까지 | 구현됨 |
| B2 | ④ 포락선 목표 | **bed-only oracle**: `env_a`(as)·`env_p`(ps)를 bed-only 렌더 값으로 바꾼다. 시작점은 impact만 렌더의 `env_a`가 최고치의 10% 아래로 떨어진 시점이다. **env10으로 고정**한다. 개발군에서 env10·env50·aligned가 모든 설정에서 결과가 같았다(진행 기록 6) | 확정 |
| B3 | ③ 피크·트랙 인정 | bed-only oracle(주파수 ±3% 대응) | **판정에서 제외한다.** 사전 조건 (c)를 모든 개발 설정에서 통과하지 못했다. impact만 렌더의 변화가 −11 ~ +18 dB였고, 기준은 ≤ −20 dB다. (b)에서도 일부 ID 중복이 남았다(진행 기록 7). 출처 기반 대응 B3′는 후속 연구 후보다 |
- **B3 사전 조건:** 구현 시 (a) 트랙 대응표(혼합 ↔ bed / impact), (b) 교체 후 위상·수명 상태의 일관성 검사, (c) **정상 타격 보존 대조**를 보고해야 한다. (c)는 impact만 입력한 렌더에 B3을 적용했을 때 생성층이 바뀌지 않는지 확인하는 것이다. 이 셋을 충족하지 못하면 B3 결과는 귀속 판정에 쓰지 않는다. 자기 주입 비트 동일만으로는 충분하지 않다.
- **조합(TH1):** leave-one-out 3개, leave-one-in 3개, 전체 1개 = 7조합. 두 방식의 판정이 어긋나면 "상호작용"으로 표시한다. B3이 없으면 B1·B2의 3조합(B1, B2, B12)만 보고하고, 그 한계를 기록한다.
- **기여 판정(설정별):** 감소 ≥50%는 주기여, 10–50%는 부분, 10% 미만은 작음.
- **주입 무결성:** 혼합 렌더에 자기 값을 주입하면 생성층과 출력이 비트 동일해야 한다. 자기 기록 트랙 테이프 재생도 마찬가지다. 모든 코호트에서 파형 × 모델 × 출력마다 첫 세기 설정으로 검사한다. 하나라도 다르면 실행을 멈춘다. 개발군 22건(−18 dB)은 모두 동일했다.

### 판정 문턱 (연구 임시 기준 — 가청 문턱 아님)
- **개선·악화 혼재 판정 (사용자 결정 2026-10-28, TH2의 "악화 0건" 조건을 대체):** 악화가 있다는 이유만으로 기각하지 않는다. 개선 폭과 악화 폭을 비교한다. 반올림 대조를 통과한 구간만 쓴다.
  - **G (개선 폭)** = 해당 유형에서 파형 단위 E 감소의 중앙값(dB).
  - **L (악화 폭)** = 악화된 파형들의 E 증가 가운데 최댓값(dB). 악화 파형이 없으면 0이다.
  | 판정 | 조건 | 처리 |
  |---|---|---|
  | **채택에 가까움** | G ≥ 3 dB, 파형의 2/3 이상(킥 6/8, 광대역 3/4)에서 감소, **L ≤ G/2** | 귀속 성립. 악화 사례는 목록으로 공개하고 기각 사유로 쓰지 않는다 |
  | **보류 / 옵션** | G ≥ 3 dB, 2/3 이상에서 감소, 그러나 **L > G/2**(악화가 개선과 비슷한 수준) | 귀속은 "혼재"로 기록한다. 후속 수정은 기본값이 아니라 실험 옵션으로만 다룬다 |
  | **미성립** | G < 3 dB 또는 감소 파형 < 2/3 | 귀속 미성립 |
- **보존 비용 (유일한 규칙; F3·F4):** 이 연구의 보존 비용 척도는 **어택 구간 생성 에너지 변화** 하나다.
  - 포락선 %p 예산(TH3)은 이 연구에 **적용하지 않는다(N/A).** oracle은 수정 후보가 아니기 때문이다. TH3는 이후 수정 후보 연구에 적용한다.
  - **값:** `{oracle}_attack_change_db` = 10 log10(oracle 렌더의 어택 구간 생성층 에너지 / 원래 혼합의 같은 에너지).
  - **예산:** oracle × 모델 × 출력 × 유형마다 계산한다. 파형 단위(세기 중앙값) 값의 중앙값이 **−1 dB 이상**이고, 설정별 최악값이 **−3 dB 이상**이면 예산 안이다.
  - **적용:** 개발군과 보존군에서 각각 계산한다. 둘 중 하나라도 예산을 넘거나 계산되지 않았으면 **채택에 가까움은 보류/옵션으로 낮춘다. 보류/옵션은 그대로 두고 초과 내역만 기록한다. 미성립은 그대로다**(사용자 결정 2026-10-28). 기각 사유로는 쓰지 않는다.
  - 확인군 자체의 어택 변화는 기록만 하고 이 규칙에는 쓰지 않는다.
  - 판정 JSON에는 `raw_verdict`(G/L만으로 낸 판정), `budget_exceeded_in`, `budget_not_checked_in`, `verdict`(최종 판정)를 함께 남긴다.
  - 진짜 종료 반례(보존군 `ends`)는 개별로 보고한다.
  - 참고(이전 −18 dB 관측): B2는 최저 0.0 dB, B1은 최저 −6.8 dB(개발군) / −3.9 dB(보존군)였다.
- **G·L 산출 세부 (관문 ① 2차 검토 반영):**
  - G와 L은 oracle(B1/B2/B12…) × 모델(P1+/v0.3) × 출력(−18/−3 dB) × 구간(early/late) × 유형(킥/광대역)마다 따로 계산한다.
  - 파형 단위 값은 그 파형의 두 세기에서 나온 E 변화(dB)의 중앙값이다.
  - G/2 기준은 dB 단위의 허용치로 해석한다. 예: G = 6 dB이면 L ≤ 3 dB.
  - 판정은 L로 하지만, **설정별 최대 악화(세기별)도 따로 공개한다.**
- **제외 규칙:**
  - 반올림 대조 마스크(R/E > −20 dB인 구간)는 원래 렌더에서 한 번만 정하고, 모든 oracle에 같은 마스크를 쓴다.
  - 에너지 0, 0/0, 유한하지 않은 값은 제외하고 그 개수를 공개한다.
  - 제외한 뒤 유효 파형 수가 판정 분모(킥 6/8, 광대역 3/4)를 채우지 못하면 **미성립**이다.
- **R의 한계:** R은 입력 반올림 한 가지 경로의 민감도다. 모든 수치 경로를 포함한 오차 상한이 아니다.
- **2차 분석(사전 등록):** −6 dBFS 설정만으로 같은 G·L 판정을 한다. 파형 단위 값은 단일 세기 값이다. 1차 판정을 대체하지 않으며, 사용자 증상("강한 타격")과 세기 의존성(진행 기록 6)을 보기 위한 분석이다.
- **해석:** 귀속이 성립해도 "그 단계를 고치면 들리는 잡음이 준다"는 주장은 아니다. 수정 후보 채택은 별도 연구와 연구 2(실기기) 관문을 거친다.
- **중단 규칙:**
  - 확인군에서 실패하면 실패로 기록한다. 같은 확인군에 맞춰 다시 조정하지 않는다.
  - 단계 B 대상을 바꾸려면 개발군에서 다시 시작하고, 확인군은 새 seed를 쓴다.
  - 같은 실패 패턴이 2회 나오면 연구 종료를 제안한다.

### 확인군 실행 절차 (F1)
1. 이 문서와 코드를 담은 커밋에 동결 태그 `s1-v2-final`을 붙이고 push한다. 그 커밋의 **전체 SHA**를 #2·#4에 기록한다.
2. `research-s1.yml`을 `workflow_dispatch`로 실행하고, 입력으로 `frozen=s1-v2-final`과 `frozen_sha=<전체 SHA>`를 준다. 워크플로는 태그 자체를 checkout한다.
3. 스크립트는 다음을 모두 확인한다. 하나라도 어긋나면 확인군을 열지 않고 실행을 멈춘다.
   - 태그가 존재하는가.
   - 태그가 가리키는 커밋이 `frozen_sha`와 같은가.
   - 실제로 checkout한 HEAD가 `frozen_sha`와 같은가.
   - 추적 파일이 수정되지 않았는가.
   - 개발군·보존군 예산 보고서가 같은 커밋에서 나왔는가.
4. 같은 실행 안에서 보존군 → 개발군 → 확인군 순서로 돌린다. 결과 JSON의 `checkout`에 위 확인값(checkout SHA, 태그 SHA, 추적 파일 변경 여부)을 남긴다.
