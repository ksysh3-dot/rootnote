## Resultant R4: 기본음 80–150 Hz에서 P1이 하는 일 (해체, 개발 자료만)

**상태:** 개발 관찰 (2026-10-30). 확인 아님. 앱·기본값 불변. Slakh validation 270곡 미개봉.
**질문:** 최신 음악 베이스의 기본음은 대부분 55–150 Hz다. P1은 서브베이스 (예: 45 Hz 사인, 층이 4–8차 180–360 Hz에 놓임)에 맞춰져 있다. 80–150 Hz에서는 무엇이 막고 있나.

### 해체 측정 (`research_r4_band_anatomy.py`; Slakh train 60곡 MIDI 참조 (BabySlakh 겹침 제외, 30–90 s), MUSDB 144곡 YIN 참조)
| f0 대역 | 추적 (Slakh / MUSDB) | 층 에너지 k2 / k3 / k4 몫 | 층/원래 배음, 앱 기본 (k2, k3) | 원래 배음 위에 더하는 양 (k2, k3) |
|---|---|---|---|---|
| 55–80 | 89 / 79 % | 1 / 26–30 / 9–14 % | (−58), −16 dB | 0.0, 0.1 dB |
| 80–100 | 94 / 92 % | 33–35 / 8–10 / <1 % | −10 ~ −15, −13 ~ −18 dB | 0.1–0.4, 0.1–0.2 dB |
| 100–125 | 88 / 90 % | 43–44 / 2 / 0 % | −12 ~ −13, −26 dB | 0.2–0.3, 0.0 dB |
| 125–150 | 94 / 85 % | 37–42 / 1 / 0 % | −22, −32 ~ −34 dB | 0.0 dB |

- **음 찾기는 문제가 아니다.** 추적률이 85–94 %다.
- **100 Hz 위에서 층은 사실상 2차 하나다** (200–300 Hz, 폰 스피커가 가장 약한 대역). 앱 기본값으로 100 Hz 사인을 넣으면 층은 k2 −12.8, k3 −25.1, k4 −36.9, k5 −63 dB다 (입력 기본음 대비).
- **원래 배음보다 10–35 dB 작아 더하는 양이 0–0.4 dB다.** 이 대역에서 P1은 거의 들리지 않는다. 원래 베이스의 k2는 기본음 대비 0 ~ −7 dB로 이미 강하다 (Slakh 신스는 더 강하다).
- 층 에너지 중 배음 창 (±max(3 Hz, 1.5 %)) 안 몫이 0.38–0.56인 것은 측정 한계다 (128 ms Hann 창 주엽이 창보다 넓다). 층이 비배음적이라는 증거가 아니다 (Fable 검토).
- 더하는 양은 전력 합으로 계산했다. 위상이 맞는 경우는 과소 평가다. 다음 지표 (기기 가중 배음 이득, 아래)로 바꾼다.

### 원인 (코드, `pvb_vb52.cpp` renderTrack52 104–113)
앱 P1 (알고리즘 6, `gentle` + upperMode 1)은 **220 Hz 위의 지속 배음을 옥타브당 24 dB씩 깎는다** (고정 모서리). 가중치 표 자체는 100 Hz에서 k2:k3:k4를 0 : −1.8 : −3 dB로 거의 평평하게 의도한다. 감쇠와 출력 LP2 600 Hz를 합친 예측 (k3/k2 −12.5, k4/k2 −24.5 dB)이 측정 (−12.3 / −24.1 dB)과 맞는다. 45 Hz에서는 층이 220 Hz 근처라 거의 깎이지 않는다. 그래서 서브베이스는 되고 100–150 Hz는 2차만 남는다.

- LP 600 → 800 Hz는 거의 효과가 없다 (가중치 표가 k5 이상을 이미 0으로 둔다).

### R4 후보 (다음 단계, 아직 구현 전)
1. **음역 기준 감쇠 모서리:** `c = max(220, 3 f0)`. 판정 (`k f0 > c`)과 기울기 (`log2(k f0 / c)`) 둘 다에 쓴다. 버스트 경로 (`burstSample52`)도 같다. f0 < 73 Hz에서는 P1과 비트 단위로 같다. 위험은 gentle24가 막으려던 지글거림·울림이 220 Hz 위에서 다시 생기는 것과, 다른 악기 배음에 잘못 잠기는 것이다.
2. **부족분 채우기:** 원래 배음이 이미 있으면 (`found`, 추정 진폭 `ae`) 목표에서 그만큼 빼고 렌더한다 (0에서 자름). 중복을 막고 1번의 과잉을 막는 상한이다. 신스 베이스에서는 층이 거의 없어질 수 있다.
3. (1·2에서 여지가 보이면) 80 Hz 이상 가중치 표를 기기 가중 지표로 다시 맞춘다.
4. 원래 배음을 음높이에 맞춰 키우는 방식 (동적 EQ)은 실제 베이스의 k3·k4가 20–45 dB 낮아 효과가 작을 것으로 본다.
5. 타악 경로 게이트가 100–150 Hz에서 열리는지 먼저 본다 (stage capture `percussion_gate`).

**지표 (개발):** 기기 가중 배음 이득 (DWHG). 앱 출력 (dry, dry+층)에서 k f0 사인 최소제곱 적합 진폭에 폰 응답 (4차 HP, f_c 400/500/700 Hz와 800 Hz +4 dB 공진)을 곱한 합의 비다. 같은 전체 수준으로 맞춘 뒤 잰다. 해악 항목은 세 가지다: 층의 배음 적합 SNR (≥ 10 dB), `PhoneModel` 보호 리미터 GR 변화 (250·500 Hz 대역), 같은 계열 부분음 3개 이상. 서브베이스 무회귀는 f0 < 73 Hz 비트 비교와 `song_ring.py`로 본다.

### 24 dB/oct는 왜 있나: 노이즈 원인 조사 (2026-10-30, 엔진 변경 없음)
**기록:** `docs/LAB_PLAN.md` 14차 청감에서 "위쪽 배음 +24 dB/oct" (= 감쇠 없음)가 거울미로 (LOGOFF)에서 노이즈였다. "+12"는 400 Hz 위에서 차이가 없었다. 시험의 세기·렌더 조건은 저장소에 없다. 사용자 요구: **노이즈 없이** 이 제약을 풀 방법을 찾는다.

1. **생성기 자체는 높은 차수에서도 깨끗하다** (`research_r4_purity_synth.py`). 42.7 ms 창에서 생성기의 k f에 대해 공동 최소제곱 적합을 하고, 남는 몫을 '비정상'으로 본다. 일정한 사인 45/100/125 Hz는 감쇠가 기본이든 평평이든 비정상 몫이 −80 ~ −190 dB다. 뜯는 음 (−10 ~ −17 dB), 비브라토 (−10 ~ −21 dB; 창 안 주파수 변화라 일부는 지표의 한계), 서브베이스+킥 (−20 ~ −30 dB, 400–600 Hz −0.5 dB)에서만 비정상 몫이 생긴다. 이 비율은 감쇠 설정과 거의 무관하다.
2. **LOGOFF 30–90 s** (`research_r4_noise_anatomy.py`): 평평하게 하면 층이 250–400 Hz에서 +9 dB, 400–600 Hz에서 +20 dB 커진다. 비정상 몫 비율은 −6 ~ −8 dB로 기본과 같다. 즉 새 종류의 잡음이 아니라, 원래 있던 변조 성분 전체가 덜 가려지는 대역에서 커진다. (원음과의 맥놀이 지표는 변별력이 없어 버렸다.)
3. **거칠기 (단순 Daniel–Weber형, `research_r4_roughness.py`).** 1 ERB 대역마다 포락선 변조 20–200 Hz를 70 Hz 정점으로 가중해 잰다. 앱 기본 체인 다음에 S26 Ultra 모델 (`study/phone_model.py`의 동적 처리기 + 스피커·실내)을 거친다. 아래는 200–600 Hz에서 층을 끈 출력 대비 변화다.
   - LOGOFF 30–90 s: 기본 −0.3 %, 12 dB/oct 0.0 %, 평평 +1.1 % (타격 +2.0 %). 기본 +6 dB는 −0.4 %, 평평 +6 dB는 +3.6 % (**타격 +5.4 %**). 순서와 "타격 때 지글거림, 세기를 올릴수록 심함"이라는 증상의 방향이 청감 기록과 같지만 크기는 작다.
   - 합성 베이스 (감쇠하는 3배음 음 + 킥 + 분홍 잡음, `research_r4_make_synth.py`), 평평 +6 dB: 45 Hz +13.7 %, 55 Hz **+57.9 %**, 100 Hz +27.5 %, 125 Hz −20.2 %. 기본 +6 dB는 각각 +3.6 / +12.5 / +8.6 / −7.7 %다.
   - **가설 "분리되는 배음 (f0 > 청각 필터 폭)은 거칠지 않다"는 이 지표로 확인되지 않았다** (100 Hz도 증가). 지표는 귀로 보정되지 않은 근사다 (Butterworth 대역의 넓은 옆자락이 f0 간격 맥놀이를 거칠기로 셀 수 있다).
4. **판단:** 노이즈는 감쇠를 풀어 생기는 새 잡음이 아니다. 층의 변조 (특히 타격 순간)가 덜 가려지는 대역·수준으로 올라오는 현상으로 보인다. 그래서 풀 수 있는 조건은 "언제·얼마나 올리느냐"다. 후보: (a) 음역 모서리 `max(220, 3 f0)` (서브베이스 불변), (b) **타격 보호**: 저역 타격 뒤 짧은 구간 (~150 ms)에는 24 dB/oct를 유지하고 지속 구간에서만 푼다, (c) 세기·입력 수준에 따라 푸는 양을 줄인다. 채택 전에 **청감으로 지표를 보정**해야 한다. 블라인드 세트: LOGOFF 기본 vs 평평 (+6), 80–150 Hz 곡 기본 vs 후보, 같은 소리 쌍 포함.

### R4 후보 구현과 개발 평가 (2026-10-30, 호스트 전용 플래그, 앱 불변)
**구현** (`pvb_vb52.cpp`, `pvb_vb_stage.h`, 커밋 281d47e·12a183e):

- `StageOnsetProtect` (33554432, 위와 함께): 저역 타격 (`onsetLeft_`) 뒤 처음 `hold` 홉 동안 모서리 몫을 `floor`로 낮춘다 (~10 ms). 그 뒤 `tau`로 돌아온다. 버스트는 220 Hz다. 조절은 `pvb_set_r4_research(hold, floor, tau)` (기본 24, 0, 60 ms)다.
