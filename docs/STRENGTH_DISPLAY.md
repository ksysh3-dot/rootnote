# Strength display coordinates

`StrengthDisplay.STRENGTH_DISPLAY_OFFSET_DB` is the single offset, currently **0**.
The s59 measurement will inform a later user decision. Only this constant needs
changing for an integer-dB offset. `display = actual + offset`; an edit subtracts
the offset before writing, then clamps to the existing actual range.

| Boundary | Units |
|---|---|
| Home/XML/Compose/developer widgets, accessibility ranges, numeric entry | Display dB |
| Settings, profiles, presets, track memory, DevParams arrays, RN1 payload/defaults | Actual dB |
| VolumeLevelLink, engine encoder, JNI and research JSON/CSV | Actual dB |
| A/B screen labels, remembered-song labels, fit results and settings copy | Display dB |
| Historical research records, including their saved labels | Actual dB, converted when rendered where structured values exist |

Physical slider range remains -6..+12 dB. General retains its existing +9 dB cap
outside developer mode; developer/s26u retain +12. At offset +3 these appear as
-3..+15 (general normal cap +12); at -2 they appear as -8..+10. The base/S26U default and
fullness preset remain actual +4, shown as +4/+7/+2 respectively. Device-profile
defaults (including neutral 0) are preserved. Volume-link
reductions and relative harmonic gains are differences, so their numbers do not
shift. Applied strength can lie below the slider floor and is displayed without
raising it to that floor. P1+++ keeps its fixed physical layer; its strength
editors are disabled and indicate not applicable.

All pre-existing storage paths already used actual dB, including the alpha 1/2
list migrated by schema 4. No subtractive migration or new schema is appropriate:
it would change existing audio. Tests check the existing versioned migration,
current-value precedence and idempotence; changing the display offset leaves
stored values untouched. RN1 remains actual and works across different offsets
without a format/version change. Fit records and exported research text retain
their original actual-dB evidence.

JVM tests: `:app:testRootlessFdroidGeneralPreviewUnitTest` and
`:app:testRootlessFdroidS26uPreviewUnitTest`, with `--max-workers=2 --no-parallel`.
`StrengthDisplayTest` checks 0/+3/-2, finite round trips, limits, non-finite
fallbacks, migration, presets, RN1 and production UI/actual boundaries.
`cbc393b-strength.tsv` was generated by compiling the unmodified cbc393b sources
with `StrengthRegressionStates`: 24 states across both flavors, signed levels,
volume link, developer mode, routes, rates, bypass and P1+++.
It records home values/labels/caps, preset writes, copied-settings text and RN1,
plus SHA-256 of each complete little-endian raw-float engine packet. The s63
verification also compares all 5,568 raw packet bytes directly with `cmp` and
recompiles temporary +3/-2 presentation constants outside the worktree.
Android UI compilation and JVM checks do not establish TalkBack/device behavior.
