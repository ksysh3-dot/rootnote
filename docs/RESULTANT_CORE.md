# Resultant 코어 설계서 v1 (2026-10-30)

상태: 설계 (관문 ① 검토 전). 코드는 아직 없다. 이 문서는 구현 (Sonnet)과 검증 (Sonnet, 구현과 다른 에이전트)의 기준이다. 숫자 문턱은 구현 전에 정한 것이고, 결과를 본 뒤에 바꾸지 않는다. 바꿔야 하면 버전을 올리고 이유를 적는다.

## 0. 요약
P1의 고질병은 **배음층의 크기를 음악이 아니라 분석 관문이 정한다**는 것이다. 새 코어는 P1의 앞단 (대역 경로·HPSS·트래커·표·위상 정렬)을 그대로 두고, 지속층의 크기 경로만 새로 만든다.

- **무엇이 울리나** (음높이 후보): P1의 128 ms 트래커가 정한다. 바꾸지 않는다.
- **얼마나, 언제 울리나** (진폭·위상): 트랙 주파수에서 짧은 창으로 최소제곱 (LS)을 풀어 입력에서 직접 읽는다. 해상도는 10–64 ms다.
- **합성**: 목소리마다 위상이 이어지는 발진기로 k·f 배음을 표본 단위로 만든다.
- **신뢰도**: 맞춤 검사 (Fit)는 더 이상 층을 끄지 않는다. 목소리가 태어나고 끝날 때만 관여한다.

지연·출력 대역·엔진 체인·앱은 바꾸지 않는다. 새 경로를 고르지 않으면 P1은 비트까지 같다.

## 1. 근거 (진단)
- **층의 존재를 관문이 정한다.** P1 지속층은 128 ms 정상 사인 맞춤 (`kPvN` 384 @ 3 kHz, 잔차 ≤ −15 dB)과 28 hop 이력 유지 (`hold52_`)를 통과해야 fade가 1로 간다 (`pvb_vb52.cpp` `tr.fade+=...`). 그래서 다음이 생긴다.
  - 같은 음을 다시 치면 매번 약 0.2초 비고 (`research_r4l_trace_gap.py`), 노이즈나 믹스에서는 깜빡인다 (`research_r4l_gate_flicker.py`: 음마다 실패 0–41 hop, 전환 ≤ 10회).
  - 글라이드에서도 정상 맞춤이 실패한다.
- **끌어내리기만 한다.** 음악 엔벨로프 강제 `gain = clampv(as/ps, 0, 1)` (`core52`)는 층을 줄일 수만 있고, 빈 곳을 채우지 못한다.
- **P1이 깨끗한 이유.** 층이 입력 배음보다 약 7 dB 아래라 관문의 흔적이 가려지기 때문이다. 층을 그보다 올리면 (R4c 단독 +3 dB, L6 +9 dB) 흔적이 모두 들린다. R4-L v1/v2 블라인드 4회가 이것을 보였다 (docs/RESULTANT_R4.md).
- **음높이 측정** (`research_resultant_pitch_truth.py`, Slakh train 6곡, 베이스가 큰 hop 19 373개):
  - 가장 센 40–220 Hz 트랙이 틀린 비율은 20.0 %이고, 그중 옥타브·12도 오류가 7.4 %다.
  - 어떤 트랙이든 맞는 비율은 88.6 %다.
  - 그러므로 하나의 음을 골라 입히는 설계는 안 된다. 트랙마다 따로 처리한다.

## 2. 목표와 비목표
- **목표**
  - G1: 층 크기가 입력 음을 따른다. 재어택·글라이드·노이즈에서 공백과 깜빡임이 구조적으로 없다.
  - G2: 기본 음색 (L = 0, P1 voicing)에서 정상 상태 수준과 위상 정렬이 P1과 같다. 같은 크기로 비교할 수 있어야 한다.
  - G3: 공격적 음색 (음역 모서리 + 세기)을 관문 흔적 없이 낼 수 있다.
  - G4: 지연·출력 대역·엔진 체인·앱은 그대로다. P1 (알고리즘 0–14)은 비트까지 같다.
- **비목표 (이번 범위 아님)**
  - 타격층 (HPSS 타격부의 u^k 발생기) 재설계.
  - 트래커 교체.
  - 73 Hz 아래 R3-a 동작 변경.
  - 앱 통합.

## 3. 시간축 정의 (구현이 반드시 지킬 것)
- 코어 표본률은 fs = 3000 Hz, hop H = 16이다. hop h는 코어 인덱스 `i_h`에서 `pvFrame52()`가 불릴 때다 (`(i−383)%16==0`, future = 0).
- **입력 시간 축** (decimated input d의 인덱스): 분석 중심은 `c_h = i_h − 382`다 (P1 trace 헤더 [9]와 같다).
- **bh 인덱스 축**: bh (`bhRing_`)와 대역 지연 신호 (`detailRing52_`), d 지연 신호 (`md2_52_`)의 인덱스 j는 입력 시간 j − 191에 해당한다. 따라서 c_h에 해당하는 인덱스는 `n_h = i_h − 191`이다. 쓸 수 있는 미래는 n_h + 191 = i_h까지다.
- **출력 코어 시간 축**: hop h의 추정값은 출력 코어 시각 `C_h = i_h + 16`에 놓인다. 출력 표본 n은 입력 시간 n − 398에 해당한다 (P1과 같다).
- **쓰는 구간**: hop h는 출력 표본 [C_{h−1}, C_h) = [i_h, i_h + 16)을 쓴다. core52가 표본 i_h를 읽기 전에 pvFrame52가 끝나므로 인과적이다 (StageOscillator와 같은 방식).
- **지연**: 모듈 지연 (`latencyFrames`)은 P1과 같아야 한다. 엔진의 원음 정렬은 바꾸지 않는다.

## 4. 구조와 통합
### 4.1 블록도
```
x(48k) ─▶ [P1] 3 kHz 변환 ─▶ LR4 190 Hz ─▶ HPSS ─┬─ bh (조화부) ─▶ [P1] PV 트래커 (128 ms) ─▶ 트랙 목록
                                                  │                                              │
                                                  │      ┌───────────── [새] 목소리 관리 ◀──────┘
                                                  ├──────▶ [새] 짧은 창 LS (진폭·위상) ◀── detailRing52_/bh
                                                  │      ├─ [새] 입력 부분음 위상 (md2_52_) ─▶ 정렬 목표 ψ
                                                  │      └─ [새] 발진기 합성 (k=2..8) ─▶ s_res
                                                  └─ bp (타격부) ─▶ [P1] u^k 발생기·gate·poly ─▶ hp
                         s_res + hp ─▶ [P1] 출력 필터 150–600 Hz ─▶ 48k ─▶ 엔진 (원음 지연·섞기·리미터)
```
### 4.2 통합 방식
- **새 파일** `app/src/main/cpp/libpvb/pvb_resultant.h/.cpp`에 `class ResultantCore`를 둔다.
  - 담는 것: 목소리 관리, LS, 위상, 발진기.
  - 고정 크기 배열만 쓰고, 오디오 스레드에서 할당하지 않는다.
- **VbHpv 연결점** (최소 변경, 모두 `if(resultant_)`로 막는다. 포인터가 null이면 P1과 비트 동일):
  1. `ResultantCore* resultant_=nullptr;` 멤버와 `friend class ResultantCore;`를 추가한다.
  2. `pvFrame52()`: 트랙 갱신 (선택·잔차·fade·이력 등)은 그대로 둔다.
     - `resultant_`가 있으면 `renderTrack52`와 `addGrain52`를 부르지 않는다. 이는 맞은 트랙과 잃은 트랙 두 갈래 모두에 해당한다.
     - 대신 hop 끝 (`std::copy(next...)` 뒤)에서 `resultant_->hop(*this)`를 부른다.
     - 측정 없이 일찍 돌아가는 경로 (`missingFrame52`, Absolute/NoPeak/Relative)에서도 `resultant_->hop(*this)`를 불러서 목소리를 정상적으로 해제한다.
  3. `core52()`: `resultant_`가 있으면 `preFilter = resultant_->sample(i_) + hp`로 바꾼다. 엔벨로프 강제 (appliedGain)와 그레인 (`out`)은 섞지 않는다. 나머지 (`hp`, `poly52_`, 출력 필터 `out_`, stage capture)는 그대로다.
- **새 모듈** `VbResultant final : VbModule`
  - 안에 P1 프로필 (`setAlpha2Profile(VB_ALPHA2_P1)`)의 VbHpv와 ResultantCore를 가진다.
  - `tick`, `configure`, `reset`, `latencyFrames`는 안의 VbHpv에 넘긴다.
- **새 알고리즘 번호**
  - `VbAlgo`에 `VB_RESULTANT = 15`를 추가한다 (`VB_ALGO_COUNT` 16). 엔진 `vbMods_`에 연결한다.
  - 엔진의 `if (algo >= VB_ALPHA2_P1) vbAlpha2_.setAlpha2Profile(algo)` (`pvb_engine.cpp` 262)를 15가 타지 않게 고친다. `pvb_engine.h` 206/214의 `vbDelay_` 갱신도 15일 때 새 모듈의 지연을 쓰게 맞춘다.
  - 앱 (`PvbModels`)에는 추가하지 않는다. 앱에서 고를 수 없어야 한다. 앱이 저장된 번호를 검증하는 방식을 확인하고 문서에 적는다.
- **호스트 연구 API** (`tools/pvb-harness/pvb_capi.cpp`):
  - `int pvb_set_resultant(void* e, const double* v, int n)`: 매개변수 (5.8)를 받는다. n이 짧으면 기본값을 유지한다. 범위를 검증하고 1 또는 0을 돌려준다.
  - `pvb_resultant_trace_enable(e, capacity)`와 `pvb_resultant_trace_copy(e, double* out, int cap)`: hop마다 목소리마다 다음 필드를 고정 순서로 기록한다. `[core index of hop, voice id, track id, state, f, dfdt, A, c, sigma, N, snr_db, raw_db, res_db, subordinate, theta_hat, psi_2, psi_3, a_2, a_3]` (총 19개).
### 4.3 유지하는 것 (코드 그대로)
- 변환·대역: `configure`, FIR 변환, `band_` LR4.
- HPSS: `hpssFrame`, `olaH_`/`olaP_`.
- 타격 발생기: `bandLayer`, gate, `polyCausal52`/`poly52_`.
- PV 트래커 전체: 피크·잔차·종속 피크 제거·이력·트랙 배정.
- 표 `lookup(f,w,gain)`, `psi52` (R1 위상), 출력 필터 `vbt::kOutSos`, 위상 보정 `phaseDelta52`, 3 kHz → 48k 변환.

## 5. 새 구성요소
### 5.1 hop 입력
`hop()`은 다음을 읽는다.
- 트랙 목록 `tr52_[0..nt52_)`: id, f, dfdt, a, residual (이력 포함), rawResidual (현재 프레임), missing, age, strong.
- bh와 대역 지연 신호: `bhRing_`, `detailRing52_` (인덱스 축 = bh 축).
- d 지연 신호: `md2_52_`.
- 이번 hop의 bh 프레임 크기 스펙트럼: `xr52_`/`xi52_`를 `loBin_..hiBin_`에서 `hypot`으로 구한다. `binHz_` = 3000/2048.
- 전대역 스펙트럼: `sm52_`. `pvFrame52`에서 `spectrum52(md2_52_)`로 이미 구해 둔 것이다.
- 맥락: `percEnv52_`, `harmEnv52_`.

### 5.2 목소리 관리
- **슬롯과 이어 붙이기**
  - 목소리 슬롯은 최대 V_max = 8개다. 목소리는 트랙 id에 묶인다.
  - 트랙이 사라진 뒤 3 hop 안에, 예측 주파수 (f + dfdt·Δt) 3 % 이내에 새 id의 트랙이 나타나면 같은 목소리로 이어 붙인다 (relink). 그래서 트래커의 재탄생 (born-cut 등)이 소리를 끊지 않는다.
- **상태와 전이**: 상태는 CAND, ON, REL 세 가지다. 판정은 5.4에 따른다.
  - 새 트랙 (이어 붙일 목소리가 없을 때) → CAND.
  - CAND → ON 조건은 둘 중 하나다.
    - 2 hop 연속으로 다음을 모두 만족: SNR ≥ 15 dB, (raw ≤ −12 dB 또는 res ≤ −15 dB), 그리고 두 hop 사이 |Δf|/f ≤ 3 %.
    - 1 hop이라도 SNR ≥ 22 dB.
  - ON → REL 조건은 셋 중 하나다.
    - 트랙이 3 hop 넘게 없다 (이어 붙이기 실패).
    - SNR < 6 dB가 6 hop 연속이다.
    - 목소리 수를 넘는다 (가장 작은 A·c부터 내보낸다).
  - REL → ON: 트랙이 다시 이어지고 SNR ≥ 12 dB.
  - REL에서 c < 0.01이고 트랙도 없으면 슬롯을 비운다.
  - **Fit 실패 (res > −15)만으로는 ON에서 내려가지 않는다. 이것이 처방의 핵심이다.**
- **종속 목소리**
  - 다음을 만족하면 목소리 v는 종속이다: 어떤 ON 목소리 u가 f_u < 0.9 f_v이고, m ∈ {2,3,4}에 대해 |f_v − m·f_u| ≤ 0.015 f_v.
  - 종속 목소리는 LS에는 들어간다 (실제 성분이기 때문이다). 합성 가중 σ_v는 0으로 간다 (τ 20 ms). 종속이 아니면 σ_v → 1.
- **c (신뢰도 가중)**: hop마다 c ← c + (c* − c)(1 − e^{−H/(fs·τ)})로 갱신한다.
  - c*는 ON일 때 1, CAND와 REL일 때 0이다.
  - τ = 8 ms (올라갈 때), 30 ms (내려갈 때).
  - 표본 사이는 선형으로 보간한다.

### 5.3 짧은 창 LS (진폭·위상)
- **대상**: hop마다 슬롯이 있는 모든 목소리 (CAND, ON, REL, 종속 포함, 최대 8개)를 함께 푼다.
- **신호 x(m)**, m = −N..N, j = n_h + m:
  - `ampSource` 0: bh = `bhRing_[j]` (기본).
  - `ampSource` 1: 대역 지연 신호 = `detailRing52_[j]`. HPSS 이전이라 어택이 약 30 ms 빠르지만 타격 에너지가 섞인다. 검증에서 0과 비교한다.
- **창**: Hann w(m) = 0.5(1 + cos(πm/(N+1))).
- **창 길이 N**
  - 목표값 N* = clamp(⌈κ·fs/Δf_min⌉, N_lo, 191).
    - Δf_min은 서로 다른 목소리 사이의 가장 작은 주파수 차이다. 목소리가 하나면 ∞.
    - κ = 1.0.
    - N_lo = clamp(⌈fs/f_low⌉, 30, 191)이다. f_low는 가장 낮은 목소리 주파수이며, 창이 그 한 주기 이상이 되게 한다.
  - 이력: N*이 현재 N과 25 % 넘게 다른 상태가 3 hop 이어질 때만 바꾼다. 목소리가 새로 생기거나 없어져서 Δf_min이 바뀐 경우는 바로 바꾼다.
- **기저**
  - 위상 Φ_v(m) = 2π(f_v·m + ½ ḟ_v m²/fs)/fs. ḟ_v = clamp(dfdt, ±400 Hz/s)이다.
  - 열 벡터는 cos Φ_v와 sin Φ_v이고, 실수 미지수는 2V개다.
  - 실수 LS를 쓰므로 Hilbert 위상 문제가 없다.
- **풀이**
  - 정규방정식 G = Σ w·b bᵀ, r = Σ w·b x를 세운다. G에 λI를 더한다 (λ = 1e−4·trace(G)/(2V)). 그다음 Cholesky로 푼다.
  - 두 목소리가 0.75·fs/191 ≈ 11.8 Hz보다 가까우면 하나의 열로 합친다 (센 쪽 주파수). 진폭은 트래커 진폭 a의 비율로 나눈다.
- **출력**
  - α_v, β_v에서 A_v = √(α² + β²) (사인 첨두 진폭)을 얻는다.
  - θ_v = atan2(−β_v, α_v)다. m = 0에서 성분이 A·cos(Φ + θ)가 되는 위상이다.
  - 정상 상태에서 A_v는 P1의 tr.a와 같은 양이어야 한다 (검증 V1).

### 5.4 신뢰도 입력
- **SNR_v** (dB): 이번 hop bh 프레임의 크기 스펙트럼 mag에서 구한다.
  - 피크 = f_v 주변 ±2 bin 안의 최대값.
  - 바닥 = 다음 조건을 모두 만족하는 bin들의 중앙값.
    - |f_b − f_v|가 18–40 Hz 사이다. 128 ms Hann의 주엽 ±15.6 Hz를 피하기 위해서다.
    - 다른 모든 목소리에서 ±18 Hz 밖이다.
    - 쓸 bin이 4개 미만이면 18–60 Hz까지 넓힌다.
  - SNR_v = 20 log10(피크/바닥).
- **raw_v와 res_v**: 트래커의 rawResidual (현재 프레임)과 residual (이력 포함)을 그대로 쓴다.
- **Δf**: 같은 목소리의 앞 hop 대비 상대 변화다. dfdt로 예측한 값과 비교하므로 글라이드는 허용된다.

### 5.5 입력 부분음 위상과 정렬 목표 ψ_vk
- **측정**: k = 2..8, k·f_v ≤ 700 Hz인 배음마다 한다.
  - `md2_52_` 위에서 n_h 중심, N_p = 191 Hann 창으로 단일 주파수 투영을 한다.
  - 주파수는 k·f_v, 처프는 k·ḟ_v다.
  - 결과는 입력 부분음의 복소 진폭 C_vk다.
- **존재 판정**: 다음을 모두 만족하면 부분음이 있다고 본다.
  - |C_vk| ≥ 0.01·A_v.
  - |C_vk| ≥ pvAbs (`pvAbs_`).
  - 전대역 스펙트럼 `sm52_`에서 k·f_v ±2 % 안에 국소 최대가 있다. P1의 `found`와 같은 조건이다.
- **목표 위상**
  - 부분음이 있으면: ψ* = arg C_vk − k·θ̂_v(C_h) + Φcomp(k f_v).
  - 부분음이 없으면: ψ* = `psi52(k, f_v, crest=true)` (R1).
- **Φcomp(f)**: 층 경로 (출력 필터 `kOutSos`와 3k → 48k 변환)와 원음 경로 (`phaseDelta52`의 EQ) 사이의 위상차를 보정한다. 정의는 다음과 같다.
  - Φcomp(f) = −arg H_out(f) + phaseDelta52(f) (+ 변환 FIR이 원음과 다르면 그 차이).
  - 부호와 정의는 P1의 `renderTrack52` 목표 식 (`interp52(vb52t::kPhase,...)+phaseDelta52(fk)+2π fk tc − k·phi`)을 분해해 같은 결과가 나오게 맞춘다.
  - **완료 판정은 측정으로 한다 (V2).**
- **회전**
  - hop마다 ψ ← ψ + clamp(wrap(ψ* − ψ), ±0.12 rad)로 P1과 같은 한도를 둔다.
  - 목소리가 태어날 때는 ψ = ψ*로 바로 둔다.
  - 표본 사이는 선형으로 보간한다.

### 5.6 발진기 합성
- **기준 위상 θ̂_v** (목소리마다 누적)
  - hop h에서 예측값: θ̂_pred = θ̂_v(C_{h−1}) + 2π·½(f_{v,h−1} + f_{v,h})·H/fs.
  - 갱신: θ̂_v(C_h) = θ̂_pred + β·wrap(θ_v,h − θ̂_pred). β = 0.25다. 그래서 θ̂는 입력 기본음 위상을 부드럽게 따른다.
  - 구간 [C_{h−1}, C_h)의 증분은 일정하게 (θ̂(C_h) − θ̂(C_{h−1}))/H로 둔다.
  - 태어날 때 θ̂ = θ_v다.
- **배음 진폭**
  - a_vk = G_L(f_v) · g(f_v) · w_k(f_v) · R_k(f_v) · A_v · c_v · σ_v.
  - g, w_k: P1 `lookup(f)` 표.
  - R_k: 위쪽 감쇠다.
    - voicing 0 (P1): k·f > 220 Hz에서 P1과 같은 감쇠를 쓴다. `rolloff(kf, 220)`과 `research_.upperBlend` (gentle24)로 계산한다.
    - voicing 1 (음역): f ≥ 73.3 Hz이면 corner = max(220, 3f)를 쓴다 (R4c 정의).
  - G_L: voicing 0에서는 1이다. voicing 1에서는 10^(L·s(f)/20)이다.
    - s(f)는 73.3 Hz에서 0이다. 92.4 Hz까지 3·log2(3f/220)으로 올라 1이 되고, 150 Hz까지 1, 220 Hz에서 0으로 내려간다 (R4-L 정의).
  - a_vk는 hop 끝값 사이를 표본 단위로 선형 보간한다.
- **합성**
  - s_res(n) = Σ_v Σ_{k=2..8, k f_v ≤ 700} a_vk(n) cos(k θ̂_v(n) + ψ_vk(n)).
  - n ∈ [C_{h−1}, C_h)이고, 원형 버퍼에 쓴다.
- **엔벨로프 강제는 없다.** 크기가 이미 입력을 따르기 때문이다.

### 5.7 섞기와 출력
- `preFilter = s_res + hp` → `out_` (150–600 Hz) → 48k로 간다. 엔진 체인은 바뀌지 않는다.
- 모듈 출력은 '충실' 수준 (vb_level 0 dB)이다.

### 5.9 실시간 제약과 연산량
- 할당하지 않는다. 배열 크기는 V_max 8, K 7, 창 ≤ 383으로 고정한다.
- hop당 연산량:
  - LS: 열 16개 × 383 × (기저 + 그람 136항) ≈ 6만 MAC.
  - 부분음 투영: 8 × 7 × 383 ≈ 2만 MAC.
  - 합성: 16 표본 × 56 cos.
- 초당 약 2천만 연산이다. P1 FFT 경로와 같은 크기다. 목표는 호스트 시간 ≤ 1.6 × P1이다.

## 7. 검증 계획 (구현 전 고정)
- **원칙**
  - 검증 에이전트는 구현 에이전트와 다르다.
  - P1 기준선은 기존 빌드 (`build_r4l2`, vb_algo 6)로 먼저 잰다.
  - Slakh validation 분할은 열지 않는다. train만 쓴다.
- **V0 비트 동일 (필수)**
  - 새 빌드에서 알고리즘 0–14와 기존 빌드 (`build_r4l2`)의 출력 차이가 최대 0이다. 신호: 합성 4종, Track00060 30초, LOGOFF 30초.
  - 연구 회귀 (`test_track_prediction_research.py`)도 통과해야 한다.
- **V1 보정**: 정상 100 Hz 3배음 톤 (−12 dBFS, 4초, 0.5초 이후)에서 잰다.
  - 트레이스의 A_v / P1 trace의 tr.a = 0 ± 0.5 dB.
  - 층 (코어 `post_filter`) 150–600 Hz 수준이 P1 대비 ±1 dB (L = 0, voicing 0).
- **V2 위상 정렬**: 같은 신호로 엔진 출력에서 잰다.
  - 층 = 출력 − (vb_level −120 출력). 두 출력 모두 out_db −18로 렌더해 리미터가 걸리지 않게 한다.
  - 층과 원음의 k = 2, 3 성분 위상차 평균이 |Δφ| ≤ 0.3 rad.
  - 같은 측정을 P1에도 하고, P1 값과 함께 보고한다.
- **V3 타이밍**: 맨 베이스 (0.5초마다 음, 8 ms 어택, 350 ms 감쇠).
  - 전체 출력 150–600 Hz의 주기 평균 정점이 21 ± 10 ms.
  - 300 Hz에서 층/입력 배음 비가 40–450 ms 구간 (20 ms 칸)에서 최대 − 최소 ≤ 4 dB. P1은 약 40 dB였다.
  - 층 엔벨로프에 10–60 ms 사이 6 dB 넘는 골이 없다.
- **V4 깜빡임**: 베이스+핑크, 베이스+킥+핑크 (`research_r4l_gate_flicker.py`와 같은 신호).
  - 음별 층 에너지 (150–600 Hz)의 음 사이 표준편차 ≤ 1.5 dB.
  - 음 안의 20 ms 칸 중 그 음의 중앙값보다 6 dB 넘게 낮은 칸 ≤ 2 %.
- **V5 실곡 연속성**: Track00060 39–47초, L = 0.
  - 층 150–600 Hz를 0.5초 칸으로 P1 층과 비교한다. 75 % 이상의 칸이 ±3 dB 안이다.
  - (코어 − P1) dB의 최대값 − 중앙값 ≤ 4 dB (몰아 붙는 증폭이 없음).
- **V6 음높이 품질**: Slakh train 10곡 × 30초. 6곡은 이미 쓴 곡이고, 4곡을 새로 골라 고정한다.
  - **덮음**: 베이스가 큰 hop에서, 합성하는 ON 비종속 목소리 중 MIDI 베이스 f0 (또는 2f0, 3f0)의 50 cent 안에 있는 것이 있는 비율.
    - P1의 같은 정의 (fade ≥ 0.5인 트랙)보다 **+5 %p 이상**이어야 한다.
  - **틀린 음 에너지**: 합성 에너지 (Σ a_vk²) 가운데, 모든 악기의 MIDI 음과 그 ½, 1, 2, 3배 어디에도 50 cent 안에 들지 않는 목소리의 몫.
    - P1 (렌더 진폭 a·fade 기준) 대비 +2 %p 이하여야 한다.
- **V7 해악**: L = 0 기준이다.
  - (a) 엔진 출력 (코어 − 원음)의 1.5 kHz 위 에너지가 원음 1.5 kHz 위보다 50 dB 이상 작다.
  - (b) 폰 모델 거칠기 (`research_r4_roughness.py`, MUSDB·Slakh 개발곡) ≤ P1 +5 %.
  - (c) 폰 모델 저역 GR 최대 ≤ P1 + 0.5 dB.
  - (d) LOGOFF 4.12 / 4.73초 타격의 층 150–600 Hz 에너지 ≤ P1 + 1 dB. 사용자의 판정 기준 지점이다.
- **V8 연산량**: 60초 스테레오 48 kHz, 호스트 처리 시간 ≤ 1.6 × P1.
- **ampSource 결정**: 0과 1을 모두 잰다. V3–V7을 모두 통과하는 쪽 가운데 V3 정점이 21 ms에 더 가까운 쪽을 고른다. 동률이면 0이다.
- **공격적 음색 보고** (합격·불합격 없음, 청감 자료): voicing 1, L = 6과 9.
  - V3–V7 지표를 보고한다.
  - 폰 가중 150–600 Hz 이득을 P1 대비로 보고한다 (`research_r4_coherent_gain.py` 정의, MUSDB 100–125 Hz와 Slakh).

## 8. 블라인드 계획 (사용자)
- 객관 검증 V0–V5와 V7을 통과한 뒤에만 한다.
- 진행 방식:
  - 각 묶음에 무효 짝을 하나 넣는다.
  - 키 해시는 듣기 전에 고정한다.
  - 들을 곳은 키와 무관하게 |변형 − P1|로 정해 안내한다.
- **묶음 A (L = 0 대 P1)**: 맨 베이스, 합성 (킥+노이즈), T60, LOGOFF. 묻는 것: 노이즈, 타이밍 어긋남, 더 센 쪽.
- **묶음 B (voicing 1 L6 대 P1)**: T60, Track00040, LOGOFF, 합성.
- 해석 규칙은 블라인드 문서에 미리 적는다. 청감은 거부권이 아니다. 객관 지표가 1차다.

## 9. 역할과 순서
1. 설계 관문 ①: Sonnet이 독립 검토한다. BLOCKING이 있으면 고친 뒤에 다음으로 간다.
2. 구현 (Sonnet A): 브랜치 `research/resultant-core-20261030`에서 4.2–5.9를 구현한다. 빌드는 `build_core`이고 V0를 직접 확인한다.
3. 검증 (Sonnet B, A와 병렬): `tools/pvb-harness/research_core_metrics.py`를 쓰고, P1 기준선을 먼저 잰다. 구현이 끝나면 V1–V8을 잰다.
4. Opus: 결과를 검토하고, 실패 원인을 보고 설계 v1.x를 정한다. 그다음 블라인드를 준비한다.
5. 다음: 사전 등록 (관문 ①) → validation 1회 → 관문 ②. 앱 통합은 사용자가 정한다.
- 커밋: 에이전트는 커밋하지 않는다. Opus가 검토한 뒤 사용자 이름으로 커밋하고, Windows repo에서 push한다.
