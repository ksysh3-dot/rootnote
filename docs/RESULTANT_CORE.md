# Resultant 코어 설계서 v1.5 (2026-10-30)

상태: 설계. 관문 ① (Sonnet 독립 검토, v1과 v1.1 두 번)과 Gemini (Argon Medium, 다른 계열 교차 검토)의 지적 가운데 Opus가 확인한 것을 반영했다. 변경 기록은 11절에 있다. 코드는 아직 없다. 이 문서는 구현 (Sonnet A)과 검증 (Sonnet B, A와 다른 에이전트)의 기준이다. 숫자 문턱은 구현 전에 정했고, 결과를 본 뒤에 바꾸지 않는다. 바꿔야 하면 버전을 올리고 이유를 적는다.

## 0. 요약
P1의 고질병은 **배음층의 크기를 음악이 아니라 분석 관문이 정한다**는 것이다. 새 코어는 P1의 앞단 (대역 경로, HPSS, 트래커, 표, 위상 보정)은 그대로 두고 지속층의 크기 경로만 새로 만든다.
- **무엇이 울리나** (음높이 후보): P1의 128 ms 트래커가 정한다.
- **얼마나, 언제 울리나** (진폭·위상): 트랙 주파수에서 과거 쪽에 무게를 둔 짧은 창으로 최소제곱 (LS)을 풀어 입력에서 직접 읽는다. 해상도는 10–107 ms이고 신호 대 잡음비와 가까운 음 간격에 따라 정해진다. 미래는 최대 8 ms만 본다.
- **합성**: 목소리마다 위상이 이어지는 발진기가 표본 단위로 k·f 배음을 만든다. 주파수는 측정 위상으로 다듬는다.
- **신뢰도**: 맞춤 검사 (Fit)는 층을 끄지 않는다. 목소리는 한 hop 안에서 판정해 태어나고 (지연 없음), 입력에 그 음이 없어질 때 끝난다.
- **바뀌지 않는 것**: 지연, 출력 대역, 엔진 체인, 앱. vb_algo 15를 고르지 않으면 P1은 비트까지 같다.

## 1. 근거 (진단)
- **관문이 층의 존재를 정한다.** P1 지속층은 128 ms 정상 사인 맞춤 (`kPvN` 384 @ 3 kHz, 잔차 ≤ −15 dB)과 28 hop 이력 유지 (`hold52_`)를 통과해야 fade가 1로 간다 (`pvb_vb52.cpp` `tr.fade+=...`).
  - 같은 음을 다시 치면 이력에 남은 어택 프레임의 나쁜 잔차 때문에 약 0.2초 비고 (`research_r4l_trace_gap.py`), 노이즈와 믹스에서는 깜빡인다 (`research_r4l_gate_flicker.py`: 음마다 실패 0–41 hop, 전환 ≤ 10회).
  - 새 음높이는 이력이 없어서 (res = −200) 바로 통과한다.
- **강제 이득은 끌어내리기만 한다.** 음악 엔벨로프 강제 `gain = clampv(as/ps, 0, 1)` (`core52`)는 층을 줄일 수만 있고 빈 곳을 채우지 못한다.
- **P1이 깨끗한 이유.** 층이 입력 배음보다 약 7 dB 아래라 관문의 흔적이 가려지기 때문이다. 그 위로 올리면 흔적이 모두 들린다 (R4-L v1/v2 블라인드 4회, docs/RESULTANT_R4.md).
- **음높이 측정** (`research_resultant_pitch_truth.py`, Slakh train 6곡, 베이스가 큰 hop 19 373개): 가장 센 40–220 Hz 트랙이 틀린 비율은 20.0 % (옥타브·12도 7.4 %)이고, 어떤 트랙이든 맞는 비율은 88.6 %다. 그래서 트랙마다 따로 처리한다.

## 2. 목표와 비목표
- **목표**
  - G1: 층 크기가 입력 음을 따른다. 재어택, 글라이드, 노이즈에서 공백과 깜빡임이 없고, 앞울림 (pre-echo)도 없다.
  - G2: 기본 음색 (voicing 0)에서 고립된 정상 톤의 수준과 위상 정렬이 P1과 같다. 믹스에서는 P1이 강제 이득 (≤ 1)으로 깎던 만큼 커질 수 있다. 이것은 의도한 차이이며 V5(b)에서 잰다.
  - G3: 공격적 음색 (voicing 1)을 관문 흔적 없이 낸다.
  - G4: 지연, 출력 대역, 엔진 체인, 앱은 그대로다. 알고리즘 0–14는 비트까지 같다.
- **비목표**: 타격층 재설계, 트래커 교체, 73 Hz 아래 R3-a 변경, 앱 통합.

## 3. 시간축 (관문 ①에서 코드 대조 확인)
- 코어 fs = 3000 Hz, hop H = 16이다. hop h는 코어 인덱스 `i_h = 383 + 16h`에서 `pvFrame52()`가 불릴 때다 (future = 0, defer = 0).
- **입력 시간**: 분석 중심 c_h = i_h − 382 (P1 trace 헤더 [9]). 코어 시계는 48 kHz 입력 시간축보다 1359 표본 (28.3 ms, 데시메이터) 늦으므로, 입력 초로 바꿀 때는 c_h/3000 + 1359/48000 s다 (수용 감사에서 찾은 누락, `research_core_api.hop_time` 정정).
- **ring 인덱스 축**: `bhRing_`, `detailRing52_`, `md2_52_`의 슬롯 j는 입력 시간 j − 191에 해당한다. c_h에 해당하는 슬롯은 `n_h = i_h − 191`이다.
  - 쓸 수 있는 범위는 [i_h − 511, i_h]다 (kRing 512). 그러므로 과거는 n_h 기준 최대 320, 미래는 최대 191이다.
- **출력 코어 시간**: hop h의 추정은 `C_h = i_h + 16`에 놓인다. 출력 표본 n은 입력 시간 n − 398에 해당한다.
- **쓰는 구간**: hop h는 [C_{h−1}, C_h) = [i_h, i_h + 16)를 쓴다. core52가 표본 i_h를 읽기 전에 쓰므로 인과적이다 (`takeGrain52`보다 앞).
- **지연**: 지연은 P1과 같다. 같은 VbHpv 인스턴스를 쓴다.

## 4. 구조와 통합
### 4.1 블록도
```
x(48k) ─▶ [P1] 3 kHz ─▶ LR4 190 Hz ─▶ HPSS ─┬─ bh ─▶ [P1] PV 트래커 (128 ms) ─▶ 트랙 목록 ─┐
                                              │  bh / detailRing52_ ─▶ [새] LS (과거 쪽 창) ◀─┤
                                              │  md2_52_ + sm52_ ─▶ [새] 부분음 위상·두드러짐 ◀┤
                                              │                       [새] 목소리 관리 ◀───────┘
                                              │                       [새] 발진기 ─▶ s_res
                                              └─ bp ─▶ [P1] u^k·gate·poly ─▶ hp
  out := s_res, appliedGain := 1 ─▶ [P1] preFilter = out·appliedGain + hp ─▶ 출력 필터 150–600 ─▶ 48k ─▶ 엔진
```
### 4.2 통합 방식 (v1.1: 같은 인스턴스에 붙인다)
- **알고리즘 15 = `vbAlpha2_` (VbHpv)의 P1 프로필 + Resultant 경로 켬.**
  - 새 모듈 클래스와 두 번째 VbHpv는 만들지 않는다. 메모리, configure, bindEq, capture, trace 배선이 모두 그대로 쓰인다.
  - `setAlpha2Profile(15)`: P1 (6)과 똑같이 설정한 뒤 `resultantOn_=true`로 둔다. 다른 모든 프로필에서는 `resultantOn_=false`다.
    - 강제는 오래 유지되어야 한다 (v1.3). 프로필 switch (`pvb_vb.cpp` 24 부근)에 15를 넣는다.
    - C1 프로필처럼 `p1PlusFixed_=true`로 두고 `p1PlusFlags_=0`, `p1ppImpactMode_=0`, `p1ppV04_=0`으로 고정한다. 그래야 뒤에 오는 호스트 설정자 (`pvb_engine.h:203-217` → `pvb_vb.h:219,240,247`)가 덮어쓰지 못한다.
    - `stageFlags_=0`이다. 0이 아닌 stage 연구 플래그를 붙이려 하면 15에서는 무시하거나 거부한다.
    - `gen_` (setGenResearch, 프로필 전환 뒤에도 남음)는 `resultantOn_`일 때 쓰지 않는다.
    - future = defer = 0.
  - `VbAlgo`: `VB_RESULTANT = 15`, `VB_ALGO_COUNT` 16.
  - `pvb_engine.h:335`의 `vbMods_` 초기값에 16번째 `&vbAlpha2_`를 추가한다. 빠지면 nullptr로 모든 알고리즘이 터진다.
  - 엔진의 `algo >= VB_ALPHA2_P1` 분기 (`pvb_engine.cpp:262`)와 configure 매핑 (`:322`, a > P1 → vbOk_[P1])은 15를 그대로 포함한다. 구현이 확인한다.
  - `pvb_capi.cpp:306-311`의 `pvb_vb_create(15)`도 `setAlpha2Profile(15)`로 동작해야 한다.
  - 앱 (`PvbModels.kt`)은 바꾸지 않는다. 키로 저장되는 닫힌 목록이라, 모르는 키는 P1이 된다 (관문 ① 확인).
- **코드 배치**
  - 선언은 `pvb_resultant.h`에 둔다. 고정 크기 상태만 있고, 기저는 회전 재귀로 즉석 계산해 저장하지 않으며, 인스턴스당 약 10 kB를 넘지 않는다.
  - 정의는 `pvb_resultant.inc`에 두고 `pvb_vb52.cpp` 끝에서 `#include`한다.
  - 그래서 빌드 목록 (app/rootfx CMake, build_host.sh, build_host_windows.py, 테스트 컴파일 목록)을 바꾸지 않는다. 같은 번역 단위라 익명 namespace의 `psi52`, `interp52`, `offset52`, `kernel52`도 쓸 수 있다.
  - mutation 테스트가 `pvb_vb52.cpp`에서 한 번만 나오는지 세는 문자열 (`(centre-16+g)`, `k*(tr.phi+phase)`, `pvOut_[slot]+=grain[g]*gw_[g];`)을 vb52.cpp에 새로 늘리지 않는다.
  - VbHpv에 `ResultantCore resultant_; bool resultantOn_=false;`와 `friend class ResultantCore;`를 둔다. `VbHpv::reset()`이 `resultant_.reset()`을 부른다.
- **연결점** (모두 `if(resultantOn_)`. 끄면 P1과 비트 동일)
  1. `pvFrame52()`: `renderTrack52` 호출 3곳 (`vb52:296,846,892` 부근)과 `addGrain52` 2곳 (`:303,912`)만 건너뛴다.
     - 잃은 트랙 유지 (`if(tr.life>0) next[nextCount++]=tr; else grave52(tr)`)와 `missingFrame52`의 압축은 그대로 두어 tr52_가 P1과 같게 한다.
     - hop 끝 (`std::copy(next...)`와 hop 카운터 뒤)에서 `resultant_.hop(*this, /*measured=*/true)`를 부른다.
  2. `missingFrame52()` 끝에서 `resultant_.hop(*this, false)`를 부른다. 한 곳에서 Absolute, NoPeak, Relative를 모두 덮는다.
     - 이 hop에서는 `sm52_`, `sr52_`, `si52_`가 이전 값이다. 트랙 필드도 마지막 측정 hop에 멈춰 있고 missing ≥ 1이다.
     - 그래서 이 hop에서는 태어남, 부분음 판정, ψ 갱신을 하지 않는다. LS와 SNR (bh 스펙트럼 `xr52_`/`xi52_`는 이미 이번 값)은 한다.
  3. `core52()`: `takeGrain52` 대신 `resultant_.take(i−defer)`를 쓴다 (읽고 지움). 그리고 `out=sample; appliedGain=1`로 둔다.
     - preFilter 식, devMix_, tonalOnly_, stage capture 필드는 그대로 동작한다.
     - envA_/envP_ 계산은 돌아도 섞이지 않는다.
- **호스트 연구 API** (`pvb_capi.cpp`)
  - `int pvb_set_resultant(void* e, const double* v, int n)`: 5.8 순서로 받는다. n이 짧으면 나머지는 기본값을 유지한다. 범위를 검증해 1/0을 돌려준다. 엔진이 15가 아닐 때도 설정은 보관한다.
  - `pvb_resultant_trace_enable(e, capacityHops)`와 `pvb_resultant_trace_copy(e, double* out, int cap)`: hop마다 목소리마다 다음 필드를 기록한다.
    `[hop core index, voice id, track id, state(0 빈칸 1 CAND 2 ON 3 REL), coasting, f_track, f_osc, dfdt_s, A, c, sigma, Np, snr_db, prominent, raw_db, res_db, subordinate, theta_hat, psi_2, psi_3, a_2, a_3]` (22개).
  - 할당은 enable에서만 한다. 오디오 경로는 고정 버퍼에 쓴다.
  - Python 감싸개 `tools/pvb-harness/research_core_api.py`가 argtypes, 필드 이름, 렌더 도우미를 제공한다.

## 5. 새 구성요소
### 5.1 hop 입력
`hop()`이 읽는 것은 다음과 같다.
- `tr52_[0..nt52_)`: id, f, dfdt, a, residual, rawResidual, missing, age, strong.
- `bhRing_`, `detailRing52_`, `md2_52_` (ring 축).
- bh 프레임 스펙트럼: `xr52_`/`xi52_`를 loBin_..hiBin_에서 hypot으로 구한다. `binHz_` = 3000/2048.
- 측정 hop일 때만: `sm52_`와 `src[0]`, `src[1]`, ns (pvFrame52 지역 변수 `src`/`ns`는 hop에 인자로 넘긴다).
- `percEnv52_`, `harmEnv52_`.

### 5.2 목소리 관리
- **슬롯과 이어 붙이기**
  - 슬롯은 V_max = 8개이고, 목소리는 트랙 id에 묶인다.
  - 트랙이 사라진 목소리는 **coasting**에 들어간다. 이때 주파수 = 마지막 f + ḟ_s·Δt (ḟ는 감쇠 0.9/hop)이고, LS와 SNR은 그 주파수에서 계속 잰다.
  - coasting 중 이어 붙이기: 최대 48 hop (256 ms) 안에, 예측 주파수 3 % 안에 새 id의 트랙이 나타나면 같은 목소리로 이어 붙인다. 목소리 id, θ̂, ψ, c를 유지한다.
- **상태와 전이**
  - **CAND → ON** (v1.3): 측정 hop 두 번 (태어난 hop과 그다음 측정 hop, 약 5.3 ms)으로 판정한다. 두 hop 모두에서 (a)와 (b)를 만족하고, 그 사이에서 (c)를 만족해야 한다.
    - (a) SNR_v ≥ snrOn (15 dB).
    - (b) 근거: 측정 hop의 전대역 피크 목록 `src[0]` ∪ `src[1]`에, k ∈ {1,2,3,4}에 대해 |p − k·f_v| ≤ max(4 Hz, 3 %·k·f_v)인 피크 p가 있다. P1 Grid 규칙과 같은 성격이라, 기본음이 약한 베이스도 2–4배음 근거로 받는다.
    - (c) 두 hop 사이 |Δf|/f ≤ 3 %이고, |Δf/Δt| ≤ maxDfdtBirth (200 Hz/s). 새 트랙의 dfdt는 첫 hop에 0이라 쓸 수 없다. 그래서 두 hop의 주파수 차이로 잰다. 킥 쓸기와 과도 피크가 여기서 걸린다.
    - v1.1의 한 hop 경로 (e)는 없앴다. 아끼는 시간이 5.3 ms뿐인데, 킥을 통과시킨다.
  - **CAND 해제** (v1.3): 트랙이 측정 hop 2번 연속 없거나, 12 측정 hop 안에 ON이 되지 못하면 슬롯을 비운다.
  - **같은 hop의 태어남 순서 (v1.2)**: 낮은 주파수부터 처리한다. 태어나는 목소리가 이미 ON인 목소리나 같은 hop에 먼저 ON이 된 목소리에 대해 종속 조건을 만족하면, σ_v = 0으로 시작한다 (감쇠를 기다리지 않음).
  - **ON 유지**: Fit 실패 (res > −15, raw 나쁨)로는 내려가지 않는다.
  - **ON → REL** (v1.3): 다음 가운데 하나다.
    - SNR_v < snrOff (6 dB)가 **측정 hop 24번 연속** (128 ms)이다.
      - SNR 추정은 128 ms 프레임이 겹쳐서 약 24 hop 동안 상관된 ±3.5 dB 흔들림을 가진다 (관문 ① 모의 실험). 6 hop으로 판정하면 경계의 음이 초당 4–7번 깜빡인다.
      - 진폭은 A_v가 입력을 따르므로, 음이 실제로 끝난 뒤 ON이 128 ms 남아도 층은 이미 작다.
    - **LS 근거 규칙**: 1단계 LS의 A_v가 15 Hz 안에 있는 더 센 LS 이웃의 A보다 20 dB 넘게 작은 상태가 측정 hop 3번 연속이면 REL이다.
      - 이웃 음의 Hann 주엽이 스펙트럼 SNR을 채워서 꺼진 목소리가 켜진 채 남는 것을 막는다 (5.9 Hz 떨어지면 이웃 대비 −1.0 dB, 9 Hz면 −3.7 dB, 12 Hz면 −8.6 dB).
      - coasting 목소리는 −12 dB로 더 엄격히 본다.
    - coasting이 48 hop을 넘는다.
    - 슬롯이 넘친다 (A·c가 가장 작은 목소리부터).
    - 넘쳐서 밀려난 목소리는 페이드 전용 칸 2개 중 하나로 옮긴다 (v1.2). 이 칸은 합성만 하고 LS에는 들지 않으며, τ 5 ms로 사라진다. 그래서 같은 hop에 새 목소리가 슬롯을 쓸 수 있다.
  - **REL → ON** (v1.3): 다음 둘을 만족하는 상태가 측정 hop 3번 연속이면 된다 (트랙이나 coasting 주파수 기준).
    - SNR_v ≥ snrOff + 4 dB (10 dB).
    - 근거 (b)도 만족한다.
    - 한 번 확인된 목소리이므로 태어날 때보다 문턱이 낮다. 다만 해제 (24 hop)와 재개 (3 hop, +4 dB)의 비대칭 이력으로 경계의 깜빡임을 막는다.
  - **REL → 빈칸**: c < 0.01이고 트랙도 없다.
  - **비측정 hop** (missingFrame52): 태어남이 없고, 상태는 SNR 규칙만 따른다.
- **종속 목소리** (v1.5: 주파수 비만으로는 판정하지 않는다)
  - 기본 조건: 어떤 ON 목소리 u가 f_u < 0.9 f_v이고, m ∈ {2,3,4}에 대해 |f_v − m f_u| ≤ 0.015 f_v다.
  - 추가 조건 (모두 만족해야 종속):
    - (i) u가 ON으로 측정 hop 8번 넘게 이어졌다.
    - (ii) u의 |ḟ_s|는 50 Hz/s 이하다.
    - (iii) A_v ≤ 2·A_u.
    - (iv) **위상 고정**: 최근 측정 hop 8번 동안 φ = θ_v − m·θ_u의 원형 표준편차가 0.6 rad 이하다.
  - 예외: 두 목소리가 같은 hop에 태어났으면 (같은 어택) 기본 조건만으로 종속이다.
  - 이유: 킥 꼬리 (약 50 Hz, 쓸어 내림)가 ON이 되면, 주파수 비만으로는 100 Hz 베이스가 그 "2배음"으로 판정되어 꺼진다. 구현 시험에서 베이스+킥+핑크의 V4(a)가 2.0 dB, (b)가 22.7 %로 실패했고, 종속을 끄면 0.63 dB와 0.4 %였다. 같은 음원의 배음은 위상이 고정되어 있고, 서로 다른 음원은 떠돈다.
  - 종속 목소리는 LS에 들어간다. 합성 가중 σ_v는 0으로 간다 (τ 20 ms). 종속이 아니면 σ → 1.
- **c (신뢰도 가중)**
  - c* = 1 (ON), 0 (CAND, REL)이다.
  - τ = 8 ms (올라감), 30 ms (내려감).
  - hop 끝값 사이는 표본 단위로 선형 보간한다.

### 5.3 LS (진폭·위상)
- **LS 집합**: ON, CAND, 그리고 c > 0.1인 REL 목소리 (최대 8개). 종속 목소리와 coasting 목소리를 포함한다. c ≤ 0.1인 REL은 빼고, 그 A는 마지막 값을 쓴다 (c가 곧 0이 된다).
- **신호 x(m)** (m = −N_p..N_f, 슬롯 j = n_h + m)
  - ampSource 0: `bhRing_` (기본).
  - ampSource 1: `detailRing52_` (HPSS 이전, 어택이 약 30 ms 빠르지만 타격 에너지가 섞인다).
- **창** (과거 쪽에 무게, 앞울림 방지)
  - 과거 쪽: m ∈ [−N_p, 0]에서 w = ½(1 + cos(π m/(N_p+1))).
  - 미래 쪽: m ∈ [0, N_f]에서 w = ½(1 + cos(π m/(N_f+1))).
  - N_f = min(N_p, nFuture) (기본 24 = 8 ms).
- **두 단계 LS (v1.2)**: 창 하나로 모든 목소리를 풀면, 꺼져 가는 약한 목소리 하나가 새로 어택한 깨끗한 목소리의 창까지 길게 만든다 (Gemini 지적 3). 그래서 두 단계로 푼다.
  - **1단계 (함께 풀기)**: LS 집합 전체를 과거 N_J, 미래 N_f 창으로 함께 푼다. 목소리끼리 분리하고 약한 목소리를 안정되게 잡는 단계다.
    - N_J = clamp(max(N_lo, N_sep, N_snr(s_ON)), N_lo, 320)이다.
    - s_ON은 **ON 목소리들의** SNR 최소값이다. CAND와 REL은 맞춤에는 들어가지만 이 최소값에서는 뺀다. ON이 없으면 전체 최소값을 쓴다.
  - **2단계 (목소리별 다듬기)**: SNR_v ≥ 18 dB인 목소리 v마다 한다.
    - 잔차 r_v(m) = x(m) − Σ_{u≠v} (1단계 계수로 만든 u의 성분)을 구한다.
    - r_v에 단일 목소리 LS를 과거 N_v, 미래 N_f 창으로 다시 풀어 A_v와 θ_v를 얻는다.
    - N_v = clamp(max(N_lo,v, N_snr(SNR_v)), N_lo,v, N_J)이고, N_lo,v는 f_v의 한 주기다.
    - SNR_v < 18 dB이면 1단계 값을 쓴다.
    - **자기 배음 열 (v1.3)**: 2단계 LS에 그 목소리의 2f와 3f (200 Hz 아래일 때)를 성가신 열로 함께 넣는다.
      - 과거 쪽 비대칭 창에서는 Hann 영점이 배음 위에 오지 않는다. 그래서 자기 배음 누설로 진폭이 0.4–2.8 dB 치우친다 (60 Hz 이하에서 1.7–2.8 dB, 관문 ① 모의 실험).
      - 이 열은 그 치우침을 없앤다. 쓰는 것은 기본음 계수뿐이다.
- **창 길이 규칙**
  - N_lo = clamp(⌈fs/f_low⌉, nMin (30), 320): 가장 낮은 목소리의 한 주기 이상이다. Hann의 영점이 그 배음 위에 와서 배음 누설이 작다 (관문 ① 모의 실험).
  - N_sep = ⌈2κ·fs/Δf_min⌉ − N_f: 전체 길이가 2κ·fs/Δf_min 이상이 되게 한다. Δf_min은 LS 집합의 가장 작은 간격이고, κ는 1.0이다.
  - N_snr(s): s ≥ 30 dB이면 N_lo, s ≤ 12 dB이면 320이고, 그 사이는 log-선형이다. 잡음 속 진폭 흔들림 (관문 ①: SNR 15 dB, N 30에서 hop당 2.5 dB)을 막는다.
  - 이력: N_J와 N_v 각각, 목표가 현재와 25 % 넘게 다른 상태가 3 hop 이어질 때 바꾼다. LS 집합이 바뀌면 N_J는 바로 바꾼다.
  - **전환 상태 (v1.2)**: ON 목소리의 위상 오차 |e| > 0.5 rad가 측정 hop 2번 연속이면 음높이가 옮겨 가는 중으로 본다. |e| < 0.3 rad가 될 때까지 그 목소리의 N_v = N_lo,v로 둔다.
- **기저**
  - 위상 Φ_v(m) = 2π(f_b,v·m + ½ ḟ_s,v m²/fs)/fs다.
    - f_b,v = f_track + f_off,v (5.6의 ±12.5 % 한계; v1.5에서 문구 정정). coasting이면 예측 주파수다.
    - ḟ_s는 트랙 dfdt의 4 hop 이동평균이며 ±400 Hz/s로 자른다.
  - 열은 cos Φ_v, sin Φ_v이고 실수 미지수는 2V개다.
  - 기저는 회전 재귀로 만든다 (처프는 2차 위상 재귀). 표본마다 cos, sin을 부르지 않는다.
- **풀이**
  - G = Σ w b bᵀ (대칭, 상삼각만 누적), r = Σ w b x를 세운다. G에 λI (λ = 1e−4·tr(G)/(2V))를 더하고 Cholesky로 푼다.
  - 두 목소리가 3 Hz보다 가까우면 같은 소리로 보고 젊은 쪽을 늙은 쪽에 합친다. 젊은 쪽은 REL로 보내고, 늙은 쪽은 이어 붙인 것으로 처리한다. 3–11.8 Hz 사이는 합치지 않고 긴 창으로 함께 푼다 (관문 ①: 5.9 Hz, N 191에서 cond 5.3).
- **출력**
  - A_v = √(α² + β²) (사인 첨두 진폭; 고립 정상 톤에서 tr.a와 같은 단위).
  - θ_v = atan2(−β, α): 슬롯 n_h에서 cos의 위상이다. e^{−jΦ} 투영과 같은 규약이고, FFT와 `ModulationFit`의 규약과도 같다.

### 5.4 신뢰도 입력
- **SNR_v** (dB): bh 프레임 크기 스펙트럼에서 구한다.
  - 피크 = f_b,v 주변 ±2 bin의 최대값.
  - 바닥 = 다음 bin들의 중앙값이다.
    - |f_b − f_v|가 22–45 Hz 사이다 (128 ms Hann의 주엽 ±15.6 Hz와 첫 옆엽 18–22 Hz를 피함).
    - **제외 (v1.2)**: 모든 LS 목소리와 이번 hop의 모든 트랙 주파수 u, 그리고 그 2u, 3u에서 ±22 Hz 안의 bin은 뺀다. 저음 (약 22–60 Hz)에서 자기 2배음이나 3배음을 바닥으로 읽어 SNR이 낮게 나오는 것을 막는다 (Gemini 지적 4).
  - 쓸 bin이 4개 미만이면 22–70 Hz까지 넓힌다. 그래도 4개 미만이면 전역 바닥을 쓴다: bh 스펙트럼 20–200 Hz에서 같은 제외를 한 bin들의 중앙값이다.
- **두드러짐**: 5.2 (b). 측정 hop에서만 쓴다.
- **raw, res**: 트레이스에 기록만 하고 판정에는 쓰지 않는다. 비교와 진단용이다.

### 5.5 입력 부분음 위상과 정렬 목표 ψ_vk (v1.1: P1의 보정을 그대로 쓴다)
- **hop 안 순서 (v1.2)**: LS (1, 2단계) → θ̂·f_off 갱신 (5.6) → 부분음 투영. 투영은 갱신된 다음 hop 주파수 f_osc를 쓴다 (Gemini 지적 5).
- **측정** (측정 hop만): k = 2..8, k·f_v ≤ 700 Hz인 배음에 대해 한다.
  - `md2_52_`에서 n_h 중심, 대칭 Hann 반길이 N_k로 주파수 k·f_osc,v (처프 k·ḟ_s)에 단일 투영한다. 결과는 C_vk다 (같은 위상 규약).
  - N_k = clamp(round(191·2/k), 48, 191)이다 (k = 2에서 191, 4에서 96, 8에서 48). 높은 배음은 주파수 오차가 k배로 커지므로 짧은 창의 넓은 주엽으로 받는다.
- **존재 판정 (이력, v1.2)**
  - 켜짐 조건 (모두 만족): |C_vk| ≥ 0.01·A_v, |C_vk| ≥ `pvAbs_`, 그리고 `sm52_`에서 k·f ±max(3 Hz, 2 %) 안에 국소 최대가 있음 (P1의 `found`와 같은 시험).
  - 꺼짐 조건: |C_vk| < 0.005·A_v가 측정 hop 2번 연속이거나, found 시험이 2번 연속 실패.
  - 켜짐과 꺼짐 사이에 오가는 깜빡임을 막는다.
- **보정**: Φcomp(f) = interp52(vb52t::kPhase, 3920, (f−20)·4) + phaseDelta52(f) + 2π f·tc다.
  - tc = 2·80/48000 + 398/3000 − 7052/48000 ≈ −10.917 ms이다. `renderTrack52`의 식과 같다.
  - kPhase = arg H_eqref − arg H_out이고, phaseDelta52 = arg(H_eq,actual/H_eqref)이다 (관문 ① 확인).
  - EQ는 hop마다 현재 값을 쓴다.
- **목표 위상**
  - 부분음이 있으면: ψ* = arg C_vk − k·θ̂_v(C_h) + Φcomp(k f_v).
  - 부분음이 없으면: ψ* = `psi52(k, f_v, crest)`. crest는 매개변수이고 기본 0 (= kPsi, P1 기본값)이다.
- **회전과 유지**
  - hop마다 ψ ← ψ + clamp(wrap(ψ* − ψ), ±psiSlew (0.12))로 회전한다. 표본 사이는 그 hop의 (잘린) 증분으로 선형 보간한다.
  - 태어날 때 ψ = ψ*다.
  - 비측정 hop과 coasting 중에는 ψ를 그대로 둔다 (P1이 !observed || !on일 때 off를 유지하는 것과 같다).
  - θ̂는 감지 않은 (unwrapped) 누적값으로 둔다.

### 5.6 발진기 합성
- **기준 위상 θ̂_v와 주파수 다듬기**
  - 예측: θ̂_pred = θ̂(C_{h−1}) + 2π·f_osc,v,h−1·H/fs.
  - 오차: e = wrap(θ_v,h − θ̂_pred).
  - β = clamp((SNR_v − 10)/20, betaMin (0.2), betaMax (0.9))다. 깨끗하면 측정 위상을 바짝 따르고, 잡음 속에서는 부드럽게 따른다.
  - θ̂(C_h) = θ̂_pred + β·e.
  - 주파수 오프셋 (v1.2, 이득은 v1.3): f_off ← clamp(f_off + γ·e/(2π H/fs), ±12.5 % f_track)이다.
    - **γ = min(0.2, 0.5/c_b)·β (v1.3)**. c_b = |m_c|/H이고, m_c는 그 목소리가 이번 hop에 실제로 쓴 창 (2단계, 없으면 1단계)의 무게중심이다 (m 단위; 과거 쪽 창에서 약 −0.297·(N_p − N_f)).
    - 주파수 오차 δ가 있으면 LS 위상은 2π·δ·m_c/fs만큼 치우친다. 이것이 적분 루프 안의 지연 검출기처럼 작동한다. 루프는 γ·c_b < β일 때만 안정하므로, 고정 γ = 0.2β는 N_p − N_f > 약 269에서 진동한다 (관문 ① 모의 실험: N_p 320에서 −0.6 ~ +3.0 Hz를 오감).
    - 이 이득이면 긴 창에서도 수렴한다.
    - **낮은 SNR에서 멈춤 (v1.5)**: SNR_v < 12 dB이면 γ = 0이다 (새는 항만 작동해 f_off → 0). 구현 시험에서 f_osc 표준편차가 대역 SNR 12 dB에서 0.67 Hz, 0 dB에서 2.5 Hz였고 (±12.5 % 한계까지 감), 배음 k에서 k배가 된다.
    - **같은 id 트랙의 3 % 넘는 도약**에서도 f_off ← clamp(f_osc,prev − f_track,new)로 연속을 지킨다 (구현이 v1.1 규칙을 유지; 채택).
    - 범위는 온음까지 덮는다. 계단식 라인에서 트래커가 늦게 미끄러져도 따라가기 위해서다 (Gemini 지적 1).
    - 새는 항: |e| < 0.2 rad인 hop에서는 f_off ← 0.98·f_off로 트래커 쪽으로 천천히 돌아간다. 노이즈로 떠도는 것을 막는다.
    - 태어날 때 f_off = 0이다.
    - **이어 붙이기·합침에서는 0으로 두지 않는다.** 발진기 주파수가 이어지게 f_off ← clamp(f_osc,prev − f_track,new)로 둔다 (Gemini 지적 6).
  - 다음 hop의 f_osc = f_track + f_off이고, LS 기저 f_b도 같다.
  - 구간 [C_{h−1}, C_h)의 증분은 일정하게 (θ̂(C_h) − θ̂(C_{h−1}))/H다.
  - 태어날 때 θ̂ = θ_v, f_off = 0이다.
  - 계단식 베이스 라인에서 트래커 주파수가 늦게 따라와도 발진기는 측정 위상을 따라 빠르게 새 음으로 간다 (V3c로 잰다).
- **배음 진폭**: a_vk = G_L(f_v)·g(f_v)·w_k(f_v)·R_k(f_v)·A_v·c_v·σ_v.
  - g, w_k: P1 `lookup(f)`.
  - R_k
    - voicing 0: k·f > 220 Hz에서 P1과 같은 감쇠를 쓴다 (`rolloff(kf,220)`와 `research_.upperBlend`).
    - voicing 1: f ≥ 73.3 Hz이면 corner = max(220, 3f)다 (R4c).
  - G_L: voicing 0에서 1이다. voicing 1에서는 10^(L·s(f)/20)이고 s(f)는 R4-L 정의를 따른다.
    - s(f)는 73.3 Hz에서 0, 92.4 Hz까지 3·log2(3f/220)로 올라 1, 150 Hz까지 1이다. 150–220 Hz에서는 log2(220/f)/log2(220/150)로 내려가 220 Hz에서 0이다 (R4-L 코드와 같음).
  - hop 끝값 사이는 표본 단위로 선형 보간한다.
- **합성**: s_res(n) = Σ_v Σ_{k=2..8, k f ≤ 700} a_vk(n)·cos(k θ̂_v(n) + ψ_vk(n))이다.
  - 회전 재귀 또는 `fastmath`의 sincos를 쓴다.
  - n ∈ [C_{h−1}, C_h)이고 출력 ring에 쓴다. `take()`가 읽고 지운다.
- **엔벨로프 강제는 없다.** 크기가 입력을 따르고, 과거 쪽 창이 앞울림을 막는다. V3d로 확인한다.

### 5.7 섞기와 출력
- `out = s_res`, `appliedGain = 1`이다. 그다음은 P1 그대로 `preFilter = out·appliedGain + hp` → `out_` (150–600) → 48k로 간다.
- 모듈 출력은 '충실' 수준 (vb_level 0 dB)이다.

### 5.9 실시간 제약과 연산량
- 할당하지 않고 고정 배열만 쓴다. 상태는 인스턴스당 10 kB 이하다.
- hop당 연산량:
  - LS: 열 ≤ 16 × 길이 ≤ 345 × 상삼각 136 ≈ 4.7만 MAC (기저 재귀 포함 약 6만).
  - 부분음 투영: ≤ 56 × 383 ≈ 2.1만.
  - 합성: 16 표본 × ≤ 56 배음.
- 초당 약 1.6–2천만 연산이다. P1의 예전 16열 modulation 맞춤이 엔진 연산의 3/4이었으므로 (`pvb_vb_modulation.h:5-7`), 대칭 누적, 회전 재귀, 빈 목소리 생략이 필수다.
- 호스트 목표: 평균 ≤ 1.6 × P1이고, hop당 최악 시간을 함께 보고한다.
