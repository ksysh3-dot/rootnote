# Resultant 코어 — P1 구조 개편 설계 메모 (초안, 2026-10-30)

사용자 요청 (2026-10-30 저녁): "P1에서 유지할 것만 유지하고 나머지를 전부 뜯어고쳐. P1에 계속 덧대는 식으로는 근본적인 아키텍처의 고질병을 해결 못 할 것 같다." 이 메모는 그 판단의 근거, 남길 것과 바꿀 것, 단계를 적는다. 엔진은 아직 바꾸지 않았다.

## 진단: 고질병은 "층의 크기를 분석 신뢰도가 정한다"는 것
- 층이 있느냐 없느냐를 정상 사인 맞춤 검사가 정한다. 이 검사는 128 ms 창 (`kPvN` 384 @ 3 kHz)으로 Fit을 판정하고, 28 hop 이력 유지를 거친다. 그래서 같은 음의 재어택마다 층이 약 0.2초 비고 (`research_r4l_trace_gap.py`), 노이즈나 믹스에서는 깜빡인다 (`research_r4l_gate_flicker.py`).
- 음악 엔벨로프 강제는 `gain = clampv(as/ps, 0, 1)`이다 (`core52`). 층을 음악 엔벨로프 아래로 끌어내릴 수만 있고, 빈 곳을 채우지는 못한다.
- P1이 깨끗한 이유는 층이 입력 배음보다 약 7 dB 아래에 있어 관문의 흔적이 가려지기 때문이다. R0–R4가 부딪힌 천장이 이것이다. 층을 입력 배음 위로 올리는 순간 (R4c 단독 +3 dB, L6 +9 dB) 흔적이 모두 들린다 (R4-L 블라인드 4회).
- P1 전체가 나쁜 것은 아니다. 바꿀 것은 **크기 경로**다. 크기가 음악을 따르지 않고 분석 관문을 따른다.

## 남길 것 (검증된 부분)
- 3 kHz 대역 경로, LR4 190 Hz 분리, 150–600 Hz 출력 필터, 엔진 체인 (리미터, 수준 추정, 폰 리미터 추정).
- HPSS (조화·타격 분리). 타격층 (burst)도 남긴다. 사용자의 노이즈 판정 기준 ("가장 큰 타격")이 여기에 있다.
- PV 트래커는 **음높이 후보 공급원으로만** 쓴다 (추적 85–94 %, 아래 측정에서 어떤 트랙이든 맞는 비율 88.6 %).
- 무게·이득 표, R1 위상 (크레스트 최적), 73 Hz 아래의 R3-a (채택됨).

## 바꿀 것
- fade, permission, Fit 관문이 정하는 크기와, 거기에 묶인 hop마다 그레인을 만드는 합성.
- 대신 **트랙마다 위상이 이어지는 k·f 발진기**를 둔다. 크기는 `w_k(f) × A_track(t)`이다. A_track은 입력 (HPSS 조화부)을 트랙 주파수에서 복조한 표본 동기 진폭이다 (시간 분해능 약 10–20 ms). 크기가 입력 음을 그대로 따라가므로 재어택 공백도, 관문 깜빡임도 구조적으로 생기지 않는다.
- Fit 잔차는 느린 히스테리시스 "음높이 신뢰도"로 바꾼다. 신뢰도는 트랙 가중을 서서히 바꿀 뿐, 잡혀 있는 음을 끄지 않는다. 지금 관문이 맡던 노이즈·가짜 부분음 거부는 이 신뢰도와 복조 진폭 (노이즈에서는 작다)이 나눠 맡는다. 위험은 이쪽으로 옮겨 간다.
- 음역 모서리와 세기는 "폰에서 들리는 배음" 기준으로 다시 정한다. 공격성은 손잡이 하나로 둔다.
- 쌓여 온 연구 플래그는 새 경로에 들이지 않는다.

## 설계를 가르는 측정: 음높이 정확도 (`research_resultant_pitch_truth.py`)
- 방법: Slakh train 6곡 (Track00060, 00040, 00001, 00005, 00012, 00020), 앞 30초. validation 분할은 열지 않았다.
- 베이스가 큰 hop (MIDI 음이 있고, 스템 40–220 Hz가 p95에서 10 dB 안)에서 P1 트래커와 MIDI 정답을 비교했다.
- 결과 (19 373 hop):
  - **가장 센 40–220 Hz 트랙이 틀린 비율 (> 50 cent) 20.0 %**, 그중 옥타브·12도 오류 7.4 %.
  - 곡별로는 4.2 ~ 37.0 %이다.
  - 트랙이 하나도 없는 경우는 0 %이고, **어떤 트랙이든 맞는 비율은 88.6 %**이다.
- 뜻: "가장 센 트랙 = 베이스 음"으로 하나만 골라 입력 엔벨로프를 입히는 설계는 쓸 수 없다. 5번 중 1번 틀린 음을 크게 낸다.
- 그래서 **트랙마다 자기 주파수에서 복조한 진폭**을 쓴다 (단일 음 선택 없음). 이렇게 하면 다음이 성립한다.
  - 베이스의 2배음을 잡은 트랙은 베이스 배음열의 짝수 배음을 만든다. 틀린 음이 아니다.
  - 다른 악기의 낮은 음은 P1처럼 그 악기의 배음을 만든다.
  - 노이즈에서 생긴 트랙은 진폭이 노이즈 수준이라 작다.

## 단계
- **0단계 (스크립트만, 몇 시간):** 오프라인 시제품을 만든다.
  - P1 trace의 트랙 주파수와 StageCapture의 조화부로 트랙별 복조 진폭을 구하고, 발진기 층을 합성한다. vb_on=0 체인 출력에 L6과 같은 150–600 Hz 수준으로 더한다.
  - 지표: 맨 베이스 150–600 정점 (목표 21 ms), 베이스+노이즈의 배음 선 몫, T60의 0.5초별 이득 (목표: 끊기지 않을 것), LOGOFF.
  - 그 뒤 같은 방식의 블라인드를 한다.
- **1단계 (며칠):** 새 경로를 C++로 만든다.
  - 새 파일 (`pvb_resultant.*`)과 새 vb_algo로 둔다. 선택하지 않으면 P1은 비트까지 같다.
  - 코드보다 먼저 설계 사전 등록 (관문 ①, SOLO에서는 Sonnet)을 거친다.
- **2단계:** 동결 후보 → validation 1회 → 관문 ② → (앱 통합은 사용자 결정).
