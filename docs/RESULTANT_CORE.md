# Resultant 코어 설계서 v1.6 (2026-10-30)

상태 (2026-10-31): v1.5 구현 (83c862d)은 12절에서 수용 불합격으로 판정했다. 그러나 16.16 (기준 엄격성 점검, P1 기준 재판정)과 16.18 (LOGOFF 4.12 s는 진짜 음 시작)에 따라 **P1보다 대부분 나은, 채택에 가까운 후보**로 다시 판정했다. 앱 통합 계획은 17절에 있다 (구현 전). 이전 상태 (2026-10-30): 12절 불합격. v1.6 변경은 13절에 있고, 그 부분은 관문 검토 전이다. 이전 상태: 설계. 관문 ① (Sonnet 독립 검토, v1과 v1.1 두 번)과 Gemini (Argon Medium, 다른 계열 교차 검토)의 지적 가운데 Opus가 확인한 것을 반영했다. 변경 기록은 11절에 있다. 코드는 아직 없다. 이 문서는 구현 (Sonnet A)과 검증 (Sonnet B, A와 다른 에이전트)의 기준이다. 숫자 문턱은 구현 전에 정했고, 결과를 본 뒤에 바꾸지 않는다. 바꿔야 하면 버전을 올리고 이유를 적는다.

## 0. 요약
P1의 고질병은 **배음층의 크기를 음악이 아니라 분석 관문이 정한다**는 것이다. 새 코어는 P1의 앞단 (대역 경로, HPSS, 트래커, 표, 위상 보정)은 그대로 두고 지속층의 크기 경로만 새로 만든다.
- **무엇이 울리나** (음높이 후보): P1의 128 ms 트래커가 정한다.
- **얼마나, 언제 울리나** (진폭·위상): 트랙 주파수에서 과거 쪽에 무게를 둔 짧은 창으로 최소제곱 (LS)을 풀어 입력에서 직접 읽는다. 해상도는 10–107 ms이고 신호 대 잡음비와 가까운 음 간격에 따라 정해진다. 미래는 최대 8 ms만 본다.
- **합성**: 목소리마다 위상이 이어지는 발진기가 표본 단위로 k·f 배음을 만든다. 주파수는 측정 위상으로 다듬는다.
- **신뢰도**: 맞춤 검사 (Fit)는 층을 끄지 않는다. 목소리는 한 hop 안에서 판정해 태어나고 (지연 없음), 입력에 그 음이 없어질 때 끝난다.
- **바뀌지 않는 것**: 지연, 출력 대역, 엔진 체인, 앱. vb_algo 15를 고르지 않으면 P1은 비트까지 같다.

## 1. 근거 (진단)
- **관문이 층의 존재를 정한다.** P1 지속층은 128 ms 정상 사인 맞춤 (`kPvN` 384 @ 3 kHz, 잔차 ≤ −15 dB)과 28 hop 이력 유지 (`hold52_`)를 통과해야 fade가 1로 간다 (`pvb_vb52.cpp` `tr.fade+=...`).
  - 같은 음을 다시 치면 이력에 남은 어택 프레임의 나쁜 잔차 때문에 약 0.2초 비고 (`research_r4l_trace_gap.py`), 노이즈와 믹스에서는 깜빡인다 (`research_r4l_gate_flicker.py`: 음마다 실패 0–41 hop, 전환 ≤ 10회).
  - 새 음높이는 이력이 없어서 (res = −200) 바로 통과한다.
- **강제 이득은 끌어내리기만 한다.** 음악 엔벨로프 강제 `gain = clampv(as/ps, 0, 1)` (`core52`)는 층을 줄일 수만 있고 빈 곳을 채우지 못한다.
- **P1이 깨끗한 이유.** 층이 입력 배음보다 약 7 dB 아래라 관문의 흔적이 가려지기 때문이다. 그 위로 올리면 흔적이 모두 들린다 (R4-L v1/v2 블라인드 4회, docs/RESULTANT_R4.md).
- **음높이 측정** (`research_resultant_pitch_truth.py`, Slakh train 6곡, 베이스가 큰 hop 19 373개): 가장 센 40–220 Hz 트랙이 틀린 비율은 20.0 % (옥타브·12도 7.4 %)이고, 어떤 트랙이든 맞는 비율은 88.6 %다. 그래서 트랙마다 따로 처리한다.

## 2. 목표와 비목표
- **목표**
  - G1: 층 크기가 입력 음을 따른다. 재어택, 글라이드, 노이즈에서 공백과 깜빡임이 없고, 앞울림 (pre-echo)도 없다.
  - G2: 기본 음색 (voicing 0)에서 고립된 정상 톤의 수준과 위상 정렬이 P1과 같다. 믹스에서는 P1이 강제 이득 (≤ 1)으로 깎던 만큼 커질 수 있다. 이것은 의도한 차이이며 V5(b)에서 잰다.
  - G3: 공격적 음색 (voicing 1)을 관문 흔적 없이 낸다.
  - G4: 지연, 출력 대역, 엔진 체인, 앱은 그대로다. 알고리즘 0–14는 비트까지 같다.
- **비목표**: 타격층 재설계, 트래커 교체, 73 Hz 아래 R3-a 변경, 앱 통합.

## 3. 시간축 (관문 ①에서 코드 대조 확인)
- 코어 fs = 3000 Hz, hop H = 16이다. hop h는 코어 인덱스 `i_h = 383 + 16h`에서 `pvFrame52()`가 불릴 때다 (future = 0, defer = 0).
- **입력 시간**: 분석 중심 c_h = i_h − 382 (P1 trace 헤더 [9]). 코어 시계는 48 kHz 입력 시간축보다 1359 표본 (28.3 ms, 데시메이터) 늦으므로, 입력 초로 바꿀 때는 c_h/3000 + 1359/48000 s다 (수용 감사에서 찾은 누락, `research_core_api.hop_time` 정정).
- **ring 인덱스 축**: `bhRing_`, `detailRing52_`, `md2_52_`의 슬롯 j는 입력 시간 j − 191에 해당한다. c_h에 해당하는 슬롯은 `n_h = i_h − 191`이다.
  - 쓸 수 있는 범위는 [i_h − 511, i_h]다 (kRing 512). 그러므로 과거는 n_h 기준 최대 320, 미래는 최대 191이다.
- **출력 코어 시간**: hop h의 추정은 `C_h = i_h + 16`에 놓인다. 출력 표본 n은 입력 시간 n − 398에 해당한다.
- **쓰는 구간**: hop h는 [C_{h−1}, C_h) = [i_h, i_h + 16)를 쓴다. core52가 표본 i_h를 읽기 전에 쓰므로 인과적이다 (`takeGrain52`보다 앞).
- **지연**: 지연은 P1과 같다. 같은 VbHpv 인스턴스를 쓴다.

## 4. 구조와 통합
### 4.1 블록도
```
x(48k) ─▶ [P1] 3 kHz ─▶ LR4 190 Hz ─▶ HPSS ─┬─ bh ─▶ [P1] PV 트래커 (128 ms) ─▶ 트랙 목록 ─┐
                                              │  bh / detailRing52_ ─▶ [새] LS (과거 쪽 창) ◀─┤
```

### 4.2 통합 방식 (v1.1: 같은 인스턴스에 붙인다)

    - C1 프로필처럼 `p1PlusFixed_=true`로 두고 `p1PlusFlags_=0`, `p1ppImpactMode_=0`, `p1ppV04_=0`으로 고정한다. 그래야 뒤에 오는 호스트 설정자 (`pvb_engine.h:203-217` → `pvb_vb.h:219,240,247`)가 덮어쓰지 못한다.
    - `stageFlags_=0`이다. 0이 아닌 stage 연구 플래그를 붙이려 하면 15에서는 무시하거나 거부한다.
    - `gen_` (setGenResearch, 프로필 전환 뒤에도 남음)는 `resultantOn_`일 때 쓰지 않는다.

  - `pvb_engine.h:335`의 `vbMods_` 초기값에 16번째 `&vbAlpha2_`를 추가한다. 빠지면 nullptr로 모든 알고리즘이 터진다.

## 5. 새 구성요소
### 5.1 hop 입력
`hop()`이 읽는 것은 다음과 같다.
- `tr52_[0..nt52_)`: id, f, dfdt, a, residual, rawResidual, missing, age, strong.
- `bhRing_`, `detailRing52_`, `md2_52_` (ring 축).
- bh 프레임 스펙트럼: `xr52_`/`xi52_`를 loBin_..hiBin_에서 hypot으로 구한다. `binHz_` = 3000/2048.
- 측정 hop일 때만: `sm52_`와 `src[0]`, `src[1]`, ns (pvFrame52 지역 변수 `src`/`ns`는 hop에 인자로 넘긴다).
- `percEnv52_`, `harmEnv52_`.

### 5.2 목소리 관리
- **슬롯과 이어 붙이기**
  - 슬롯은 V_max = 8개이고, 목소리는 트랙 id에 묶인다.
  - 트랙이 사라진 목소리는 **coasting**에 들어간다. 이때 주파수 = 마지막 f + ḟ_s·Δt (ḟ는 감쇠 0.9/hop)이고, LS와 SNR은 그 주파수에서 계속 잰다.
  - coasting 중 이어 붙이기: 최대 48 hop (256 ms) 안에, 예측 주파수 3 % 안에 새 id의 트랙이 나타나면 같은 목소리로 이어 붙인다. 목소리 id, θ̂, ψ, c를 유지한다.
- **상태와 전이**
  - **CAND → ON** (v1.3): 측정 hop 두 번 (태어난 hop과 그다음 측정 hop, 약 5.3 ms)으로 판정한다. 두 hop 모두에서 (a)와 (b)를 만족하고, 그 사이에서 (c)를 만족해야 한다.
    - (a) SNR_v ≥ snrOn (15 dB).
    - (b) 근거: 측정 hop의 전대역 피크 목록 `src[0]` ∪ `src[1]`에, k ∈ {1,2,3,4}에 대해 |p − k·f_v| ≤ max(4 Hz, 3 %·k·f_v)인 피크 p가 있다. P1 Grid 규칙과 같은 성격이라, 기본음이 약한 베이스도 2–4배음 근거로 받는다.
    - (c) 두 hop 사이 |Δf|/f ≤ 3 %이고, |Δf/Δt| ≤ maxDfdtBirth (200 Hz/s). 새 트랙의 dfdt는 첫 hop에 0이라 쓸 수 없다. 그래서 두 hop의 주파수 차이로 잰다. 킥 쓸기와 과도 피크가 여기서 걸린다.
    - v1.1의 한 hop 경로 (e)는 없앴다. 아끼는 시간이 5.3 ms뿐인데, 킥을 통과시킨다.
  - **CAND 해제** (v1.3): 트랙이 측정 hop 2번 연속 없거나, 12 측정 hop 안에 ON이 되지 못하면 슬롯을 비운다.
  - **같은 hop의 태어남 순서 (v1.2)**: 낮은 주파수부터 처리한다. 태어나는 목소리가 이미 ON인 목소리나 같은 hop에 먼저 ON이 된 목소리에 대해 종속 조건을 만족하면, σ_v = 0으로 시작한다 (감쇠를 기다리지 않음).
  - **ON 유지**: Fit 실패 (res > −15, raw 나쁨)로는 내려가지 않는다.
  - **ON → REL** (v1.3): 다음 가운데 하나다.
    - SNR_v < snrOff (6 dB)가 **측정 hop 24번 연속** (128 ms)이다.
      - SNR 추정은 128 ms 프레임이 겹쳐서 약 24 hop 동안 상관된 ±3.5 dB 흔들림을 가진다 (관문 ① 모의 실험). 6 hop으로 판정하면 경계의 음이 초당 4–7번 깜빡인다.
      - 진폭은 A_v가 입력을 따르므로, 음이 실제로 끝난 뒤 ON이 128 ms 남아도 층은 이미 작다.
    - **LS 근거 규칙**: 1단계 LS의 A_v가 15 Hz 안에 있는 더 센 LS 이웃의 A보다 20 dB 넘게 작은 상태가 측정 hop 3번 연속이면 REL이다.
      - 이웃 음의 Hann 주엽이 스펙트럼 SNR을 채워서 꺼진 목소리가 켜진 채 남는 것을 막는다 (5.9 Hz 떨어지면 이웃 대비 −1.0 dB, 9 Hz면 −3.7 dB, 12 Hz면 −8.6 dB).
      - coasting 목소리는 −12 dB로 더 엄격히 본다.
    - coasting이 48 hop을 넘는다.
    - 슬롯이 넘친다 (A·c가 가장 작은 목소리부터).
    - 넘쳐서 밀려난 목소리는 페이드 전용 칸 2개 중 하나로 옮긴다 (v1.2). 이 칸은 합성만 하고 LS에는 들지 않으며, τ 5 ms로 사라진다. 그래서 같은 hop에 새 목소리가 슬롯을 쓸 수 있다.
  - **REL → ON** (v1.3): 다음 둘을 만족하는 상태가 측정 hop 3번 연속이면 된다 (트랙이나 coasting 주파수 기준).
    - SNR_v ≥ snrOff + 4 dB (10 dB).
    - 근거 (b)도 만족한다.
    - 한 번 확인된 목소리이므로 태어날 때보다 문턱이 낮다. 다만 해제 (24 hop)와 재개 (3 hop, +4 dB)의 비대칭 이력으로 경계의 깜빡임을 막는다.
  - **REL → 빈칸**: c < 0.01이고 트랙도 없다.
  - **비측정 hop** (missingFrame52): 태어남이 없고, 상태는 SNR 규칙만 따른다.
- **종속 목소리** (v1.5: 주파수 비만으로는 판정하지 않는다)
  - 기본 조건: 어떤 ON 목소리 u가 f_u < 0.9 f_v이고, m ∈ {2,3,4}에 대해 |f_v − m f_u| ≤ 0.015 f_v다.
  - 추가 조건 (모두 만족해야 종속):
    - (i) u가 ON으로 측정 hop 8번 넘게 이어졌다.
    - (ii) u의 |ḟ_s|는 50 Hz/s 이하다.
    - (iii) A_v ≤ 2·A_u.
    - (iv) **위상 고정**: 최근 측정 hop 8번 동안 φ = θ_v − m·θ_u의 원형 표준편차가 0.6 rad 이하다.
  - 예외: 두 목소리가 같은 hop에 태어났으면 (같은 어택) 기본 조건만으로 종속이다.
  - 이유: 킥 꼬리 (약 50 Hz, 쓸어 내림)가 ON이 되면, 주파수 비만으로는 100 Hz 베이스가 그 "2배음"으로 판정되어 꺼진다. 구현 시험에서 베이스+킥+핑크의 V4(a)가 2.0 dB, (b)가 22.7 %로 실패했고, 종속을 끄면 0.63 dB와 0.4 %였다. 같은 음원의 배음은 위상이 고정되어 있고, 서로 다른 음원은 떠돈다.
  - 종속 목소리는 LS에 들어간다. 합성 가중 σ_v는 0으로 간다 (τ 20 ms). 종속이 아니면 σ → 1.
- **c (신뢰도 가중)**
  - c* = 1 (ON), 0 (CAND, REL)이다.
  - τ = 8 ms (올라감), 30 ms (내려감).
  - hop 끝값 사이는 표본 단위로 선형 보간한다.

### 5.3 LS (진폭·위상)
- **LS 집합**: ON, CAND, 그리고 c > 0.1인 REL 목소리 (최대 8개). 종속 목소리와 coasting 목소리를 포함한다. c ≤ 0.1인 REL은 빼고, 그 A는 마지막 값을 쓴다 (c가 곧 0이 된다).
- **신호 x(m)** (m = −N_p..N_f, 슬롯 j = n_h + m)
  - ampSource 0: `bhRing_` (기본).
  - ampSource 1: `detailRing52_` (HPSS 이전, 어택이 약 30 ms 빠르지만 타격 에너지가 섞인다).
- **창** (과거 쪽에 무게, 앞울림 방지)
  - 과거 쪽: m ∈ [−N_p, 0]에서 w = ½(1 + cos(π m/(N_p+1))).
  - 미래 쪽: m ∈ [0, N_f]에서 w = ½(1 + cos(π m/(N_f+1))).
  - N_f = min(N_p, nFuture) (기본 24 = 8 ms).
- **두 단계 LS (v1.2)**: 창 하나로 모든 목소리를 풀면, 꺼져 가는 약한 목소리 하나가 새로 어택한 깨끗한 목소리의 창까지 길게 만든다 (Gemini 지적 3). 그래서 두 단계로 푼다.
  - **1단계 (함께 풀기)**: LS 집합 전체를 과거 N_J, 미래 N_f 창으로 함께 푼다. 목소리끼리 분리하고 약한 목소리를 안정되게 잡는 단계다.
    - N_J = clamp(max(N_lo, N_sep, N_snr(s_ON)), N_lo, 320)이다.
    - s_ON은 **ON 목소리들의** SNR 최소값이다. CAND와 REL은 맞춤에는 들어가지만 이 최소값에서는 뺀다. ON이 없으면 전체 최소값을 쓴다.
  - **2단계 (목소리별 다듬기)**: SNR_v ≥ 18 dB인 목소리 v마다 한다.
    - 잔차 r_v(m) = x(m) − Σ_{u≠v} (1단계 계수로 만든 u의 성분)을 구한다.
    - r_v에 단일 목소리 LS를 과거 N_v, 미래 N_f 창으로 다시 풀어 A_v와 θ_v를 얻는다.
    - N_v = clamp(max(N_lo,v, N_snr(SNR_v)), N_lo,v, N_J)이고, N_lo,v는 f_v의 한 주기다.
    - SNR_v < 18 dB이면 1단계 값을 쓴다.
    - **자기 배음 열 (v1.3)**: 2단계 LS에 그 목소리의 2f와 3f (200 Hz 아래일 때)를 성가신 열로 함께 넣는다.
      - 과거 쪽 비대칭 창에서는 Hann 영점이 배음 위에 오지 않는다. 그래서 자기 배음 누설로 진폭이 0.4–2.8 dB 치우친다 (60 Hz 이하에서 1.7–2.8 dB, 관문 ① 모의 실험).
      - 이 열은 그 치우침을 없앤다. 쓰는 것은 기본음 계수뿐이다.
- **창 길이 규칙**
  - N_lo = clamp(⌈fs/f_low⌉, nMin (30), 320): 가장 낮은 목소리의 한 주기 이상이다. Hann의 영점이 그 배음 위에 와서 배음 누설이 작다 (관문 ① 모의 실험).
  - N_sep = ⌈2κ·fs/Δf_min⌉ − N_f: 전체 길이가 2κ·fs/Δf_min 이상이 되게 한다. Δf_min은 LS 집합의 가장 작은 간격이고, κ는 1.0이다.
  - N_snr(s): s ≥ 30 dB이면 N_lo, s ≤ 12 dB이면 320이고, 그 사이는 log-선형이다. 잡음 속 진폭 흔들림 (관문 ①: SNR 15 dB, N 30에서 hop당 2.5 dB)을 막는다.
  - 이력: N_J와 N_v 각각, 목표가 현재와 25 % 넘게 다른 상태가 3 hop 이어질 때 바꾼다. LS 집합이 바뀌면 N_J는 바로 바꾼다.
  - **전환 상태 (v1.2)**: ON 목소리의 위상 오차 |e| > 0.5 rad가 측정 hop 2번 연속이면 음높이가 옮겨 가는 중으로 본다. |e| < 0.3 rad가 될 때까지 그 목소리의 N_v = N_lo,v로 둔다.
- **기저**
  - 위상 Φ_v(m) = 2π(f_b,v·m + ½ ḟ_s,v m²/fs)/fs다.
    - f_b,v = f_track + f_off,v (5.6의 ±12.5 % 한계; v1.5에서 문구 정정). coasting이면 예측 주파수다.
    - ḟ_s는 트랙 dfdt의 4 hop 이동평균이며 ±400 Hz/s로 자른다.
  - 열은 cos Φ_v, sin Φ_v이고 실수 미지수는 2V개다.
  - 기저는 회전 재귀로 만든다 (처프는 2차 위상 재귀). 표본마다 cos, sin을 부르지 않는다.
- **풀이**
  - G = Σ w b bᵀ (대칭, 상삼각만 누적), r = Σ w b x를 세운다. G에 λI (λ = 1e−4·tr(G)/(2V))를 더하고 Cholesky로 푼다.
  - 두 목소리가 3 Hz보다 가까우면 같은 소리로 보고 젊은 쪽을 늙은 쪽에 합친다. 젊은 쪽은 REL로 보내고, 늙은 쪽은 이어 붙인 것으로 처리한다. 3–11.8 Hz 사이는 합치지 않고 긴 창으로 함께 푼다 (관문 ①: 5.9 Hz, N 191에서 cond 5.3).
- **출력**
  - A_v = √(α² + β²) (사인 첨두 진폭; 고립 정상 톤에서 tr.a와 같은 단위).
  - θ_v = atan2(−β, α): 슬롯 n_h에서 cos의 위상이다. e^{−jΦ} 투영과 같은 규약이고, FFT와 `ModulationFit`의 규약과도 같다.

### 5.4 신뢰도 입력
- **SNR_v** (dB): bh 프레임 크기 스펙트럼에서 구한다.
  - 피크 = f_b,v 주변 ±2 bin의 최대값.
  - 바닥 = 다음 bin들의 중앙값이다.
    - |f_b − f_v|가 22–45 Hz 사이다 (128 ms Hann의 주엽 ±15.6 Hz와 첫 옆엽 18–22 Hz를 피함).
    - **제외 (v1.2)**: 모든 LS 목소리와 이번 hop의 모든 트랙 주파수 u, 그리고 그 2u, 3u에서 ±22 Hz 안의 bin은 뺀다. 저음 (약 22–60 Hz)에서 자기 2배음이나 3배음을 바닥으로 읽어 SNR이 낮게 나오는 것을 막는다 (Gemini 지적 4).
  - 쓸 bin이 4개 미만이면 22–70 Hz까지 넓힌다. 그래도 4개 미만이면 전역 바닥을 쓴다: bh 스펙트럼 20–200 Hz에서 같은 제외를 한 bin들의 중앙값이다.
- **두드러짐**: 5.2 (b). 측정 hop에서만 쓴다.
- **raw, res**: 트레이스에 기록만 하고 판정에는 쓰지 않는다. 비교와 진단용이다.

### 5.5 입력 부분음 위상과 정렬 목표 ψ_vk (v1.1: P1의 보정을 그대로 쓴다)
- **hop 안 순서 (v1.2)**: LS (1, 2단계) → θ̂·f_off 갱신 (5.6) → 부분음 투영. 투영은 갱신된 다음 hop 주파수 f_osc를 쓴다 (Gemini 지적 5).
- **측정** (측정 hop만): k = 2..8, k·f_v ≤ 700 Hz인 배음에 대해 한다.
  - `md2_52_`에서 n_h 중심, 대칭 Hann 반길이 N_k로 주파수 k·f_osc,v (처프 k·ḟ_s)에 단일 투영한다. 결과는 C_vk다 (같은 위상 규약).
  - N_k = clamp(round(191·2/k), 48, 191)이다 (k = 2에서 191, 4에서 96, 8에서 48). 높은 배음은 주파수 오차가 k배로 커지므로 짧은 창의 넓은 주엽으로 받는다.
- **존재 판정 (이력, v1.2)**
  - 켜짐 조건 (모두 만족): |C_vk| ≥ 0.01·A_v, |C_vk| ≥ `pvAbs_`, 그리고 `sm52_`에서 k·f ±max(3 Hz, 2 %) 안에 국소 최대가 있음 (P1의 `found`와 같은 시험).
  - 꺼짐 조건: |C_vk| < 0.005·A_v가 측정 hop 2번 연속이거나, found 시험이 2번 연속 실패.
  - 켜짐과 꺼짐 사이에 오가는 깜빡임을 막는다.
- **보정**: Φcomp(f) = interp52(vb52t::kPhase, 3920, (f−20)·4) + phaseDelta52(f) + 2π f·tc다.
  - tc = 2·80/48000 + 398/3000 − 7052/48000 ≈ −10.917 ms이다. `renderTrack52`의 식과 같다.
  - kPhase = arg H_eqref − arg H_out이고, phaseDelta52 = arg(H_eq,actual/H_eqref)이다 (관문 ① 확인).
  - EQ는 hop마다 현재 값을 쓴다.
- **목표 위상**
  - 부분음이 있으면: ψ* = arg C_vk − k·θ̂_v(C_h) + Φcomp(k f_v).
  - 부분음이 없으면: ψ* = `psi52(k, f_v, crest)`. crest는 매개변수이고 기본 0 (= kPsi, P1 기본값)이다.
- **회전과 유지**
  - hop마다 ψ ← ψ + clamp(wrap(ψ* − ψ), ±psiSlew (0.12))로 회전한다. 표본 사이는 그 hop의 (잘린) 증분으로 선형 보간한다.
  - 태어날 때 ψ = ψ*다.
  - 비측정 hop과 coasting 중에는 ψ를 그대로 둔다 (P1이 !observed || !on일 때 off를 유지하는 것과 같다).
  - θ̂는 감지 않은 (unwrapped) 누적값으로 둔다.

### 5.6 발진기 합성
- **기준 위상 θ̂_v와 주파수 다듬기**
  - 예측: θ̂_pred = θ̂(C_{h−1}) + 2π·f_osc,v,h−1·H/fs.
  - 오차: e = wrap(θ_v,h − θ̂_pred).
  - β = clamp((SNR_v − 10)/20, betaMin (0.2), betaMax (0.9))다. 깨끗하면 측정 위상을 바짝 따르고, 잡음 속에서는 부드럽게 따른다.
  - θ̂(C_h) = θ̂_pred + β·e.
  - 주파수 오프셋 (v1.2, 이득은 v1.3): f_off ← clamp(f_off + γ·e/(2π H/fs), ±12.5 % f_track)이다.
    - **γ = min(0.2, 0.5/c_b)·β (v1.3)**. c_b = |m_c|/H이고, m_c는 그 목소리가 이번 hop에 실제로 쓴 창 (2단계, 없으면 1단계)의 무게중심이다 (m 단위; 과거 쪽 창에서 약 −0.297·(N_p − N_f)).
    - 주파수 오차 δ가 있으면 LS 위상은 2π·δ·m_c/fs만큼 치우친다. 이것이 적분 루프 안의 지연 검출기처럼 작동한다. 루프는 γ·c_b < β일 때만 안정하므로, 고정 γ = 0.2β는 N_p − N_f > 약 269에서 진동한다 (관문 ① 모의 실험: N_p 320에서 −0.6 ~ +3.0 Hz를 오감).
    - 이 이득이면 긴 창에서도 수렴한다.
    - **낮은 SNR에서 멈춤 (v1.5)**: SNR_v < 12 dB이면 γ = 0이다 (새는 항만 작동해 f_off → 0). 구현 시험에서 f_osc 표준편차가 대역 SNR 12 dB에서 0.67 Hz, 0 dB에서 2.5 Hz였고 (±12.5 % 한계까지 감), 배음 k에서 k배가 된다.
    - **같은 id 트랙의 3 % 넘는 도약**에서도 f_off ← clamp(f_osc,prev − f_track,new)로 연속을 지킨다 (구현이 v1.1 규칙을 유지; 채택).
    - 범위는 온음까지 덮는다. 계단식 라인에서 트래커가 늦게 미끄러져도 따라가기 위해서다 (Gemini 지적 1).
    - 새는 항: |e| < 0.2 rad인 hop에서는 f_off ← 0.98·f_off로 트래커 쪽으로 천천히 돌아간다. 노이즈로 떠도는 것을 막는다.
    - 태어날 때 f_off = 0이다.
    - **이어 붙이기·합침에서는 0으로 두지 않는다.** 발진기 주파수가 이어지게 f_off ← clamp(f_osc,prev − f_track,new)로 둔다 (Gemini 지적 6).
  - 다음 hop의 f_osc = f_track + f_off이고, LS 기저 f_b도 같다.
  - 구간 [C_{h−1}, C_h)의 증분은 일정하게 (θ̂(C_h) − θ̂(C_{h−1}))/H다.
  - 태어날 때 θ̂ = θ_v, f_off = 0이다.
  - 계단식 베이스 라인에서 트래커 주파수가 늦게 따라와도 발진기는 측정 위상을 따라 빠르게 새 음으로 간다 (V3c로 잰다).
- **배음 진폭**: a_vk = G_L(f_v)·g(f_v)·w_k(f_v)·R_k(f_v)·A_v·c_v·σ_v.
  - g, w_k: P1 `lookup(f)`.
  - R_k
    - voicing 0: k·f > 220 Hz에서 P1과 같은 감쇠를 쓴다 (`rolloff(kf,220)`와 `research_.upperBlend`).
    - voicing 1: f ≥ 73.3 Hz이면 corner = max(220, 3f)다 (R4c).
  - G_L: voicing 0에서 1이다. voicing 1에서는 10^(L·s(f)/20)이고 s(f)는 R4-L 정의를 따른다.
    - s(f)는 73.3 Hz에서 0, 92.4 Hz까지 3·log2(3f/220)로 올라 1, 150 Hz까지 1이다. 150–220 Hz에서는 log2(220/f)/log2(220/150)로 내려가 220 Hz에서 0이다 (R4-L 코드와 같음).
  - hop 끝값 사이는 표본 단위로 선형 보간한다.
- **합성**: s_res(n) = Σ_v Σ_{k=2..8, k f ≤ 700} a_vk(n)·cos(k θ̂_v(n) + ψ_vk(n))이다.
  - 회전 재귀 또는 `fastmath`의 sincos를 쓴다.
  - n ∈ [C_{h−1}, C_h)이고 출력 ring에 쓴다. `take()`가 읽고 지운다.
- **엔벨로프 강제는 없다.** 크기가 입력을 따르고, 과거 쪽 창이 앞울림을 막는다. V3d로 확인한다.

### 5.7 섞기와 출력

### 5.9 실시간 제약과 연산량
- 할당하지 않고 고정 배열만 쓴다. 상태는 인스턴스당 10 kB 이하다.
- hop당 연산량:
  - LS: 열 ≤ 16 × 길이 ≤ 345 × 상삼각 136 ≈ 4.7만 MAC (기저 재귀 포함 약 6만).
  - 부분음 투영: ≤ 56 × 383 ≈ 2.1만.
  - 합성: 16 표본 × ≤ 56 배음.
- 초당 약 1.6–2천만 연산이다. P1의 예전 16열 modulation 맞춤이 엔진 연산의 3/4이었으므로 (`pvb_vb_modulation.h:5-7`), 대칭 누적, 회전 재귀, 빈 목소리 생략이 필수다.
- 호스트 목표: 평균 ≤ 1.6 × P1이고, hop당 최악 시간을 함께 보고한다.

## 10. 열린 질문

- **V0 6→15→6**: 시간에 따라 줄어든다 (0.1 s 0.065, 0.5 s 0.013, 1.7 s ≈ 1e-7). ~~15 동안 P1 렌더 상태가 멈춰 있어서다~~ → **정정 (diag16 Q6)**: 프로필을 바꿀 때마다 `reset()`이 VbHpv를 냉시작한다. 6→14→6도 똑같은 0.065를 보인다. 6→15→6과 6→14→6의 차이는 되돌린 뒤 64 ms 동안 0.003이고, 그 뒤로는 비트 동일하다. 15 때문이 아니다. 기준이 잘못 정의된 것이므로 13절에서 다시 정한다.
- **판정자의 원인 해석 (가설, 측정 아님)**
  - A의 어택이 20–30 ms 늦다. bh가 HPSS로 지연되기 때문이다 (V3a, V3h, V3c.enter, V3f).
  - B는 어택이 빠르지만 타격 누출이 생긴다 (V4b, V5a, V7c, V9e).
  - 꼬리가 느리다 (25 dB에서 44–48 ms).
  - V6b는 P1의 Fit 관문이 눌러 두던 킥 꼬리와 서브 톤을 코어가 계속 합성하기 때문이다.
  - V3g는 두드러짐 (b)가 hop +8~9까지 0이라서다.
  - V6a는 덮음 이득이 없다. 트래커 한계로 보며, v2 (트래커 교체) 항목이다.
- **Opus 판단**
  - P1 관문의 병 (공백, 깜빡임, 출렁임)은 측정상 사라졌다.
  - 대신 관문이 하던 다른 일, 곧 음이 아닌 성분 거르기와 타격 억제가 드러났다 (V6b, V7d 4.12).
  - 다음은 v1.6이다. 고치기 전에 진단부터 한다.
    - 틀린 무게와 V5a 낮은 칸이 드럼 어택 뒤 짧은 폭발에 몰리는지 본다. 그렇다면 진폭 추정기 문제다.
    - 아니면 지속 목소리에 퍼져 있는지 본다. 그렇다면 목소리 관리 문제다.
    - 트랙별 비율, 목소리 수명, |ḟ|/f, 감쇠, V3g 근거 (b), V3h 꼬리의 N_v를 본다.
  - 설계 제약: 새로 진폭을 바꾸는 인자는 연속적이고 느려야 한다. 그 인자의 깜빡임 지표도 사전 등록한다. 관문을 새 모습으로 다시 들이지 않는다.

## 13. v1.6 설계 (진단 diag16 근거, 2026-10-30)
진단 자료는 `~/r3a-dev/diag16/`에 있다 (q1–q10 보고서). 기본 Sonnet이 쟀고, 판단은 Opus가 했다. Slakh train만 썼다.

### 13.1 진단 요약 (측정)
- **틀린 음 (V6b)**: 대부분이 드럼 직후의 폭발이 아니다.
  - 킥 뒤 0–200 ms에 44 %가 있다 (시간 비율 17 %). 나머지 56 %는 1 s 넘게 사는 목소리에 퍼져 있다.
  - 태어난 시점과 드럼의 거리는 맞는 음과 같다.
  - 가르는 특징은 f_off 1.3 % 이상, 트래커 raw 나쁨, ḟ다. coasting에 틀린 무게의 30 %가 있다 (맞는 무게는 16 %).
  - **연속 가중치 후보 (Q7)는 모두 기각한다.**
    - f_off 가중은 틀린 음 몫을 14–21 %로 낮추지만, 맞는 무게의 23–37 %와 재어택 무게의 40–69 %를 잃고, 초당 3.8–7.1번 깜빡인다.
    - 느린 Fit 가중은 26–31 %까지만 낮춘다.
    - coasting 감쇠는 효과가 작고 깜빡인다.
    - 주파수가 아직 수렴하지 않은 정상 어택과 틀린 목소리를 이 자료로는 가를 수 없다.
- **가까운 목소리 쌍 (Q3, Q10)**: hop의 54 %에 14 Hz 안의 LS 쌍이 있다.
  - 그 가운데 83 %는 한쪽이 coasting이다. 이 쌍이 틀린 무게의 64 %와 맞는 무게의 36 %를 가진다.
  - N_J = 320 (전체 344 표본)으로는 17 Hz보다 가까운 쌍을 분해하지 못한다 (N_sep이 320에 잘린다).
  - 약한 쪽의 A_joint/A_single은 p95가 약 7이다. LOGOFF 4.12 s의 0.118 (single 0.034)이 이 경우다.
- **V5a 낮은 칸 (Q2)**: 11칸 가운데 7칸이 어택 지연, 3칸이 드럼과 겹침이다. REL이나 넘겨받기는 없다.
- **꼬리 (Q5)**: 음이 끝나면 128 ms SNR이 떨어지고, N_snr이 창을 25 ms 안에 30에서 320으로 늘린다. 창이 끝난 음을 다시 담아 A가 15.8 dB 되살아났다가 107 ms에 걸쳐 빠진다. c와 REL은 관여하지 않는다.
- **V3g (Q4)**: 35 Hz에서는 근거 (b)만 막는다. k = 1, 2가 hop +0부터 국소 최대이지만, "±27 bin 중앙값보다 10 dB 위" 조건이 음이 128 ms 창을 덜 채운 동안 너무 엄격하다. 45 Hz에서는 SNR (a)도 hop +9까지 막는다.
- **어택 보강 (Q8)**: 10 ms 창에서는 대비 (TF) 탐침이 주엽 안에 들어가 쓸 수 없다. 대비 조건 없는 태어남 보강은 맨 음 rise50을 18에서 4 ms로, rise90을 32에서 23 ms로 줄인다 (τ 60). 킥에서 태어난 낮은 목소리는 크게 튀지만 층 대리값은 +0.13 dB 이하다.

### 13.2 바꾸는 것
- **D1 분해능 규칙 (5.3 보충)**
  - 분해 한계 Δf_sep(N) = 2κ·fs/(N + N_f)로 정한다 (N_sep과 같은 식).
  - LS 집합의 두 목소리가 1단계 창 N_J로 Δf_sep보다 가깝고 한쪽이 coasting이면, coasting 쪽을 LS 집합에서 빼고 REL로 보낸다. c는 보통 REL처럼 τ 30 ms로 내려간다. 같은 소리가 트랙 id만 바뀐 경우가 대부분이다 (Q10). 3 % 안이면 기존 이어 붙이기가 먼저다.
  - 둘 다 트랙이 있으면 함께 푸는 것은 그대로 두고, D2의 진폭 상한만 건다.
- **D2 진폭 상한 (5.3 출력)**
  - 모든 목소리에 A_v ← min(A_v, ρ·A_v^single), ρ = 2 (+6 dB)를 건다.
  - A_v^single은 같은 신호, 같은 창 (그 목소리의 최종 창, 2단계면 N_v), 같은 기저 (처프 포함)로 그 목소리만 푼 LS 진폭이다. 자기 배음 열은 넣지 않는다.
  - 연속 함수 (min)이고 결정이 아니다.
- **D3 어택 보강 (5.3 출력, 매개변수 4번 attackTauMs, 기본 50, 0이면 끔)**
  - A_v ← A_v + o_v·max(0, A_v^fast − A_v)다.
  - A_v^fast는 `detailRing52_` (HPSS 이전)에서 그 목소리만 푼 LS 진폭이다. 과거 N_lo,v, 미래 N_f 창이다.
  - o_v는 CAND→ON, REL→ON, 전환 상태 진입 때 1로 놓고, exp(−Δt/attackTauMs)로 줄인다.
  - 한쪽으로만 더하고 연속으로 줄어든다. 킥 누출은 V4b, V9e, V7d로 잰다.
  - 적용 순서: D2 → D3 (상한을 건 A에 보강을 더한다).
- **D4 창 늘림 제한과 진폭 하강 규칙 (5.3 창 길이 규칙)**
  - **늘림 제한**: N_J와 N_v는 hop마다 최대 +16 표본만 늘어난다. 줄어드는 것은 바로 한다. 이력 규칙 (25 %, 3 hop)은 그대로다.
  - **하강 규칙**: 다음 두 조건이 측정 hop 2번 연속이면, 그 목소리의 N_v (1단계에서는 그 목소리가 정하는 N_J 몫)를 N_lo,v로 3 hop 동안 둔다. 그 뒤로는 늘림 제한을 따른다.
    - (i) N_lo,v 창 단일 LS 진폭이 현재 창 A_v보다 6 dB 넘게 작다.
    - (ii) SNR_v가 4 측정 hop 전보다 3 dB 넘게 떨어졌다.
  - (ii)는 정상 잡음 톤에서의 거짓 발동을 줄인다 (Q9: (i)만이면 6 dB 톤에서 초당 0.44번).
- **D5 근거 (b′) (5.2 (b) 보충)**
  - SNR_v ≥ 25 dB인 목소리에 한해, 근거 (b) 대신 다음을 받는다. 코어가 SNR에 쓰는 bh 128 ms 크기 스펙트럼에서, k ∈ {1..4}의 허용 범위 안 국소 최대가 ±27 bin 중앙값보다 6 dB 위에 있으면 된다.
  - P1의 `src` 피크 목록은 바꾸지 않는다.
  - 25 dB 문턱이라 노이즈만 있을 때의 태어남 (V9)은 늘지 않을 것으로 본다. V9로 잰다.
- **바꾸지 않는 것**
  - 목소리별 연속 가중치 (Q7 후보)는 넣지 않는다.
  - ampSource 기본값은 0이다. 1은 매개변수로만 남긴다.
  - V6a (덮음)는 트래커 한계라 v2 (트래커 교체)로 넘긴다.
- **비용 추정**: 목소리마다 단일 LS 투영 2–3개 (N ≤ 320)가 더해진다. 8목소리 기준 hop당 약 15k MAC이고, V8 (≤ 1.5×)로 잰다.

  - **V3h.rebound → RERISE**
    - 층 엔벨로프 (5 ms 상자 RMS, 150–600 Hz)를 쓴다. 기준은 음이 끝나기 45–8 ms 전의 평균이다.
    - 처음 −20 dB 아래로 떨어진 때부터 음 끝 + 120 ms까지, 엔벨로프 최대값이 −20 dB 선 위로 몇 dB인지 잰다 (0에서 자름).
    - 25 dB 끊긴 라인, 음 2..39의 중앙값이다. 6 dB 넘는 음의 수도 낸다.
    - 한계는 ≤ 6 dB이다. v1.5는 A·c 기준 11.2 dB (21/38음 > 6)이고, 층 기준 값은 LA 비교 행에서 낸다.
  - **V7d → R1**
    - E_hit = 타격 ±50 ms 안 10 ms 상자 10개의 평균 전력이다.
    - E_ref = [−300, −100] ∪ [+100, +300] ms 상자 40개의 중앙 전력이다.
    - burst = 10·log10(E_hit/E_ref)이다.
    - 한계는 코어 ≤ max(+3 dB, P1 burst + 1 dB)다. P1이 타격에서 꺼지면 사실상 +3 dB다.
    - v1.5 (R1): 4.12 s +5.90 dB (불합격), 4.73 s +2.37 dB (합격).
- **보류 (2026-10-30)**: 사용자 결정으로 14절의 미리보기 실험을 먼저 한다. 관문 검토는 받아 두되, 구현은 14절 결과를 보고 정한다. D1과 D2는 미리보기 코어에서도 쓰일 수 있고, D3와 D4는 미리보기가 대신할 수 있다.

## 14. 0단계: 미리보기 (지연) 실험 — 사전 등록 (결과 보기 전, 2026-10-30)
- **배경**
  - 사용자는 지연별 모델 여러 개를 계획한다: 300 ms, 150 ms (현재), 50 ms, 0–5 ms.
  - 현재 엔진 지연은 모든 알고리즘에서 146.9 ms다 (48/44.1 kHz).
  - ring에는 이미 미래 191 표본 (64 ms)이 있다. 트래커 프레임의 뒤쪽 절반에 해당한다. 코어는 앞울림이 걱정돼 그중 8 ms만 쓴다.
  - 과거 HQ (P1+, 미래 +26.7 ms를 가운데 정렬 HPSS에 사용)는 이득이 작았다. 미래를 P1 내부 부품의 평활에 썼고, 관문 구조는 그대로 두었기 때문이다.
  - 이번 질문은 다르다. 미래를 **경계와 판정**에 쓰면 이득이 생기는가.
- **미리보기 L** (출력 시점 기준, 그 뒤로 쓸 수 있는 입력 길이)
  - L = 0 / 64 / 120 / 217 ms를 잰다.
    - 0: 인과
    - 64: 현재 지연 안에서 공짜다. 150 ms 모델.
    - 217: +153 ms. 약 300 ms 모델.
  - 50 ms와 0–5 ms 모델은 다른 앞단이 필요해서 이 실험의 범위가 아니다.
- **시제품 LA (Python, 오프라인, 엔진은 그대로)**
  - 입력: 엔진이 캡처한 3 kHz 흐름 (bh = `bhRing_`, band = `detailRing52_`)과 P1 트래커 트랙 (id, f, a, raw, res). 트랙은 P1 기준 빌드의 하모닉 trace에서 모든 트랙을 가져온다. 코어의 목소리 8칸이 아니다. L만큼 미래의 hop까지 쓴다.
  - (1) **덩어리**: 트랙 id의 연속 구간이다. 50 ms 안에서 3 % 안으로 이어지면 이어 붙인다 (L 안의 정보만 쓴다).
  - (2) **경계 (구간)**: 덩어리 주파수에서 10 ms 창 LS로 짧은 엔벨로프 e(t)를 잰다. 한 덩어리 안에 소리 나는 구간 [t_on, t_off]이 여러 개 있을 수 있다.
    - 시작 t_on: 탐색 시작점 t_s (덩어리 시작, 또는 직전 t_off)에서 M = max e over [t_s, t_s + L]을 구한다. 그다음 e가 0.5·M을 처음 넘는 때다. L = 0이면 M은 지금까지의 최대값이다.
    - 끝 t_off: e가 구간 시작 뒤의 중앙값보다 12 dB 아래로 떨어지고, 그 상태가 min(L, 50 ms) 동안 이어지는 첫 때다. L = 0이면 떨어진 순간이다.
    - t_off 뒤에는 같은 덩어리 안에서 t_on 탐색을 다시 시작한다 (재어택).
  - (3) **진폭**: t에서 LS 창은 [t − N_p, t + min(N_f, L)]이고, [t_on, t_off]로 자른다. N_p ≤ 320, N_f ≤ 650이며, 창 모양은 비대칭 Hann이다.
    - 겹치는 덩어리는 함께 푼다. D2와 같은 상한 A ≤ 2·A_single을 건다. L별로 상한 전 joint/single 비의 p95도 낸다.
    - 그다음 구간 안에서 A에 앞뒤 평활을 한다 (영위상, 10 ms; 미래 쪽은 L 안에서만).
    - 신호는 bh와 band 두 변형이다 (LA-bh, LA-band).
  - (4) **판정**: 구간마다 한 번, t_on + min(L, 구간 길이)에 정한다.
    - 특징 (t_on부터 L 안에서): 주파수의 수렴값과 흔들림, ḟ, 감쇠 기울기, raw와 res 중앙값, 2f·3f 근거, 길이, 다른 덩어리와의 관계 (정수비, 가까움).
    - 로지스틱 회귀이며, 무게는 덩어리의 A² 합이다.
    - 학습: Track00060/40/01/05/12. 평가: Track00020/23/24/25/26.
    - p(음) < 0.5면 그 구간 전체를 끈다 (5 ms 페이드). 구간 도중에 판정이 바뀌지 않으므로 깜빡임이 원리상 없다.
    - **판정 상한 행 (오라클)**: 구간마다 MIDI 기준으로 맞음/틀림 (무게 다수결)을 매기고 틀린 구간을 끈다. 한 구간에 한 번 정하는 방식으로 얻을 수 있는 V6b의 상한을 L별로 보여 준다. 오라클로도 P1 + 2 %p에 닿지 못하면, 한계는 판정기가 아니라 구간 단위 자체다.
  - (5) **합성**: k = 2, 3 위상 연속 발진기, 무게는 voicing 0 (P1 감쇠), 그다음 150–600 Hz 필터. 위상 정렬 (V2)은 재지 않는다.
- **비교 행**
  - LA (L 4개 × bh/band)
  - 코어 v1.5 A의 trace (목소리 f, A·c·σ)로 같은 (5) 합성을 한 층
  - P1 trace (트랙 f, a·fade)로 같은 (5) 합성을 한 층
  - 모든 행이 같은 합성과 같은 필터를 거친다. `proxy16.py`의 √Σ 대리값은 정보로만 쓴다.
- **지표** (모두 대리 층으로, 정의는 7절과 13.3을 따른다)
  - E1 어택: V3a 정점, V3h rise90 (맨 음, 25 dB 라인), V3c.enter
  - E2 꼬리: V3h tail (안정 꼬리), RERISE (13.5 A1; 결정 규칙 (c)의 "rebound"는 RERISE다)
  - E3 V5a T60 낮은 칸
  - E4 V6b 틀린 음 몫: 평가 5곡, T24를 뺀 값도 낸다. 맞는 무게 유지율도 낸다.
  - E5 V7d 타격 폭발 (13.5 A1의 R1, LOGOFF 4.12/4.73 s)
  - 지킴
    - **V3d 앞울림**: [t0 − 30, t0] ms 상승 ≤ 1 dB다. 맨 라인과 25 dB 끊긴 라인의 재어택에서 잰다. 미래를 쓰면 층이 "빨라진" 것이 아니라 "일찍 나온" 것일 수 있으므로, 이 항목이 E1 이득을 가른다.
    - V4b (bass+kick+pink)
    - V9 (핑크만 태어남·에너지)
    - V3i 대용 (SNR 8 dB 떨림 톤에서 구간 켜짐/꺼짐 횟수/s)
    - 맞는 무게 유지율 ≥ 90 %
  - 정보: 판정 AUC (평가 5곡, L별)
- **결정 규칙 (미리 고정)**
  - 우연 아님: 평가 곡은 5개뿐이다 (T24를 빼면 4개). 그래서 곡 단위 부트스트랩은 쓰지 않는다.
    - V6b와 맞는 무게의 차이는 곡별로 모두 낸다. 5곡 가운데 4곡 이상 (T24 제외 시 4곡 모두)이 같은 방향이어야 한다.
    - 합친 값은 곡 안 고정 5 s 창 단위의 묶음 부트스트랩 (10,000번)으로 95 % 구간을 낸다.
    - 합성 신호는 결정적이므로 아래 여유를 쓴다.
  - "뚜렷이 낫다" = 다음 가운데 하나 이상이면서, 지킴 항목이 한계를 넘지 않는다.
    - (a) V6b −5 %p 이상
    - (b) V5a −2 %p 이상, 그리고 V3h rise90 (25 dB) −5 ms 이상
    - (c) V3h tail −10 ms 이상, 그리고 rebound −6 dB 이상
  - **300 ms 모델을 만든다**: LA(217)이 LA(64)보다 뚜렷이 낫다.
  - **150 ms 미리보기 코어로 간다** (v1.6 D3·D4 대신): LA(64)가 LA(0)보다 뚜렷이 낫고, E1–E5 가운데 3개 이상에서 코어 v1.5 대리값보다 낫다.
  - 둘 다 아니면 미리보기 방향은 멈추고, v1.6 (13절)과 v2 추정기를 검토한다.
  - bh와 band 중에서는 E1–E5에서 더 많이 이긴 쪽을 쓴다. 동률이면 bh다.

### 16.8 목소리 나누기·끝 검출기: 사전 등록 (결과를 보기 전)
- **목표**: 틀린 에너지의 (a) 걸침과 (b) 꼬리를 줄인다. 어택 쪽, 후보 선택, 태어남 지연은 건드리지 않는다.
- **R2에서 배운 것**: R2가 깨끗했던 것은 음높이 때문만이 아니다. LS 창을 경계에서 잘랐기 때문이다. 그래서 검출기가 찾은 경계마다 두 가지를 함께 한다: 목소리를 나누거나 끝내는 것, 그리고 LS 창을 경계에서 자르는 것.
- **입력**: hop은 5.33 ms다. bh 스트림 (3 kHz), 코어 v1.5 trace (목소리 f, A, state), 트래커 후보를 쓴다.
- **사건 세 가지**
  - **E-p 음높이 바뀜** (목소리 안)
    - 조건 ①: 목소리 트랙 f의 뒤쪽 3 hop 중앙값이 앞쪽 3 hop 중앙값과 50 cent 넘게 다르고, 2 hop 넘게 유지된다.
    - 조건 ②: 목소리 f의 LS 잔차가 띠 에너지 대비 6 dB 넘게 오르고, 동시에 50 cent 넘게 떨어진 다른 후보가 6 dB 넘게 커진다 (설명 빼앗기).
    - ①이나 ② 하나면 사건이다.
    - 행동: 옛 목소리를 경계에서 10 ms 페이드로 해제한다. 새 f에서 새 목소리를 시작한다. 양쪽 LS 창을 경계에서 자른다.
  - **E-e 음 끝**
    - 그 음에서 맞춘 지수 감쇠 예측보다 관측 진폭 (경계 앞쪽 창으로만 잰 LS)이 6 dB 넘게 낮은 hop이 3번 이어진다. 또는 음 최대보다 15 dB 넘게 떨어진다.
    - 행동: 15 ms 페이드로 해제한다. 창 늘림은 끝 뒤로 넘지 않는다 (D4 늘림 제한과 함께 쓴다).
  - **E-r 같은 음 재어택**
    - 목소리 f의 띠 에너지가 감쇠 예측보다 20 ms 안에 6 dB 넘게 오른다.
    - 행동: LS 창을 경계에서 새로 시작한다. 위상은 연속으로 두고 페이드는 하지 않는다. 공백 (E1 해악)을 만들지 않기 위해서다.
- **미래 예산**
  - 검출기가 더 쓰는 미래는 40 ms 이하다.
  - 16.1 방식 (같은 앞부분, 꼬리 4종)으로 잰다. 코어 v1.5 사슬과 코어 + 검출기 사슬의 갈라짐 시각 차이가 40 ms 이하여야 한다.
  - C++로 가기 전에, 전체가 엔진의 기존 버퍼 (지연 146.9 ms, ring 미래 64 ms) 안에 드는지 따로 확인한다.
- **조율**
  - 문턱 (50 cent, 6 dB, 3 hop, 15 dB, 페이드 길이)은 개발곡 (V6 10곡)에서만 정한다.
  - 격자는 12개 설정 이하다. 고른 설정은 확인곡을 처리하기 전에 고정한다.
- **확인곡** (선택 규칙을 지금 고정한다)
  - Slakh train에서 Track 번호가 작은 순으로 고른다.
  - 제외: V6 10곡, la0·diag16·R3·R4 연구에서 쓴 곡
  - 조건: 0–30 s에 베이스 MIDI 활동이 10 s 이상인 곡
  - 5곡을 고른다. 목록은 지표를 계산하기 전에 CHOICES에 적는다.
- **행과 통과 정의** (16.3 지표, 고정 이득 F 기준, M도 보고)
  - **D-oracle** (정답 음높이 + 검출 경계): 검출기만 따로 본다. 검출 구간마다 MIDI 음높이를 주고, LS는 R2와 같게 검출 경계로 자른다.
    - 틀린/R3맞는 ≤ 0.010 (약 3 × R2, S2-core 0.034의 1/3 이하)
    - 시작 경계 오차: 스템 활동 기준 중앙값 |·| ≤ 10 ms
    - 끝 경계 오차: 중앙값 |·| ≤ 20 ms
    - 놓친 경계 ≤ 10 %
    - 지속음 위 거짓 경계 ≤ 0.5 회/s
  - **D-full** (코어 v1.5 + 검출기, 오프라인 모사): 검출기가 움직인 곳만 진폭을 다시 잰다 (경계로 자른 LS). 나머지는 trace의 A를 쓴다. 같은 모사 경로의 코어 v1.5 행과 P1 행을 함께 낸다.
    - 틀린/R3맞는 ≤ 0.5 × 코어 v1.5 값, 그리고 ≤ P1 값
    - 맞는 층 ≥ 코어 v1.5 − 1 dB
    - V5a − R3 ≤ 2 %p
    - 지킴 항목 (합성 신호, 같은 경로)
      - V3i ≤ 0.5 회/s
      - V4b ≤ 코어 + 2 %p
      - RERISE ≤ 코어 값
      - V3d ≤ 1 dB
      - 꼬리 (V3h) ≤ 코어 값
      - V7d (R1 읽기) ≤ 코어 값
      - 누출 예산 (위)
- **결정 (기계 적용)**
  - D-oracle 실패 → 검출기가 부족하다. 검출기를 다시 설계하고, C++로 가지 않는다.
  - D-oracle 통과, D-full 실패 → 코어 목소리와의 상호작용 문제다. 실패한 지킴 항목을 기록한다.
  - 개발곡과 확인곡 모두에서 둘 다 통과 → C++ 구현을 따로 사전 등록하고, 사용자에게 알린다.
  - 개발곡에서는 통과하고 확인곡에서 실패 → 과적합이다. 멈추고 기록한다.
- **범위 밖**: 태어남 지연, 후보 선택 (음높이가 맞지 않는 목소리), 어택 쪽, 앱. 블라인드 순위는 해악의 크기를 보는 데만 쓴다.
- **작업**
  - 오프라인 Python이고, Sonnet medium이 한다. 위치는 `~/r3a-dev/plan16/D/`다.
  - 시작 전에 이 절을 Sonnet medium이 짧게 읽고 검토한다. 사전 등록 결함이 두 번 연속 나왔기 때문이다.

### 16.8.1 검토 반영 (실행 전 수정, 16.8과 충돌하면 이것이 우선)
검토 (Sonnet medium, 읽기만): BLOCKING 3, MAJOR 11, MINOR 6. Opus가 하나씩 확인했다. B1은 방식을 바꿔 받고, 나머지는 받는다.

- **B1 틀린 에너지 정의 (문턱 모순)**
  - 문제: 스템 활동 경계를 준 R2s도 0.041이다. 스템이 MIDI 끝 뒤에도 울리는데 (중앙값 +20 ms, p90 +55 ms), MIDI 정의는 그 부분을 틀림으로 센다. 그래서 오디오를 따르는 검출기는 0.010을 넘을 수 없다.
  - Opus 판단: 이것은 정답 정의의 치우침이다. 스템이 그 음높이로 아직 울리는 동안의 층은 귀로 맞는 소리다.
  - 수정: D 행들은 **스템 인지 틀림**으로 판정한다. 맞는 음의 MIDI 끝 뒤라도, 그 음의 스템 활동 (스템 40–220 Hz가 음 최대 −15 dB 위인 동안) 안에서 그 음높이 (0.5/1/2/3배, 50 cent)로 난 층은 틀림에서 뺀다. MIDI 정의 값도 함께 보고한다.
  - 기준 행을 먼저 계산한다. 스템 인지 정의로 R2, R2s′ (스템 활동 −15 dB 경계), S2-core, 코어 v1.5를 낸 다음 D 행으로 간다.
  - D-oracle 통과: 틀림_sa ≤ 0.5 × S2-core_sa 이고, 동시에 ≤ max(2 × R2s′_sa, R2s′_sa + 0.005).
- **B2 D-full 문턱**: 코어 v1.5 사슬의 틀린 에너지를 먼저 분해한다. 축은 (목소리 종류: 대응 / 음높이 불일치 / 무음) × (걸침 / 꼬리 / 앞 / 기타)이고, `followup/fu.py` 방식이다.
  - 통과
    - 범위 안 몫 (대응 목소리의 걸침 + 꼬리)이 코어 v1.5 대비 50 % 이상 준다.
    - 범위 밖 몫이 코어 v1.5의 +10 % 안이다.
    - 합계가 코어 v1.5 이하다.
  - "≤ P1"은 보고만 한다.
- **B3 경계 지표**
  - 분모: 정답 경계 가운데, 경계 ±50 ms 안에 호환되는 코어 ON/REL 목소리가 있는 것만 센다. 태어남 때문에 빠진 경계 수는 따로 보고한다.
  - 매칭 허용창: ±60 ms
  - 놓친 경계: 10 % 이하
  - 거짓 경계: 모든 정답 경계에서 ±120 ms 밖에 있는 사건. 시간당 0.15 회/s 이하
  - 시작 오차 중앙값 |·| ≤ 10 ms, 끝 오차 중앙값 |·| ≤ 20 ms. 둘 다 스템 활동 기준이고, 매칭된 사건만으로 잰다.
- **M1** D-oracle의 맞는 층: R3 − 1.5 dB (F) 이상이고, R3 − 1 dB (M) 이상이어야 한다. 버린 짧은 조각의 수와 에너지 비율을 보고한다.
- **M2** D-oracle 구간: 코어 v1.5 ON/REL 목소리를 검출 경계로 쪼갠 것이다. 음높이 부여와 필터는 `s_run.py`의 `s2_select(dedup=False)`와 같다. 합성은 `build_voices`와 같다.
- **M3** E-e 정의
  - A_obs(t): 그 목소리 f에서 단일 LS, 인과 창 [t − 32, t] 표본
  - 예측: hop [t − 26, t − 4]의 log A_obs에 직선을 맞춰 t로 늘인 값. 기울기는 −60…+10 dB/s로 자른다.
  - 음 시작 뒤 26 hop 미만에서는 "최대 −15 dB"만 쓴다.
  - 음 최대: 마지막 E-p·E-r·ON 시작 이후 A_obs의 최대
  - 3 hop 이어짐은 사건 하나의 길이로 센다.
- **M4** E-e 되살림
  - 발동 뒤 80 ms 안에 A_obs가 예측의 −3 dB 안으로 돌아오면, 같은 목소리를 페이드 없이 되살리고 사건을 취소한다.
  - 해제는 미래 3 hop (예산 안)을 확인한 뒤에 한다.
  - 지킴 항목 추가 (공백): 베이스 + 킥 + 핑크 합성의 지속음 (어택 뒤 200 ms부터 음 끝까지)에서, 층 포락선이 직전 100 ms 중앙값보다 12 dB 넘게 30 ms 이상 낮은 횟수가 코어 + 0.1 회/s 이하여야 한다.
- **M5** E-p의 새 목소리
  - f는 뒤쪽 3 hop의 중앙값이다. 이 값이 트래커 후보와 50 cent 안에 있고 호환 필터를 통과할 때만 새 목소리를 만든다. 아니면 옛 목소리만 해제한다.
  - 새 목소리는 ON으로 시작한다. 첫 40 ms는 진폭 상한이 옛 목소리의 직전 A다.
  - 교차: 옛 목소리는 10 ms 코사인 페이드아웃, 새 목소리는 같은 구간에 코사인 페이드인을 쓴다. 진폭 합이 일정하게 한다.
- **M6** E-p 안전장치
  - 발동 뒤 60 ms 동안 같은 목소리에서 다시 발동하지 않는다.
  - 최근 150 ms 동안 f가 한 방향으로만 바뀌고 총 변화가 100 cent 이상이면 글라이드로 본다. 나누지 않고 f만 따라간다.
  - 지킴 항목 추가
    - 합성 비브라토 (±30, ±100 cent; 5, 6 Hz): 분할 0.1 회/s 이하
    - 글라이드 (100 cent / 100 ms): 글라이드 하나당 분할 1회 이하
- **M7** E-r
  - 새 창 진폭이 직전 A + 12 dB를 넘으면 12 dB에서 자른다.
  - 진폭 전환은 R2와 같은 10 ms 평활과 5 ms 램프로 한다.
  - 지킴 항목 추가: 베이스 + 킥 + 핑크에서 E-r 발동 2 회/s 이하. 킥 ±30 ms 안 발동 비율을 보고한다.
- **M8** D-full 다시 재기
  - R2와 같은 LS (N_p ≤ 320, N_f ≤ 191, 혼합 bh, 그 목소리 f 하나)를 쓰고, 창을 경계에서 자른다.
  - 다시 재는 구간은 경계 20 ms 앞부터 목소리 끝이나 다음 경계까지다. 이어지는 곳은 10 ms 교차 평활로 잇는다.
  - 검출기가 발동하지 않은 hop에서, 다시 잰 값과 trace A의 비의 중앙값이 ±1 dB 안인지 먼저 보고한다.
  - 시간은 입력 시간 (코어 lag −12 ms 보정 뒤)으로 통일한다.
  - D4는 넣지 않는다. 16.8의 "D4와 함께" 문구는 지운다. 끝 뒤로는 창의 미래 쪽 N_f만 경계에서 자른다.
- **M9** 격자
  - 축은 최대 3개다. 어느 축인지는 CHOICES에 적는다.
  - 선택: 개발곡 D-full의 지킴 항목을 모두 지킨 설정 가운데, D-oracle 틀림_sa가 가장 낮은 것을 고른다.
  - 그런 설정이 없으면 "설정 없음"으로 기록하고, 확인곡은 처리하지 않는다.

### 16.10 타격 맥락 확인 (드럼 직후 목소리): 사전 등록 (결과를 보기 전)
- **목표**: 드럼 타격 직후에 태어나거나 커지는 목소리의 틀린 에너지를 줄인다. 이것은 무음 오류의 34 %이고, 베이스 곡만 보면 49 %다.
  - 3절의 대응표에 미뤄 두었던 "킥 톤 꼬리 → 타격 맥락 규칙"을 이번에 다룬다.
  - 범위 밖: 베이스 없는 곡, 음높이 불일치, 걸침·꼬리, 앱
- **원칙**
  - 늦추지 않고 낮춘다. 베이스와 킥은 강박에서 자주 같이 친다. 그래서 태어남을 기다리게 하면 어택 지연 (E5 해악, V3a가 이미 실패)이 커진다.
  - 그 대신 타격 창 안에서 생긴 목소리와 진폭 상승은 **잠정**으로 둔다. 근거가 서면 올리고, 서지 않으면 내린다.
  - 판정은 모두 인과다. 드럼 MIDI는 평가에만 쓰고 검출기에는 쓰지 않는다.
- **타격 검출 (오디오만)**
  - 전대역 입력 (48 kHz)을 쓴다. 128 표본 hop의 로그 에너지 플럭스를 1–8 kHz와 40–200 Hz 두 띠에서 잰다.
  - 둘 다 직전 50 ms 중앙값보다 9 dB 넘게 오르면 타격 시각 t_d다.
  - 창은 [t_d, t_d + 60 ms]다.
  - 구현 위치: 엔진이 이미 가진 입력이다. C++ 단계에서 버퍼를 따로 확인한다.
- **잠정 처리** (창 안에서 일어난 일만)
  - 창 안 새 태어남: 진폭 상한을 −12 dB로 시작한다.
  - 창 안 기존 목소리의 상승: 창 시작 직전 A 대비 +3 dB 넘는 몫을 잠정으로 둔다.
- **확인 근거** (매 hop 갱신, 다음 셋 중 둘 이상이면 확인)
  - **K1 음높이 안정**: 목소리 f의 최근 20 ms 변화가 30 cent 이하다. 킥 톤은 빠르게 내려가고, 베이스는 거의 고정이다.
  - **K2 배음 구조**: 트래커 피크 목록 (src[0] ∪ src[1])에 2f나 3f가 30 cent 안에 있고, 목소리 진폭 대비 −20 dB 위다.
  - **K3 느린 감쇠**: 최근 최대 이후 감쇠율이 120 dB/s 이하다. 판정은 최대 뒤 15 ms부터 한다.
- **결과**
  - 확인되면 상한을 풀고 10 ms 램프로 올린다.
  - 창이 끝날 때까지 확인되지 않으면 15 ms 페이드로 내린다. 태어남은 해제하고, 상승분은 창 직전 A로 돌린다.
  - 한 목소리는 한 창에 한 번만 판정한다.
- **조율**
  - 격자 축은 최대 3개, 12개 설정 이하다. 후보 축: 9 dB, −12 dB, K3 120 dB/s, 창 60 ms.
  - 고르는 규칙은 16.8.1 M9와 같다: 지킴 항목을 모두 지킨 설정 가운데 주 지표가 가장 좋은 것. 없으면 "설정 없음"이다.
- **곡**
  - 개발: V6 10곡
  - 확인: `plan16/D/conf_list.json`의 5곡 (Track00094, 95, 96, 99, 101, 미사용)

  - 이유: P는 모든 목소리에 걸친 합집합이라, 유령 목소리 몇 %만 안정 판정을 통과해도 문이 닫히지 않는다.
- **B2: 인과 정의**
  - ON은 N_s hop 내내 state = 2이고 coasting = 0인 것이다. N_s는 100 ms에서 19, 150 ms에서 29다 (hop 5.333 ms).
  - f는 f_track이다.
  - q95는 h 이전의 state = 2, 비 coasting 행으로 만든 1 dB 칸 누적 히스토그램에서 구한다. 행이 400개가 되기 전까지 진폭 조건은 참이다.
  - 목소리 id가 바뀌거나 REL 또는 CAND이면 창을 초기화한다.
  - 판정마다 읽은 최대 trace hop 인덱스를 기록한다. 그 값은 h 이하여야 한다.
- **B3: 쉼 정의를 하나로 맞춘다**
  - **첫 음 집합**: 그 설정에서 시작 hop의 P가 0인 모든 베이스 음이다. [0, H) 안의 음도 넣는다.
  - **0b 오라클**: H마다 침묵 문턱을 H로 둔다.
  - **주 지표와 F**: t < 4 s는 모든 칸에서 뺀다 (발췌 시작은 임의 절단이다). 빼지 않은 값도 보고한다.

### 16.18 LOGOFF 4.12 s 두 번째 좁은 수정: 기존 ON 목소리의 타격 직후 상승 제한 (사전 등록, 결과를 보기 전)
- **사용자 결정 (2026-10-31)**: "그걸로 다시 고쳐"
- **가설 (16.17 재진단)**: 이미 ON인 약 105 Hz 목소리가 킥 직후 긴 LS 창 (N = 320)에 킥 꼬리를 담는다. 그래서 A가 오른다.
- **0단계 (오라클, 오프라인, 싸게)**: v1.5 trace에서 LOGOFF 4.12 s 타격 뒤 [t_d, t_d + 80 ms] 동안 기존 ON 목소리 (나이 ≥ 50 ms)의 amp를 타격 직전 값으로 묶는다. 그 상태로 합성해 R1 burst를 잰다.
  - 줄어든 폭이 2 dB 미만이면 가설이 틀린 것이다. 멈추고 구현하지 않는다.
  - 터짐 에너지를 태어남과 기존 목소리 상승으로 나눈 몫도 보고한다.
- **수정 (0단계를 통과하면, C++, 매개변수 하나로 켜고 끔, 꺼지면 v1.5와 비트 동일)**
  - **타격 신호**: 엔진이 이미 가진 HPSS 타격 성분 (P)의 40–200 Hz 에너지다. 직전 중앙값보다 +9 dB 넘게 오르면 t_d다. 인과다.
    - P를 쓰는 이유: 베이스 음 시작은 조화 성분 쪽이라 덜 걸린다.
  - **대상**: t_d 시점에 이미 ON이고 나이 ≥ 50 ms인 목소리다. 태어남과 CAND는 건드리지 않는다.
  - **동작**: [t_d, t_d + W] 동안 amp ≤ amp_pre · 10^(cap/20)으로 묶는다. 창이 끝나면 10 ms 램프로 푼다.
  - **격자**: cap ∈ {+3, +6} dB, W ∈ {40, 80} ms. 모두 4개다.
- **판정** (16.16 절차, 16.17과 같은 틀)
  - **주 지표**: LOGOFF 4.12 s R1. 결정 규칙은 16.17과 같다: ≤ +3 dB 채택, v1.5보다 2 dB 이상 낮으면 채택, 2 dB 미만이면 되돌린다.
  - **지킴 4종**: 16.17과 같다. 어택 항목에는 **같이 친 재어택**을 더한다.
    - 합성 신호: 같은 음높이의 베이스 반복음 + 같은 시각 킥이다 (16.10.1 B1 bkp-click (i) 방식).
    - 재어택 rise90 ≤ v1.5 + 5 ms
    - 이 기능이 해칠 수 있는 바로 그 경우라서 넣는다.
  - **보고만 하는 것**: 나머지 스위트, 타격 검출 횟수, 상한 작동률
  - **선택**: 지킴을 지킨 설정 가운데 4.12 s가 가장 낮은 것을 고른다. 0.5 dB 안의 동률이면 부드러운 쪽 (cap +6, W 40)을 고른다.
- **작업**: Sonnet medium이 한다. 위치는 `plan16/F2/`다. C++는 미커밋으로 두고, Opus가 검토한 뒤 커밋한다.
- **결과 (2026-10-31, `plan16/F2/`)**: **0단계에서 멈춤.** C++는 건드리지 않았다.
  - 오라클 (기존 ON 목소리를 W 80 ms 동안 직전 값으로 묶음)은 0.55 dB 줄였다. 2 dB 미만이다.
  - 상승은 큐 뒤 70–100 ms에 있다. 목소리 id462는 78 → 약 105 Hz, 8 → 77 mV다. REL에서 되살아난 id492도 있다.
  - 정보용 (등록 밖): W를 120–160 ms로 늘리면 5.6 dB가 준다. 그러나 이것은 실제 음 시작을 누르는 것과 같다.
- **Opus 확인: 원곡 입력 저역** (`plan16/F2/peek_input.py`, 곡 43.7–44.7 s, 120 ms 창 피크)
  - 44.10 s까지 40–200 Hz 수준은 −50 ~ −30 dB다.
  - 44.14 s부터 80 Hz 피크가 나타나 내려간다: 75 → 61 → 53 → 48 → 45 → 43 Hz (44.14 → 44.28 s).
  - 같은 때 97 Hz (2배음)가 서고, 수준은 −10 dB 안팎으로 30–40 dB 오른다.
  - 즉 4.12 s 지점은 **808식 음높이 하강을 가진 진짜 서브베이스 음의 시작**이다. 이 곡의 45 Hz 사인 베이스다.
- **재해석**
  - 코어의 +5.9 dB는 진짜 베이스 음이 시작될 때 층이 같이 들어온 것이다. P1의 −12 dB는 그 시작에서 층이 빠진 것이다. 이것은 [[logoff-noise-song]]의 "킥 순간 0–40 ms에 층이 7–12 dB 꺼짐"과 같은 현상이다.
  - R1 (타격 ±50 ms 대 주변 상자 중앙값)은 "타격에서 층이 오르면 안 된다"고 가정한다. 그래서 진짜 음 시작과 타격이 겹치는 이 지점을 결함으로 셌다. 지표의 가정이 이 지점에 맞지 않는다.
  - 4.73 s도 같은 방향이다. P1은 −46.5 dB로 끊기고, 코어는 +2.4 dB로 이어진다 (12절 판정자 해석과 같다).
  - 13.1의 "짧은 창 LS가 타격을 잡음"과 16.17의 "쌍 불안정"은 둘 다 이 지점의 귀속을 잘못했다.
- **Opus 판정**
  - LOGOFF 4.12 s는 "고칠 결함"에서 뺀다. 진짜 음 시작에서의 층 진입으로 재분류한다.
  - 사용자 청감 (10-29 bloom·pair 블라인드)에서도 이 부근 층 모양의 차이는 들리지 않았다.
  - 따라서 16.16 재판정에서 남았던 "진짜 결함"은 없다. [[mixed-result-decision-rule]]로 다시 정리한다.
    - **확실한 향상**: 끊김 −39 dB, 깜빡임 7.3 → 0 회/s, 타격 누출, 낮은 음 골, 맥놀이, 음 시작 층 끊김 (4.12·4.73 s)
    - **악화**: 어택 정점 +20 ms, 꼬리 44 ms, 틀린 음 몫 +16.6 %p. 모두 PC 청감 감도 아래였다.
    - 판정: **코어 v1.5는 채택에 가까운 후보**다.
  - 앱 통합 (예: 실험 토글)과 실사용 청감은 사용자 결정이다. 남은 악화 (어택, 꼬리, 유령 목소리)는 다음 걸음의 목표로 기록한다 ([[perfection-is-asymptotic]]).
