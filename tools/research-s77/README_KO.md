# S77: 183.25 ms 안정 모드 앱 반영 및 S75/S76 정정

2026-11-03. 사용자 요청: 183 ms 안정 모드를 앱과 general/s26u 배포용 빌드에 반영하고 시험 APK 제공. 공개 출시 및 실폰 설치는 별도이며 이 작업에서 하지 않는다.

## 발견한 실제 결함

S75의 고정 `PVB_S75_WINDOW=1`은 PV 분석 버퍼를 288샘플로 줄였지만 `pvb_vb_modulation.h`의 `modulation::N`은 384였다. `frame[288]`을 `modulation::fit`에 넘기면 함수가 배열 뒤를 읽는다. 70 Hz 합성 사인파로 ASan `stack-buffer-overflow`, `pvb_vb_modulation.h:322`를 재현했다. 음악 파일은 필요하지 않았다.

초기 앱 이식은 최대 배열 크기 384를 유지했으나 활성 288샘플만 채웠다. 이 경우 범위 검사만으로는 남은 미초기화 값 읽기를 찾지 못한다. 그래서 초기 3,200블록 ASan 통과만으로 이 결함이 없었다고 할 수 없다. 연구판과 앱판의 30곡 대조에서 3곡이 불일치해 원인을 추적했고, 변조 모델 수락 분기가 처음 달라지는 것을 확인했다. 분리기 출력·Hann 표·창 계수는 같았다.

이는 극소수점의 청감 차이 주장과 무관하다. 정의되지 않은 메모리 읽기를 고치는 문제다. S75/S76의 지연 축소판 결과는 수정 구현의 성능 확인으로 사용할 수 없다. 특히 `피크 위반 0`, `숫자 오류 0`은 배열 안전성을 증명하지 않는다. 기존 215 ms 창과 강함의 384샘플 경로는 이 특정 길이 불일치의 대상이 아니다.

## 수정 범위

- 안정 모드만 HPSS 144샘플, PV 288샘플, 기본 정렬 5516샘플을 사용한다.
- 변조 모델은 공통 구현을 384/288샘플로 각각 컴파일한다. 183 ms 모드의 맞춤·합성 평가 시간축 모두 96 ms 창(반창 48 ms)을 사용한다. 강함의 기존 128 ms 창과 연산 순서를 보존한다.
- 분리기 지연 3192샘플과 출력 제어 지연 88샘플을 합쳐 48 kHz에서 8796샘플 = 183.25 ms다. 강함 대비 증가분은 34.5 ms다. 실폰 전체 지연과 구분한다.
- 모드 전환 후 원음 정렬 상태를 갱신한다. 초기 앱 이식에서 발견한 안정→강함 전환 지연 문제도 수정했다.
- 기본 OFF, 강함, 안정 선택을 general/s26u 두 Release 빌드에 포함한다.

## 검증 해석

동결 S75 원본은 변경하지 않았다. 별도의 수정 참조 복사본을 빌드해 앱판과 대조한다. 기존 S76에서 사용한 30곡의 재사용 목적은 구현 일치 검사이며, 미노출 자료 확인 시험이 아니다. 최초 실패 결과도 별도 보존한다.

최종 검사 결과와 APK 해시는 `listen/apk_s77/APK_MANIFEST.json`, `gpt-cli/s77_evidence`에 기록한다. 실폰에서의 버벅임·전환음·청감·전체 지연은 사용자 확인이 남는다. 수정 183 ms 후보의 효과·공백·어택·최악 곡 손실은 별도 재평가가 필요하다. 기존 S76 평균 수치로 이를 대신하지 않는다.

## 다음 단계

1. 수정 183 ms 시험 APK로 실제 기기에서 OFF/강함/안정을 같은 음량으로 비교한다. 사용자가 미세한 수치 차이를 식별할 것을 요구하지 않는다.
2. 수정 코드와 평가기를 다시 동결하고 기존 자료를 진단 재평가한다. 이를 새 확인이라고 부르지 않는다.
3. 진단 및 실폰 결과가 실용적이면 남은 미노출 자료의 사용 가능 범위를 확인하고 사전등록한 별도 확인으로 넘어간다. 기존 S76 결과를 보고 문턱을 바꾸지 않는다.
