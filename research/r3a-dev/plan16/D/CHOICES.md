## 1. Time base, voices, hops
* Core hop h: input time T_h = core_tc[h] + lag, lag = LAGS['core'] = -0.012 s (A's calibration).  All D-full voices are in input time; truth lookups for core-derived voices use T_h - lag (= the hop centre) exactly as plan16/A `measure(lag)` does.  Truth-f voices (S2-core, D-oracle) are in input time with lag 0 in `measure` as in S.
* Stream index of hop h: j_h = stream_index(T_h) (float); a window "ending at hop h" ends at round(j_h).
* A *run* = maximal run of consecutive hops of one voice id with state > 0 (the `voices_core` unit); voice amplitude = A c sigma (trace).  "core v1.5 row" = `rows.voices_core` shifted by lag, rendered by `synth16.render_layer16` (k<=8).  The detector with no event firing reproduces it exactly.
* Real intervals for S2-core / D-oracle = S's `real_intervals_core` (state 2/3 runs per voice id, split at a gap hop or a 3->2 transition, shifted by lag).

## 2. Step-2 reference rows (stem-aware wrong, B1)
* Stem activity per truth segment (lowest-bass-note run of plan16/A `segments`): raw bass-stem SUM (`X.bass_stems_and_notes`) -> `X.band_fft(40,220)` -> 10 ms boxcar RMS envelope at 48 kHz (input time, no processing delay); P = max envelope inside the segment [s,e]; activity = the contiguous region around the argmax with envelope >= P - 15 dB, searched in [max(s - 150 ms, previous segment end), min(e + 500 ms, next segment start)]; a segment with P < (song 95th percentile of the envelope, t>0.5 s) - 40 dB has no stem activity (its activity = its MIDI interval).  (A's `stem_activity` used the stem *bh* stream and -20 dB; that R2s is kept only as a cross-reference and is not re-run.)
* **R2s'** = R2 (LS window clipped, f_true, mix bh, N_p 320 / N_f 191, plan16/A `oracle_voices`) with the interval = this -15 dB stem activity [on, off] (on clipped to >= 0).
* **Stem-aware wrong** (`sa`): a voice-hop that the V6b definition (50 cent of 0.5/1/2/3 x any sounding MIDI note, drums included, bass + tp) calls wrong is NOT wrong if there is a truth segment n with MIDI end e_n <= hop time < off_n (stem activity end of n) and the voice f is within 50 cent of 0.5/1/2/3 x f_n.  Only the time AFTER the MIDI end is excused (not before the start).  Hop time = hop centre as in A's `make_split`.  The MIDI-definition values (`v6b`) are always reported next to it.
* Rows: R2, R2s', S2-core (S's recipe: `s2_select(dedup=False)` on `real_intervals_core`, `build_voices`, lag 0), core v1.5 (voices_core, lag).  Numbers: wrong-layer energy / R3 right-layer energy (R3 right energy from plan16/A ladder_raw, summed over the 10 songs), F (gain 1) and M (global gain so that the pooled right-layer energy equals R3's), pooled and per song, with and without Track00040 (m2); right layer vs R3 in dB.
* **B2 core v1.5 breakdown**: voice class per run (unit = run; span = [first, last] time of amp > 0): *matched* = `occupancy` winner w >= 0 and `compat(fm, f_w)` (fm = median fosc over the run's ON/REL hops); *mismatch* = winner exists but incompatible; *silence* = `occupancy` returns -1.  For classes with a winner (matched, mismatch) the wrong samples are split in time by fu.py's rule: (a) spans = another bass note sounds (contained segment != w); (b) tail = no bass note sounds and t >= end of w; (c) front = no bass note and t < start of w; (d) other.  Silence-class voices have no winner: all their wrong energy is (d) other.  Cell energy = energy of a layer rendered from only the wrong samples (stem-aware) of that class and category (same phases; cross terms mean cells need not sum exactly to the total; the total is rendered separately).  In-scope share = matched x (a + b); out-of-scope = all other cells + total difference; the B2 comparison uses these cells for both core and detector chains.

## 3. Detector readings (E-p, E-e, E-r)
Common: per run and per hop of the run, all quantities are causal functions of the mix bh stream (`sig.bh`) at hop time T_h; "dB" = 20 log10 of an amplitude.
* **A_obs(h)** = single-voice LS amplitude at the voice's own frequency f_h (constant over the window), causal window of 32 samples [j_h - 31, j_h], Hann past half w(n) = 0.5 (1 + cos(pi n/33)), cos/sin basis, ridge 1e-4 (trace/2), amplitude = hypot.  (32 samples = 10.7 ms.)
* **Band energy (m5) E_b(h)**: causal 64-sample window, same LS at f_h, f_h - 10, f_h + 10 Hz; E_b = max of the three amplitude^2.  Residual power rho(h) = weighted mean-square residual of the f_h fit over the same 64-sample window; rho_dB = 10 log10(rho / (E_b/2 + tiny)).
* **Prediction** (M3): linear fit of log A_obs (dB) over hops [h-26, h-4] of the run's current note segment, slope clipped to [-60, +10] dB/s (= [-0.32, +0.0533] dB/hop), extended to h.  Needs >= 23 usable hops after the note start (26 hops per M3 are required since the note start: n_since_start >= 26).  Before that only the "-15 dB from the note maximum" rule is used.  Same construction on E_b (dB, 10 log10) for E-r.
* **Note start** = first ON hop of a run, or the last E-p / E-r event boundary (also revive hop).  "Note maximum" = max A_obs since the note start.
* **E-e**: per-hop condition c(h) = [n_since_start >= 26 and A_obs_dB(h) < pred_dB(h) - TH_DB] or [A_obs_dB(h) < peak_dB - 15].  The event is a run of >= N_HOP consecutive hops with c = true (N_HOP = 3 in the literal setting; the 3-hop persistence applies to both rules).  Event boundary b = first hop of the run; the decision is taken at hop b + N_HOP - 1 (this is the only future the E-e decision uses: (N_HOP-1) hops = 16 samples each).  Applies to ON, REL and coasting hops (m6); CAND hops never.  Action: raised-cosine 15 ms fade-out starting at T_b; the rest of the run is muted (the voice is released).  Revival (M4): during the 80 ms (15 hops) after the decision hop, if A_obs_dB >= pred_dB - 3 (pred = the frozen fit line extended; if no fit exists, peak_dB - 12 is the reference) the event is cancelled: the piece restarts at that hop with NO fade (hard return, the 5.33 ms hop interpolation is the only ramp) and the dip between b and the revival hop stays in the layer (causal).  A muted rest-of-run is re-enabled only by a core 3 -> 2 (REL -> ON) transition of the same voice id, which then counts as a new voice birth.
* **E-p (1)** pitch step: at decision hop d = b + 2, pre = median(f[b-3..b-1]), post = median(f[b..b+2]); event iff |cent(post/pre)| > TH_CENT (50 in the literal setting) and each of f[b], f[b+1], f[b+2] is > TH_CENT from pre in the same direction (>= 3 hops held; "2 hops 넘게").  Boundary = b.  State must be ON/REL (not coasting, not CAND) at b..d.
* **E-p (2)** explanation stealing: at hop h (ON/REL, not coasting): rho_dB(h) - median(rho_dB[h-12..h-6]) >= TH_DB and, among the other P1-reference-trace tracks (`sig.ts`, state > 0, f in [30,300], > 50 cent from f_h, same track id valid at h-6) at least one has its 64-sample band energy (same m5 construction at its f) risen by >= TH_DB over h-6.  Boundary = hop of the largest one-hop rise of rho_dB in [h-4, h].  The candidate pool is therefore the P1 reference trace (as in S1), so confirmation tracks need the REF-build render (step 5).
* **M5 new voice**: f_new = median(f[b..b+2]) for (1), the alternate track's median of its last 3 hops for (2).  A new voice is created only if f_new is within 50 cent of a P1-reference-trace candidate in [b-2, b+2] hops AND passes the compatibility filter = 35 <= f_new <= 220 Hz and > 50 cent from every other currently live (not muted) core voice's f.  Otherwise the old voice is only released and the rest of the run is muted.  The new voice is ON from b; its amplitude is capped during the first 40 ms at the old voice's trace amplitude of hop b-1; crossfade = raised-cosine 10 ms (old fades out, new fades in; amplitude sum constant).  The new voice's frequency afterwards is the run's fosc track from b on.
* **M6**: after an E-p fires on a voice, no E-p on the same voice (either piece) for 60 ms (11 hops).  Glide guard: over the last 150 ms (28 hops before the decision hop) f is monotone (all one-hop differences have the same sign within 3 cent) with total change >= 100 cent AND no single-hop jump larger than 25 cent -> glide: no split (the f track is followed).  (A step is monotone too; the 25-cent per-hop limit is what separates a glide from a step.)
* **E-r**: ON/REL, not coasting, >= 8 hops after note start.  At hop i: E_b_dB(i) - min(E_b_dB[i-4..i-1]) >= TH_DB (rise within the last 20 ms, backward look) AND E_b_dB(i) >= pred_E_dB(i) + TH_DB (for < 26 hops since note start, pred_E = median of E_b_dB from note start to i-5).  Boundary = hop of the largest one-hop rise in [i-4, i].  Refractory 60 ms after any E-r on the voice.  Action: LS windows restart at the boundary; the voice is NOT split for synthesis (phase continuous, no fade); the new-window amplitude is capped at the previous A + 12 dB (M7).
* Priority at one hop: E-p, then E-r, then E-e.  After an E-p / E-r the note-start bookkeeping restarts.  Events found at the same decision hop on different voices are independent.

## 4. D-full simulation (M8)
* A voice with no event: the unchanged `voices_core` voice.  A voice with events becomes pieces: [birth|E-p boundary|revive, E-p boundary|E-e boundary|run end) and windows inside a piece separated by E-r boundaries.
* Re-measured regions: a window that STARTS at an event boundary (E-p, E-r, revive): the whole window; a window that ENDS at an event boundary (E-p, E-r, E-e): its last 20 ms; windows that start at a birth and end at a natural run end: not re-measured.  Re-measure = single-voice LS exactly as R2 (plan16/A `la.solve_amplitudes` with one interval, N_p 320 / N_f 191, ridge, 8-sample grid, window basis clipped to the window), f = the hop fosc track (interpolated), mix bh, then `la.smooth` (10 ms) and a 5 ms ramp at the window start.  Elsewhere the trace amplitude; at the junction between trace and re-measured amplitude a 10 ms linear cross-fade (centered on the region start/end).  M7 cap for E-r (and for the first window of a revived/E-p-new piece relative to its predecessor).  No D4.
* Synthesis: every modified piece is regridded to 8-sample steps (amp, f linear); fade gains multiply amp.
* Non-fired hop check (M8): for runs with no event, the re-measured LS amplitude of the whole run (window clipped to the run) vs the trace amplitude A c sigma at ON hops; median of the dB ratio per song and pooled is reported first.
* Wrong-energy comparison for D-full follows B2 (three bullets).  "<= P1" and "<= 0.5 x core v1.5" are reported as information; the stem-aware wrong values are the primary ones (`v6b` shown too).
* D-full right layer >= core v1.5 right layer - 1 dB (F) and, in M, the gain needed to match R3 not larger than for core v1.5 + 1 dB (m4: both).  V5a: on the T60 excerpt (same simulation), V5a(row) - V5a(R3) <= 2 %p, R3 = 8.25 %.

## 5. D-oracle (M1, M2, B3)
* Intervals = S's `real_intervals_core` (core ON/REL runs, shifted by lag) cut by the detector events of the setting: E-p splits at b (fm recomputed per piece as the median fosc over its hops), E-e truncates at b (the muted rest dropped), revive starts a new interval; E-r does NOT cut (window boundary only; the pitch assignment sees the whole interval).  Pitch + filter = `s2_select(real, segs, dedup=False)` (winner by occupancy, `compat`), layer = `build_voices` semantics (LS on mix bh at the truth f, window clipped to the interval, 10 ms smoothing, 5 ms fades), except that the pieces of one interval separated by E-r boundaries are merged into ONE voice (continuous phase, no fade at the boundary).  Fragments shorter than GRID_A//2 = 4 samples are dropped by `build_voices`; their count and energy ratio are reported (M1).
* Pass (B1): wrong_sa / R3right <= 0.5 x S2-core_sa AND <= max(2 x R2s'_sa, R2s'_sa + 0.005); right layer vs R3 >= -1.5 dB (F) and the matched gain <= 1 dB (i.e. >= -1.0 dB: the binding one); start/end/missed/false per B3 below.  m4: F and M both.
* **B3 boundary metrics.**  Truth boundaries = starts and ends of the lowest-bass-note segments (plan16/A `segments`).  Reference times: stem activity -15 dB `on` / `off` of the segment (above).  A truth start is in the DENOMINATOR iff a core voice (state 2/3, any voice id) that is compatible (`compat`, 0.5/1/2/3 x, 50 cent) with the new note's f, or (for a contiguous change) with the previous note's f, covers time t_start - 20 ms (the boundary lies inside a living voice; attacks out of silence are the core's birth, counted separately as "birth-missing"); a truth end is in the denominator iff a core voice compatible with that note covers t_end - 20 ms.  Detector events: start-type = E-p new-voice start (b) and E-r (b); end-type = E-e (b) and the E-p old-voice release (b).  A truth boundary is matched by the nearest same-type event within +-60 ms (pitch compatible with the note for E-p starts); missed = denominator minus matched; error = event time - stem activity time of the matched pair, median of |.| over matched events (start <= 10 ms, end <= 20 ms), missed <= 10 %.  False boundary = an event farther than 120 ms from EVERY truth boundary (starts and ends, all types); rate = count / (bass-segment time at t>0.5 s), must be <= 0.15 /s (16.8.1 B3; the 16.8 "0.5 /s" is superseded); also reported per second of song time.
* Boundaries of matched events are measured on the pooled 10 songs; per song and T40-excluded (m2) are printed.

## 6. Guards (D-full, "same path")
Synthetic cores: cached `diag16/cache` / `la0/cache` streams of bare100, step25, bass9, bkp_0 (and bass8c audio for V4b), steady8, logoff_37_49, t60_36_48, plus NEW signals rendered once through the candidate lib (D-local patch of `data.audio`, cache in plan16/D/cache): `gapbkp` (8 s: three sustained 2.5 s bass notes 98/82.4/110 Hz with slow decay, kick every 0.5 s at 0.2, pink as in `sig_bass_kick_pink`), `vib_{30,100}_{5,6}` (6 s tone at 98 Hz, vibrato +-30 / +-100 cent at 5 / 6 Hz, plus pink at SNR 20 dB), `glide` (98 Hz tone, 8 glides of 100 cent in 100 ms, 0.7 s holds, SNR 20 dB).  Every guard metric is computed on the layer of the voice list (k<=8 synthesis, 48 kHz up-sampled, the metric code of la0/metrics.py with the evaluation recipe of `evaluate.eval_synthetic`) for (a) core v1.5 (no events) and (b) the detector chain.  Conditions: V3i <= 0.5 /s (voice-list branch of `onb_flips`, both rows); V4b low_frac <= core + 2 %p; RERISE median <= core; V3d (step25 plain-line median and bass9 median) <= 1 dB; V3h tail (bare100, step25) <= core (absolute 40 ms printed, m3); V7d (both hits) <= core; gap count (layer envelope = 5 ms RMS of the y48 layer; in [attack + 200 ms, note end] of the `gapbkp` notes, envelope more than 12 dB below the median of the preceding 100 ms for >= 30 ms) per second <= core + 0.1 /s; vibrato E-p splits <= 0.1 /s for all four; glide E-p splits <= 1 per glide (maximum over glides); E-r firings <= 2 /s on `gapbkp` and `bkp_0`, share within +-30 ms of a kick printed; leak budget.
* V5a / the synthetic guards are looked at once in development (M10).

## 7. Leak budget (M11)
* Every decision logs the largest bh sample index read by the quantities that decision uses (causal windows end at round(j_h); E-e/E-p decisions use hops up to d = b + N_HOP - 1 (E-e) or b + 2 (E-p); E-r uses hops <= i) minus j of the output hop whose layer changes (the boundary hop b).  Criterion: max <= 120 samples.  The re-measure LS reads up to +191 samples (64 ms) beyond its grid point; that is the engine's existing ring future and is reported separately, not counted in the 120.
* Engine buffer check (reported, decides only "go to C++"): core future = 118 ms (16.5: the tracker hop c uses input to c + ~118 ms; we add the 12 ms lag -> 130 ms relative to T_h, both printed) + the detector lead above; sum vs 146.9 ms.
* The 16.1-style prefix test (same prefix, four tails) is auxiliary; it will be run on `step25`-type signal only if time allows, otherwise reported as not run.

## 8. Tuning grid (M9): 3 axes, 12 settings, literal setting first
* TH_DB in {6, 8, 10} (the "6 dB" of E-e below prediction, E-p (2) residual/candidate rise, E-r rise); TH_CENT in {50, 75} (E-p 1 pitch step); N_HOP in {3, 5} (E-e persistence; E-p keeps 3 held hops).  Fixed: peak -15 dB, fades 10/15 ms, 60 ms refractory, glide guard.
* Selection (M9): among settings whose D-full guards ALL hold on the development songs/signals, the one with the lowest D-oracle wrong_sa (F; ties: M).  None -> "no setting", the confirmation tracks are NOT processed.
* Decision rule (16.8, mechanical): D-oracle fail -> detector insufficient, redesign, no C++; D-oracle pass, D-full fail -> interaction problem, failed guards recorded; both pass on dev and confirmation -> C++ implementation to be pre-registered separately, tell the user; dev pass and confirmation fail -> overfit, stop.
* The selected setting is frozen in `frozen_setting.json` BEFORE any confirmation track is processed.
