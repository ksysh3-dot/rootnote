## Metrics (all on mono; window = 2 s Hann FFT as BY/by_measure.metrics: 2*sum|X|^2/(N*sum w^2))
1. m1 = 20-140 Hz band level (dB), bins 20 <= f < 140.
2. m2 = 150-260 Hz envelope modulation excess: band = butter(4,[150,260]) sosfiltfilt on the whole signal; 5 ms box RMS dB envelope (floor -90 dB, 200 Hz); within the 2 s window (400 env samples) Hann, NFFT 2048, one-sided power summed over 2-30 Hz, M = sqrt(sum) in dB-rms units (b1_mod.mod_series with band 2-30); excess = M_layer - M_input, input = same band/envelope of the input mono mean (same window). Primary unit for the -1 dB threshold = difference of excesses (dB-rms units, like the 19.11 "pulse excess" column). Also listed (report-only): 20*log10(M_layer/M_input).
3. m3 = a_2 jump rate: hops per second with |20 log10 a_2[h]/a_2[h-1]| > 6 (same slot and voice id, state >= 2 in both hops, both a_2 > 1e-7), counted over all hops of the dev windows (sum count / sum seconds).

## Part A: oracle on v1.6-c traces
Reconstruction = by_attr.rebuild logic (k=2 and k=3 of every voice rebuilt from the trace: theta_hat, psi_2/3, a_2/3, linear interpolation inside a 16-sample hop), summed over all slots at the 3 kHz core rate, then the layer HP (causal Butterworth 8 at 150 Hz at 3 kHz) = 'post'. Metrics are computed on this reconstruction (the content is < 1.5 kHz so bin-for-bin identical windows), envelope boxes = 15 core samples (5 ms). Time alignment: core sample n <-> layer time (n-398)/3000 + 1359/48000 s (BY/by_attr), checked by cross-correlation against the real layer band signal.
Baseline recon vs real v1.6-c layer is printed for each dev window (m1, m4 differences in dB, m2 excess difference) so the fidelity of the projection is visible. Projected value = measured v1.6-c - (recon_baseline - recon_variant), per window; pooled values are re-pooled from the projected per-window band energies (m1, m4) or averaged (m2). m3 is read directly from the variant a_2.
Sustain segment (per slot, per voice id): events (s19_attr.events definitions: birth, REL>ON, note_chg > 50 cent over 2 hops) start a new segment; sustain = hops with state ON (2), >= 6 hops (32 ms) after the last start event, until the next start event, ON>REL or voice change. Hops 0..5 after a start event, all REL hops, and all non-sustain hops are untouched (output a == original exactly; checked numerically).
Smoothing time scale T in {30, 50} ms = time constant of a one-pole low-pass on the hop series (hop 16/3000 s). zp = forward-backward pass of that one-pole (zero phase), c1 = single causal one-pole, c2 = causal 2nd order (two cascaded one-poles of tau = T/2, critically damped). Filters run on linear amplitude a_k inside each sustain segment only (state initialised with the first segment value; zero-phase: edge-extension by the end values). Joins are continuous: out = a + w (smoothed - a) with w ramping linearly 0 -> 1 over the first R = 3 hops of the segment and 1 -> 0 over the last 3 hops (segments shorter than 6 hops: w = 0.5-peak triangle). Applied to a_2 only, and to a_2 and a_3 together (a3 variants), -> 12 variants.
Rule (19.13.1): if m1 pooled projected change (dev, 15) is not <= -2 dB AND m2 projected change is not <= -1 dB for ANY variant -> A5 family folded. If any variant reaches either, a_2-level smoothing (per harmonic, not voice amplitude) gets pre-registered next. Guards listed (report): body m4 change (pooled), m3 as an operation check. The A5P attack guard is not testable in this offline oracle because onsets are bitwise untouched; any variant that reaches a threshold must be checked with the A5P suite (V3a, V3h rise90) on an engine implementation. Several variants: report all; the decision sentence uses the best (lowest m1) and the best (lowest m2).
