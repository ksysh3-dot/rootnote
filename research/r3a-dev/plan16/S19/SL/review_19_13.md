# 19.13 사전 등록 검토 (Sonnet, 읽기 전용)

## 1. 주 지표가 남은 불만을 재는가 (영향 큰 순)
1. **가장 큰 문제: 행 6개 중 slew 8·12는 사실상 안 걸린다.** A5 결과(decide_a5.log): slew 8에서 k=2 도약(>6 dB/hop)이 3138 -> 3145~3191로 그대로였다. 줄어든 것은 slew 2(357)·4(600)뿐이다. 도약이 8 dB 안이면 8 dB 제한은 아무것도 안 하고, 12는 더 그렇다. 그런데 slew 2·4는 어택을 깼다(rise90 +15~+188 ms). 현 격자(6/8/12)는 "걸리면 어택이 깨지고 안 걸리면 무효"인 사각이다.
2. **스펙트럼 논리도 안 맞는다(추정).** v1.6-c는 BW8 150 Hz 고역 통과를 거친다. 20-140 Hz 박스의 에너지는 대부분 120-140 Hz(차단 -6~-14 dB)이고, 150-260 Hz 반송파에서 약 10-30 Hz 아래 옆띠다. 이것은 30-100 ms 규모의 변조다. 5 ms 한 hop 안의 도약을 6-12 dB로 눕혀도 그 규모의 옆띠는 거의 같다(램프가 약 50 ms 가까이 길어야 준다). 그래서 A5가 다시 거의 영 효과일 가능성이 높다. 격자에 실제로 걸리는 낮은 slew(2-3 dB)와 어택 면제 강화안을 넣거나, 아래 오라클을 먼저 돌릴 것을 권한다.
3. **오라클 한 행 추가 권장**: 렌더 후 trace의 a_2를 30-50 ms로 평활한 상한(오프라인). 20-140 Hz 절대치가 이 상한에서도 -2 dB 못 내려가면 A5 계열 전체를 접는다. 구현 없이 판정할 수 있다.
4. **지표 자체**: 20-140 Hz는 19.11에서 vanila 안(p90 -74, 최대 -60.7 dBFS)이고 원음 저역보다 45 dB 이상 작다. 폰 스피커는 150 Hz 아래를 거의 못 낸다. 그래서 불만의 직접 대리는 못 된다. 19.12는 크기가 큰 몫이라고 했고 trim -3 dB는 이미 있다. 남은 것은 "150-260 Hz k=2의 사건 결속"이다. 권장 보조 지표는 다음이다.
   - **150-260 Hz 포락선의 hop당 >6 dB 도약률(회/s)**과 사건 결속 몫. 슬루가 직접 건드리는 양이고 19.11의 귀속 정의와 같다.
   - 150-260 Hz 대역 포락선의 2-30 Hz 변조 에너지(원음 대비).
   - 앱 경로 +6 dB의 20-400 Hz 피크(보고만으로 이미 있음). 폰에서 지직이 변위에서 오는지 보는 지표다.

   20-140 절대치는 주 지표로 두되, 도약률은 판정이 아닌 "작동 확인"(걸렸는데도 지표가 안 움직였는가)에 쓴다.

## 2. 기준선·지킴 (16.16 기준)
- 기준선: 지킴은 "P1보다 나쁘고 동시에 v1.6-c보다 폭을 넘게 나쁠 때만 실패"로 16.16과 맞다. 단 어택 지킴(+2 ms)은 도약 줄이기의 직접 부작용이므로 이 이중 조건이 약하게 만들면 안 된다. 어택은 v1.6-c 대비 +2 ms를 그대로 두는 편이 낫다(A5에서 실제 해악이 났던 유일한 곳).
- 채택 문턱이 약하다: "개발 합산 -2 dB 이상 + 5/7창 개선 + 확인군 안 나빠짐". 19.4에서 nFuture 48 하나가 -2.1 dB였다. nFuture 단독 행이 이미 문턱을 넘을 수 있으므로 slew 효과와 섞이면 안 된다(아래 3번).
- 빠진 것: 확인군 "안 나빠짐"의 허용폭(0 dB인가), 개발 창 선택 시 선택 편향을 막는 "확인군 개선 부호 일치" 조건. 14곡 박동·V3c.enter·꼬리는 보고만이라 맞다.
- 과한 것: 위상 정렬 V2 0.1 rad는 A5가 진폭만 만지므로(위상 계산은 amplitude 값을 쓰지 않음) 닿는 경로가 없다. 몸통 -1 dB는 A5(-0.1 dB 이내)에 비해 여유가 있어 유지해도 해가 없다.

## 3. 뺄 것
- slew 12 행(거의 항등), slew 8 모드 1 행(모드 1과 2의 차이는 50 ms 넘는 REL 복귀뿐이고 A5에서 값이 같았다: 둘 다 올 패스, 층 비 차 0.03 dB).
- V2 0.1 rad 지킴, V3g(A5에서 5 hop에 걸린 값이 기준선과 동일해 정보 없음)는 보고만으로 내려도 된다.
- nFuture 48 행은 slew와 분리해서 한 번만(48 단독). "slew 8 + nFuture 48"은 slew 8이 무효이므로 의미가 없다. 대신 "작동하는 slew + 48" 한 행으로 바꿀 것.
- 보고 항목 중 RERISE·V6b·꼬리는 이 수정과 거리가 멀다. 14곡 박동도 진폭만 만지므로 생략 가능.

## 4. a5.diff 이식 함정
- **매개변수 번호**: diff는 kParams 19->21(0-기준 19, 20)이다. 현재 코어는 22이고 0-기준 19-21이 층 고역 통과다. 새 값은 0-기준 22(ampSlewDb), 23(slewOnsetMode)이다. setParams의 q[] 배열 초기값 목록, 범위 검사 `in(...)`, `p_` 대입, research_core_api.py의 PARAMS·DEFAULTS, h의 kParams와 주석(조각 "21 parameters")을 모두 22->24로 맞춰야 한다. diff의 hunk는 이 줄들이 달라져 그대로는 안 붙는다. 수작업 이식.
- **고역 통과·위상 보정과의 상호작용**: 위상 보정 hpc는 psi 목표에서만 쓰이고 진폭과 독립이라 충돌은 없다. 고역 통과는 합성 뒤 전체 출력에 걸리므로 slew의 진폭 램프가 BW8 150 Hz의 군지연(차단 근처 수 ms~10 ms 이상)과 겹친다. 어택 지킴은 v1.6-c 출력 기준으로 재야 한다(A5의 숫자는 고역 통과 없는 기준).
- **A·c·σ 대 a_k**: slew는 `base`에만 걸린다. a_k = g·w_k(f_osc)·r·base에서 w_k·g는 f_osc 도약(18.13: f_osc 튐이 f_track의 4-7배)에 따라 같이 뛴다. 그래서 base를 제한해도 a_2 도약은 base 몫만 줄고, 줄이는 양이 불완전하다. A5에서 3138->357은 이 비중이 작다는 뜻이지만, 지표가 안 움직인 것과 맞물려 "a_2 자체에 건다"(aStart[k] 대비 +/-slew)가 더 직접적이다. 비용: Voice에 aR[7]. 비교 행 하나로 둘 만하다.
- **0일 때 비트 동일**: slewLimit은 0이면 target>0 ? target : 0을 돌려주고 `!(base>0)`의 early return과 같은 결과라 통과한다. relHops·ampR·slewFree는 출력에 안 닿는다. 단 `u.dead`/Fade 슬롯과 `Voice{}` 초기화 경로(mergeVoices의 younger.relHops, 슬롯 재사용 시 ampR 초기화)를 확인할 것. a5_sha256.txt와 같은 방식의 0 해시 비교를 v1.6-c 설정(고역 통과 포함)에서 다시 해야 한다.
- **slew가 하는 일과 도약 정의**: 19.11의 도약은 렌더 a_2의 hop당 >6 dB다. slew S는 base의 한 hop 상승·하강을 S로 제한할 뿐이라 S >= 6이면 정의상 거의 안 줄고, S < 6이어야 도약 수가 줄어든다. 도약 수는 trace(a_2)로 같은 정의를 쓸 것.
- **바닥 1e-5**: 면제 없는 약한 탄생(SNR 15-22)은 -100 dBFS에서 올라가 6 dB/hop이면 수십 ms가 걸린다(rise90 위험). 지금은 mode 1이 강한 탄생만 면제한다. 약한 탄생에서도 첫 값은 target으로 시작하도록 고치는 편이 안전하다.
- 코드 주석은 "freed hop은 제한 없음"이라고 하지만 구현은 dead만 건너뛴다. REL이 c<0.01에서 dead로 끊기는 지점(c = 0, dead = true)과 맞는지 확인할 것.
